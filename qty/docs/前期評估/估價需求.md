## 1　背景

需要數量計算，源頭是**估價需求**。標單本身不複雜，複雜的是項目多：多數是某空間某部件的面積或長度；難以拆分的整包列「一式」。工具要解決的是重複整理耗時，不是估價公式本身。

一式、非模型項目、損耗率：見 [`範圍與邊界.md`](./範圍與邊界.md) §5～§6。

## 2　輸出兩張表

範圍已定「估價單＋明細」。欄位建議：

| 工作表 | 內容 | 用途 |
|---|---|---|
| 估價單 | 依空間／工種群組加總後的一列一項 | 對外、給廠商 |
| 明細 | 逐物件：`object_id`、所屬群組、規則、單位、數量 | 查核；數字對不上時往下追 |

底層永遠**逐物件**累加；Excel 的一列是空間 × 部件的加總。

## 3　涵蓋率檢核

手動選取的最大風險：同一物件被兩批次選到（算兩次），或沒被任何批次選到（漏算）。兩種都不會報錯，估價數字錯是要花錢的。

### 3.1 三個選取集合

```text
全部物件（基準集合）
  ├─ 已選取・已計算
  ├─ 已選取・一式
  └─ 未選取
```

一式是檢核裡的合法狀態，跟「已計算」平起平坐，可用顏色看到還沒決定去向的物件。

### 3.2 檢核順序（衝突最先）

```text
1. 已計算 ∩ 一式          → 衝突：列出、上色、擋下，不自動決定
2. 全部 − 已計算 − 一式   → 漏選
3. 已計算內部批次互相 ∩    → 重複選取
4. 已選取但參照已失效      → 第五態（見 §6 第 4 項）
```

與 `LFTagO` 相同：**只標記，不自動修**。

### 3.3 基準集合的兩個來源

- **Registry `objects[]`**：可做「這個 Type 通常該用哪個規則」的提示；未重新 Publish 會跟現況脫節
- **Rhino 文件現況掃描**：永遠最新

> **2026-09-01 實測**（[`實測報告.md`](../../../../mcp/rhino/實測報告.md) §9.1）：物件身上**有** `type_id`（`_03_ID編號`）。拿不到的是 `measurement_rule` 與 `estimation_unit`，那兩欄只在字典／Registry 的 `types[]`（[`初步評估報告.md`](../../../../mcp/rhino/初步評估報告.md) §6.2）。現況掃描可做分類與涵蓋率；規則仍須查字典。
>
> 現況掃描做涵蓋率、Registry 做規則提示，兩邊不一致也標出來（初步評估報告 §6.3）。

## 4　排序

外層（空間優先 vs 工種優先）：一份標單只選一種，計算邏輯不分叉，只改 group by 順序。

內層（哪個空間／工種先）：無法從 `spaces[]` 自動生成。建議獨立排序對照表（`space_display → sort_key`、`type_display_name → sort_key`）；新項目沒在表裡就列最後並標色。換排序不需動計算程式碼。

見 [`初步評估報告.md`](../../../../mcp/rhino/初步評估報告.md) §7.2。撈回 `3b4158c^` 的 `quantity.py` 前：

## 6　尚未定案

1. 輸出給內部預算還是對外空白標單（或兩者）
2. 同一 Type 是否可能需要不同規則——第一版不支援（見 [`功能分類.md`](./功能分類.md)）
3. SD/DD/CD 多階段出量時，選取狀態每次重選還是延續
4. GH 參照被刪：原先以為會停算。**實測會優雅降級，但太安靜**（[`實測報告.md`](../../../../mcp/rhino/實測報告.md) §5.3）——警告只在上游 param，筆數不變，`None` 傳到末端。null 檢查寫在計算程式碼；涵蓋率加第五態「已選取但參照已失效」
5. `.gh` 二進位的備份策略
6. 估價單對應哪個 `registry_revision`、重跑後如何比對差異

## 7　不要做

- 不要在字典加入「式」單位（見範圍與邊界 §6）

- 不要把損耗率、進位慣例寫死進計算邏輯
