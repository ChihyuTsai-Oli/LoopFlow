## 0　本輪規則

決策編號 `QR-nn`（Round 2）。比照 [`v2/docs/前期規劃/資料生態決策表.md`](../../../v2/docs/前期規劃/資料生態決策表.md)，採三種建議強度：

| 強度 | 意義 |
|---|---|
| **強烈建議** | 最好照做；關係到資料不斷鏈、可復原、避免靜默錯誤或能否長期擴充。若不採用，需先設計同等安全的替代方案 |
| **一般建議** | 可以改，但會增加相應的規則、操作或維護成本；決定時需明確接受代價 |
| **輕鬆建議** | 原則上不影響核心資料鏈，可依實際習慣、時程或介面偏好調整 |

裁決規則沿用 2.0：**任一 AI 標為強烈建議且做法不衝突者直接採用**；強烈建議只涵蓋部分、或做法衝突時，只採用無衝突的共同安全底線，其餘維持待決定。

> 各家只填自己的欄，不代填、不推測其他 AI 的立場。

### 0.1 Codex 第二輪覆核結論（2026-09-02）

Claude 建立的第二輪骨架可沿用，但進入實作前要修正四點：

1. **裸 Rhino GUID 不能單獨作全類型持久主鍵**。它只在單一來源模型內唯一；來源的絕對路徑與 worksession model index／serial 又不能跨電腦、開檔方式與 attach 順序持久化。應採版本化、可分流的 locator（QR-01）。
2. **Dictionary token 與目前算法有語意衝突**。2.0 的 ND-28 明定 `AREA_WD／WH／DH`、`LEN_W／D／H` 各自選軸；現行量測方法卻把三種面積 token 都算最大面、三種長度 token 都算中心線。這不是單純 warning，須先裁決（QR-15）。
3. **測試資產必須與原始工作檔隔離**。幾何、Dictionary、Registry 都在副本補強；每個案例要有期望值、容差與期望狀態，不能只加形狀。
4. **QTY 是獨立產品**。可參考 2.0 的契約與 writer，但不能把 `v2/src/loopflow` 的私有模組變成未版本化的 runtime 相依；實作期也應仿照 2.0 使用獨立整合分支。

## 1　本輪新增的實測發現

2026-09-02 於公司電腦，同一份 `LoopFlow_R_MCP.rws` 以 MCP 唯讀複核。

### 1.1 GUID 跨 session 穩定（解掉阻擋項 2 的關鍵）

本 session 稍早在**不同 Rhino 行程**記錄的三個參照物件 GUID，於 Rhino 重啟後**全部仍指向同一物件**：

```text
ec5f23f1-4d2b-46ba-a136-3eb82ab5928e   ✅ 仍存在（結構 Stair.樓梯）
9bc74080-4bd0-4e90-918b-8c485a999b34   ✅ 仍存在（結構 Curb.墩座）
b4fae896-bf13-4b19-9ff3-6f5ed902ba1f   ✅ 仍存在（CL-06）
```

**意義**：worksession 參照物件的 GUID 來自來源 `.3dm`，不是執行期配發。結構體雖無 `_07_UUID`，仍有可跨 session 持久化的身分。

**未驗證的邊界**：來源 `.3dm` 被編輯後是否仍保持；物件被刪除重畫必然換 ID（與 2.0 的 ECO-11 同源問題）。

### 1.2 `DNA_REF_*` 全部是 Point，不會污染全集

3D 側 92 個 `DNA_REF_*`（2.0 的字典參考線，ED-11 保留用於防止空圖層被 Purge）**全部是 Point**。

因此「Brep ＋ InstanceReference」的全集篩選**誤收數為 0**。但這是巧合而非保證——若日後 `DNA_REF_*` 改用其他幾何，全集就會靜默納入字典佔位物件。

### 1.3 3D 側的實際可量測物件

| 類別 | 數量 |
|---|---|
| Brep（扣除 `DNA_REF_*`） | **39** ＝ 帶標記 30 ＋ 結構 9 |
| InstanceReference | **9** ＝ 帶標記 7 ＋ 未標記 2 |
| Curve | 4（不進計算） |
| **可量測候選合計** | **48** |

結構圖層的**真實幾何只有 9 個 Brep**：Beam 3、Slab 3、Curb 1、Stair 1、Wall-RC 1。**Column.柱 與 Wall-Brick.磚牆只有 `DNA_REF_` 參考點，沒有實體**。

未標記的 2 個 Block 是 `3D_W1`、`3D_D1`（門窗），位於 `base` 圖層，idef 名稱帶 `LoopFlow_3D_R_MCP.3dm :` 前綴（linked block）。

### 1.4 Codex 獨立重跑（2026-09-02，公司電腦）

Codex 對使用者已開啟的 Rhino 8 adopted slot 執行唯讀 `run_python`，沒有開啟 GH、沒有執行產品指令：

- Active document：`LoopFlow_2D_R_MCP.3dm`，單位 `Centimeters`
- 含 reference 的列舉總數：**3116**；Brep **39**；`DNA_REF_*` **92 個且全為 Point**
- §1.1 三個 GUID **3/3 仍存在**且皆為 reference Brep
- 三者的 `ReferenceModelSerialNumber`／`WorksessionReferenceSerialNumber` 都是 **1001**；目前 session 可由 worksession 對回 `LoopFlow_3D_R_MCP.3dm`
- 執行前後 `doc.Modified` 都是 **false**

這證明「GUID 來自來源模型、可跨 Rhino 重啟」成立；但也同時證明 **1001 只是目前 worksession 的解析線索**，不能寫進持久狀態。直接開 3D 時該模型是本機模型，來源 serial／index 的語意會改變；絕對路徑則違反雙機可攜性。因此 §1.1 只解掉「物件 GUID 是否會每次啟動重配」，尚未單獨解掉跨來源、跨開檔方式的完整身分契約。

| **QR-01** | **持久身分未閉合**（QD-02／08／10） | **強烈建議**：以 **Rhino 物件 GUID 作為 QTY 的全類型統一身分**，`_07_UUID` 僅作為顯示與對 Registry join 的次要鍵。依據：§1.1 已證明 GUID 跨 session 穩定，且它是唯一同時涵蓋一般物件、結構體與 linked Block 的欄位。選取 JSON 與一式黑名單一律以 GUID 為鍵，另存 `_07_UUID`（若有）供人閱讀與追溯。**必須同時記錄**：來源 `.3dm` 路徑或 worksession model index，因為 GUID 只在該來源檔內唯一 | **強烈建議，與「裸 GUID 單鍵」衝突**：採版本化 locator。有 `_07_UUID` 時以 project-global `object_id` 為 canonical；無 UUID 時才用「可攜的 `source_model_key` ＋ Rhino GUID」。`source_model_key` 必須是相對專案根目錄的正規化路徑或明確 alias，**不得**是絕對路徑、worksession index 或 runtime serial。另存 UUID／live GUID 供診斷；重複、找不到或多重命中都回 conflict，不猜。共同安全底線：不能只存 GUID，也不能存某台電腦或某次 session 的定位值 | |
| **QR-02** | **輸入權威未定**（QO-13） | **強烈建議**：**規則與單位以現行 Dictionary 為準；空間與類型顯示名用 Registry 快照**。理由：規則是「現在要怎麼算」，屬當下決定；空間歸屬是「發布當時的事實」，屬快照。兩者 revision 不一致時**標記但不整批停**，並在 Excel 明細與報告標明各自來源與 revision。找不到規則＝該件不算並標記，不猜測。此提案與第一輪 Codex／Cursor 的方向一致，本輪只是把它從「建議」升為可裁決條文 | **強烈建議，條件同意**：可採這個權責切分，但每筆結果都要保留 Dictionary／Registry 的 revision 或內容雜湊與欄位來源。revision 漂移可降級續跑；**未知 `schema_id`／`schema_version` 必須整批停止**。缺規則時只有該件為 `不可自動量測`；live 物件不在 Registry 時標 `unpublished／space unresolved`，不得假裝 `EXT` 或靜默丟掉。任何 last-good fallback 都要明示來源，不可冒充 current | |
