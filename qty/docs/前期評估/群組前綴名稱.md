# LoopFlow — 群組前綴名稱

> 櫃體、一式等「整組量測」的群組命名契約。Toolkit 負責寫入與檢查，QTY 負責讀取，兩邊都以本檔為準。
>
> 建立日期：2026-09-03　｜　狀態：**基礎資料，可持續修改**。`CB` 類別已裁決（TKO-13～18／QD-16～19）；類別體系是否擴充仍待裁決（TKO-22／QD-23）。

## 1　為什麼需要前綴

Rhino 的 Group Table 裡什麼都有。2026-09-03 實測 `LoopFlow_3D.3dm` 的 12 個群組：

| 群組性質 | 數量 |
|---|---:|
| 櫃體最外層 | 2 |
| 櫃體子群組 | 8 |
| 非櫃體（樓板、飾條） | 2 |

而且**全部都是自動名稱**（`Group01`、`Group20`…）。沒有白名單就分不出哪些群組該量測；掃全部群組會把樓板和子群組一起算進來。

前綴只回答一個問題：**這一組要用哪一套量測與計價方式**。它不編入分類——高／矮、深／淺、工種、空間都不進名稱（TKO-16／QD-19）。

## 2　名稱格式

```text
[<來源檔名> : ]QTY_<類別>_<序號>[_<說明>]
```

| 欄位 | 規則 | 範例 | 說明 |
|---|---|---|---|
| `<來源檔名> : ` | **不要自己寫**；worksession attach 時 Rhino 自動加上 | `LoopFlow_3D.3dm : ` | 比對必須容許此前綴，否則從 2D 側跑會一個群組都找不到（QD-24） |
| `QTY_` | 固定保留字首，大寫 | `QTY_` | 標示「這是 QTY 要讀的群組」 |
| `<類別>` | 兩碼大寫英文，見 §3 | `CB` | 決定量測與計價方式 |
| `<序號>` | 三位數字，專案內同類唯一 | `001` | 工具負責擋重複，不靠人記 |
| `<說明>` | 自由文字，可中文，可省略 | `主臥櫃` | 只給人看，程式不解析 |

完整範例：

| 名稱 | 意義 |
|---|---|
| `QTY_CB_001_主臥櫃` | 第 1 座櫃體 |
| `QTY_CB_002` | 第 2 座櫃體，未加說明 |
| `QTY_LS_001_玄關燈箱` | 第 1 項一式 |
| `LoopFlow_3D.3dm : QTY_CB_001_主臥櫃` | 同一座櫃體，從 worksession 2D 側看到的名稱 |

## 3　類別表

| 類別 | 代碼 | 對象 | 成員進逐物件計算？ | 估價單呈現 | 尺寸輸出 | 狀態 |
|---|---|---|---|---|---|---|
| 櫃體 | `CB` | 完整櫃體，含門片、檯面、把手與突出物 | **照算**（板件各有字典規則） | 逐物件明細；群組另計一份參考 | Z-up OBB 長寬高原始值 | **已裁決** TKO-13～18／QD-16～19 |
| 一式 | `LS` | 不拆開報價的整座物件，例如燈箱 | **排除**（主動差集） | 一列，數量 1 | Z-up OBB 當尺寸附註，不是計價數量 | **待裁決** QD-23／TKO-22 |

兩類唯一的結構差異就是「成員要不要進逐物件計算」。量測機制完全共用：白名單 → 最外層群組 → 完整成員 → Z-up OBB。

### 3.1 候選類別（未啟用）

先不開，需要時再依 §3.2 逐一裁決。不要先佔名。

| 候選 | 可能對象 | 未啟用的原因 |
|---|---|---|
| `OB` | 一般量體、造型物 | 與 `LS` 的差別只在「要不要拆開算」，多數情況 `LS` 已足夠 |
| `EQ` | 設備、機具 | 多半已是單一物件且有 `COUNT` 規則，不需要群組 |

### 3.2 新增一個類別前必須回答

1. 成員要不要進逐物件計算？（決定它像 `CB` 還是像 `LS`）
2. 估價單上這一列的工種與單位從哪裡來？
3. 與既有類別重疊時怎麼判？
4. 有沒有至少一個真實案子的樣本？

答不出第 1、2 題就不要開類別——那通常表示它應該用既有類別，或根本不該群組化。

## 4　寫入與唯一性規則

以下依 2026-09-03 實測的 Rhino 行為訂定，不是偏好而是必要防護：

| 情形 | Rhino 實際行為 | 工具必須怎麼做 |
|---|---|---|
| `Groups.Add` 指定已存在的名稱 | **靜默加流水號**（`QTY_CB_001` → `QTY_CB01`、`QTY_LS_TEST` → `QTY_LS_TEST01`），不報錯 | 寫入後**讀回實際名稱核對**，與請求不符要當場告知 |
| `ChangeGroupName` 改成已存在的名稱 | 回傳 `false`，名稱不變 | 檢查回傳值，失敗要明確提示 |
| 解散最外層群組 | 名稱消失、成員歸零，子群組不受影響，index 不回收 | 不追蹤舊 index；使用者重新命名一次即可 |
| `_Copy` 複製整組 | 複本自成新群組但**不帶名稱**，不會併入原群組 | 列為待命名，否則該座會靜默不進數量表 |

其他規則：

- 名稱**只寫在最外層群組**。子群組不得帶 `QTY_` 前綴——那會與外層互為子集合，造成重複計量。
- 同一物件**不得同屬兩個 `QTY_` 群組**（例如嵌在櫃體裡的燈箱），必須報衝突，不自行取捨。
- 最外層一律以「成員集合為子群組的超集」判定，不靠名稱、Group Index 或選取順序。

## 5　比對規則（給實作）

```text
^(?:.+ : )?QTY_(CB|LS)_(\d{3})(?:_.+)?$
```

- 前綴與類別碼**區分大小寫**，一律大寫。
- 來源檔前綴可有可無：比對時忽略，但**必須把來源模型記進輸出**，因為不同 attach 模型可能有同名群組。
- 類別碼採白名單列舉，不用萬用比對。遇到未知類別碼要報「不認得的類別」，不可當成一般群組默默略過。
- 整份模型找不到任何符合的群組時，要明確報「本模型沒有 QTY 群組」，不要回空集合了事——這正是前綴比對寫錯時的症狀。

## 6　已知限制與待驗證

| 項目 | 狀態 |
|---|---|
| 類別體系是否擴充到 `CB` 以外 | 待裁決（TKO-22／QD-23） |
| 沒有幾何的一式（清運、管理費、運費） | 不適用群組，維持手動填寫 |
| worksession 下能否對 reference 物件建立或改名群組 | **待驗證**。已驗證的是「群組會跟著 attach 進來且可讀」；寫入應在物件的本機檔進行，尚未實測確認 |
| 巢狀深度上限 | 未定。目前只驗過一層子群組（`Group01` 含 4 個子群組） |
| 序號用完或需要重編時的處理 | 未定 |
