# LoopFlow QTY — 開發順序計畫

> 本文件是 QTY **任務切分與開發順序**的唯一來源。範圍見 [`範圍與邊界.md`](./範圍與邊界.md)，決策狀態見 [`決策紀錄_1.md`](./決策紀錄_1.md)／[`決策紀錄_2.md`](./決策紀錄_2.md)。
>
> 建立日期：2026-09-02　｜　階段：**尚未開工**

比照 2.0 的 [`開發任務與路徑.md`](../../../v2/docs/開發任務與路徑.md)：本表只安排工程工作，**不另立資料或業務答案**。任何需要裁決的問題一律回決策紀錄，不在此處自行決定。

## 1　執行規則

- 一次只修改一個 repo；同一 repo 同一時間只由一台電腦／一個 AI 作業
- P0 裁決完成、準備進入程式實作時，先由 `main` 建立長期整合分支 `qty-development`；每項任務再由該分支建立 `codex/qty-<scope>` 短期分支。日常批次回整合分支，達成發布關卡後才合回 `main`
- 任務開始前確認 upstream、乾淨工作樹與 `pull --ff-only`；結束前完成檢查、commit、push 與交接
- **任務須小到能在單一工作時段完成並留下可驗證的完整狀態**。超過一個時段就先拆，不以未提交檔案換機
- 程式一律放 `qty/src/`，**不得寫進 `v2/src/loopflow`**
- 每個階段結束都是**雙機安全停點**：可換機、可中斷、下次接手不需要口頭補充

## 2　階段總覽

```text
P0  裁決與前置        ← 目前在這裡
     ↓
P1  純 Python 核心    ← 不需要 Rhino，可 headless 測
     ↓
P2  Rhino adapter     ← 需要 Rhino，但不需要 GH
     ↓
P3  選取與持久化
     ↓
P4  Coverage 與預覽
     ↓
P5  Excel 輸出
     ↓
P6  Rhino 入口與發布（最後，且刻意很薄）
```

**倒過來做會很貴**：先做大型 `.gh` 會讓核心邏輯埋進二進位、無法 headless 測試，也無法在多 AI 之間交接。這是 2.0 已驗證的順序，不是偏好。

## 4　P1　純 Python 核心（不需要 Rhino）

以幾何抽象介面接收資料，不 import `Rhino`。可用 `python test_*.py` 直接跑。

| ID | 任務 | 前置 | 完成條件 |
|---|---|---|---|
| **QT-010** | Result／錯誤與來源模型 | QT-005、QT-006 | 成功、warning、不可量測、schema error 都有明確 typed result；每筆保留 Dictionary／Registry provenance，不用例外或字串猜狀態 |
| **QT-011** | 單位換算與量綱驗證 | QT-010 | 先為舊 `quantity.py` 建 characterization tests，再在 QTY 核心重寫最小換算；**修正 `m2` 少除 10000**。不得整檔搬回 1.x 架構；輸出 normalized raw 與 converted exact value |
| **QT-012** | 字典載入與規則 join | QT-011 | `type_id` 與 `layer_path` 兩條查詢路徑；`layer_path` **必須剝除 worksession 檔名前綴**（QR-06） |
| **QT-013** | 面積算法 | QT-012、QR-15 已裁決 | 依裁決後的 measurement token 語意實作；最大單一面 ＋ 體積÷厚度只在適用策略使用。差異超閾值回傳 `不可自動量測`，不回傳淨數量 |
| **QT-014** | 長度算法 | QT-012 | 體積÷端面截面積 ＋ 最長邊對照；**失效時回傳 `不可自動量測`，不得回傳主要值**（QR-03） |
| **QT-015** | 長度 fallback 原型與升格 | QT-014 | 閉合環中心線周長、轉角內外 rail 平均先作 prototype；各至少三種 fixture 通過期望值與容差後才升格，否則維持不可量測 |
| **QT-016** | 計數與體積 | QT-012 | `COUNT` 與 `VOL_WDH` |
| **QT-017** | 開口偵測 | QT-013 | 只回報扣除率與標記，**不自動扣量**（QR-07） |

**P1 停點**：核心可在無 Rhino 環境下對 fixtures 產出正確結果，golden baseline 全綠。

## 10　不在本計畫內

- **MCP 不是產品相依**。它只用於開發期唯讀觀察與無互動驗證，不出現在任何交付路徑
- **公式化 Excel**、**參考單價**、**損耗率**：可選後續或永不進工具（見 `範圍與邊界.md` §5）
- **`QTY_View`／`QTY_ResetView`**：待實際工作一段時間後再決定是否需要

## 11　每階段的交接要求

比照 2.0，每個停點必須留下：

1. 該階段的完成條件逐項核對結果（實際跑過，不是宣稱）
2. 未完成或繞過的項目與理由
3. commit ID 與推送狀態
4. 下一階段的第一個任務 ID

換機時另依工作區 `AGENTS.md` 的交接規範辦理。
