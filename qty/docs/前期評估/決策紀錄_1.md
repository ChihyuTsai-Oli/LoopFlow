## 0　三欄覆核說明（2026-09-02）

- `Cursor 意見` 是 2026-09-02 在公司電腦對同一份 `LoopFlow_R_MCP.rws` 以 Rhino MCP 複核盤點數字，並對照 `v2/docs/資料契約.md` 與 `v2/src/loopflow` 接縫後的判斷

### 覆核結論

整體方向正確：QTY 維持獨立產品、單向唯讀、GH1 可視流程、外部 Python 核心、先視覺檢核再輸出 Excel，均符合 2.0「人決定、系統檢查、可預覽、可重跑、不靜默修復」的原則。

但目前仍有三個實作阻擋項（Claude／Codex／Cursor 一致）：

1. **輸入權威未定**：`Project_Registry.json`、現況物件與現行 Dictionary 發生 revision 漂移時，誰優先尚未裁決（QO-13）
2. **持久身分未閉合**：一般物件可用 `_07_UUID`，但結構體沒有 UUID；「一式」黑名單與外部選取 JSON 尚無全類型共同身分契約（QD-02／QD-08／QD-10）
3. **長度算法尚非可交付答案**：15 件中已有 2 件失效，且轉角與閉合環是常見實務幾何；目前只能標異常，不能保證產出正確數量（QD-07）

Cursor 在模型上另確認、應一併寫進後續契約的三點：

- `_07_UUID` 與 3D 代表 **37/37 為 1:1**（Brep 30 ＋ Block 7）成立
- **2026-09-02**：驗證資料夾已有 `_LoopFlow_Config`（2.0.7：`loopflow/` ＋空的 `loopflow_QTY/`）。Registry revision 4，`objects[]` 37 個與模型 UUID **全部對得上**。QO-13 不再是「沒有檔」，而是「漂移時誰優先尚未裁決」
- worksession 的圖層 `FullPath` 帶 `檔名.3dm::` 前綴；結構體用 `layer_path` join 時必須先正規化，不能拿 Rhino 原字串去對字典

### 進入實作前關卡

比照 2.0，不先做大型 `.gh`：

1. 先裁決上述三項阻擋，定義 QTY 的 `schema_id`／`schema_version`、輸入優先序與物件身分
2. 先建立合法／錯誤 fixtures 與 golden baseline，至少涵蓋直線、轉角、閉合環、包覆面、開口、Block、結構體、參照失效與直接開 3D 兩種工作方式
3. 先做可在 Rhino 外測試的純 Python 核心，再做 Rhino adapter；GH Python 電池只負責轉交與顯示
4. 實作以「掃描 → 分類／選取 → 量測 → Coverage → 預覽 → 明確確認 → Excel」分批，每批都要能取消、重跑並留下可驗證停點
5. Rhino MCP 只用於開發期唯讀觀察與安全的無互動驗證，不成為產品 runtime 相依

### 1.1 櫃體群組量測裁決（2026-09-02）

本節是使用者在 Rhino MCP 實測後的後續裁決，明確增加 QD-02／QD-05 的**櫃體限定例外**，不改一般物件的既有量測策略：

| # | 決策 | 依據與邊界 |
|---|---|---|
| **QD-16** | **完整櫃體以 Rhino Group 為量測單位，不建立 Block** | Block 會阻礙既有 Tag；Group 保留各零件可個別標記。QTY 讀取 Group Table 的真正 Group Name 與完整成員集合，不修改 Nexus／Registry |
| **QD-17** | **帶 `QTY_CB_` 前綴的真正 Group Name 是櫃體群組的唯一判定來源** | 前綴只標記待量測櫃體，不含分類。成員物件名稱不等於 Group Name；一律直接用 `SetGroupName`／Toolkit 指令命名。原本規劃的「物件名稱同步一次」已於 2026-09-03 取消（Toolkit TKO-15 修正），QTY 只有 Group Name 這一個來源 |
| **QD-18** | **櫃體量測固定輸出 Z-up OBB 的原始長、寬、高** | 固定世界 Z 為高度，只在 XY 平面求主要方向；長／寬為校正方向後兩個水平尺寸。群組包含什麼就量什麼，不套標準尺寸、不排除突出物 |
| **QD-19** | **取消高／矮、深／淺四類的自動分類** | Group Name 不編分類碼；QTY 量測層只輸出幾何事實。分類、單位與特殊櫃判斷留到輸出後人工處理，不反向修改 OBB 值 |

MCP 實測（`LoopFlow_R_MCP.rws`，2026-09-02）：模型單位為 cm，兩個各含 11 個 Brep 的相同櫃體群組分別旋轉 0°／45°。World bbox 為 `100 × 36.746 × 75` 與 `96.694 × 96.694 × 75`；從幾何主要水平邊推定方向後，兩者 Z-up OBB 都是 `100 × 36.746 × 75`。該檔兩組成員的物件名稱是 `櫃體群組測試0`／`櫃體群組測試45`，真正外層 Group Name 則為 `Group03`／`Group04`，證明產品必須分清兩種名稱。
