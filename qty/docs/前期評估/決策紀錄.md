## 3　未定案

### 3.1 需要商業判斷

| # | 項目 | 狀況 |
|---|---|---|
| **QO-01** | **開口扣除的閾值** | 原則上不扣門窗開口，但很大的非門窗開口需要判定。扣除率偵測得到（實測 `WL-03` 22.4%、`WL-04` 5.0%、其餘 24 個 0.0%），但**分不出「開口」與「中空構件」**。需要閾值與人工判斷流程 |
| **QO-02** | **進位規則** | 小數第幾位、不足一單位如何計。舊 `quantity.py` 回傳原始 float，無進位邏輯 |
| **QO-03** | **輸出服務誰** | 內部抓預算（可能預填參考單價）或對外空白標單（單價留白），格式不同 |
| **QO-04** | **排序對照表** | 外層「空間優先／工種優先」可用全域開關；內層順序無法自動生成，需獨立對照表（`space_display → sort_key`、`type_display_name → sort_key`） |
| **QO-05** | **工種的來源** | 估價單有「工種」欄，但物件上只有 `type_category`（`WL`、`CB`…）。「磁磚工程」這類工種名稱需要另一層對照 |

## 4　必須先修的既有缺陷

| 項目 | 狀況 |
|---|---|
| `quantity.py` 的 `m2` 換算 | `_area()` 對「才」「坪」正確，但 `m2` 直接回傳 cm²（**少除 10000**）。目前字典沒用到 `m2` 所以**不會發作**，一旦有人新增 `m2` 規則就會出現，錯誤量級一萬倍。**撈回該檔時務必先修** |
| 撈回 `measure.py` 的三處調整 | `load_from_workfiles` → `load_dictionary(session)`；`TYPE_ID_KEY` 已搬到 `foundation.usertext`（值 `"_03_ID編號"`）；`QUANTITY_KEY` 已刪除且本來就不該用 |
| 文件路徑 | 舊報告寫的 `wip/src/loopflow/` 已過時，現在是 **`v2/src/loopflow/`** |

## 5　安全紀律（不可協商）

以下不是設計選擇，是實測付出代價換來的：

| 禁止 | 原因 |
|---|---|
| 在承載使用者工作檔的 Rhino 內以 MCP headless 載入 `.gh` | 已造成一次 Rhino 凍結退出。工具逾時後 MCP ping 成功**不代表** runtime 已恢復 |
| 用 MCP 代開 `.rws` | 需由使用者手動開啟 |
| 用 `run_command` 執行 LoopFlow 產品指令 | 模態視窗導致靜默失效 |
| 把空 `stdout` 當作成功 | 那正是靜默失效的表徵 |
| 把 MCP 設定寫進任何 repo | 本機專屬，路徑含使用者名稱與版本號 |

完整說明見 [`MCP評估/MCP設定交接.md`](../MCP評估/MCP設定交接.md) §7。
