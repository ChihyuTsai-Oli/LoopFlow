## 1　定位與範圍

- 這是《開發順序計畫》**QT-004** 的產出：QTY 開發與正確性測試的共同基準模型，檔名 `loopflow_qty_3D.3dm`，放在 `<LOOPFLOW_QTY_WORKFILES_ROOT>`。
- 內容是一間舊工業單元改造的 Loft（住家兼工作室），同時當 LoopFlow、R2B、R2O、R2M 的示範場景。
- **正確性優先於好看。** 兩者衝突時，量測樣本的尺寸與 oracle 不讓步。
- 不改 `<LOOPFLOW_QTY_MCP_WORKFILES_ROOT>` 的原始 baseline，不改正式字典，不沿用 48 件這個數字。

資產分三種，不混檔：

| 資產 | 內容 | 規則 |
|---|---|---|
| **母模型** | 殼體、空間、所有「正常」量測樣本、群組正常案例 | 凍結後算雜湊；之後任何修改都要升版 |
| **派生檔** | 失效、漂移、碰撞、單位對照、開錯檔、效能放大 | 各自獨立，由母模型複製後修改，註明來源版本 |
| **展示副本** | 家具軟裝、材質微調、燈光、相機 | 由凍結的母模型複製；不回流母模型 |

## 2　建模基準

| 項目 | 規定 |
|---|---|
| 文件單位 | **Centimeters**，絕對公差 0.1（與舊基準相同） |
| 建築座標 | 自訂 U（長向）、V（深向）、Z（高）。**U 軸 ＝ 世界 X 逆時針轉 30°**，原點在世界原點 |
| 專案設定 | `layer_prefix`＝`project_id`＝`M3D`，字典 `LoopFlow_Dictionary_tw.xlsx`（已存在於工作檔區） |
| 圖層 | Type 圖層**一律由 Nexus 從測試字典建立**，不手動新增，否則圖層上沒有 `lf_type_id` |
| 展示專用物件 | 放在 `M3D::` 以外的 `_DEMO::…` 圖層（見 §4.6） |

本文所有尺寸以 cm 寫成 U × V × Z。除非另註，方向指建築座標，不是世界座標。

## 6　Oracle（人工期望答案）

### 6.1 每件樣本要記的欄位

1. 追蹤碼、來源檔與版本、物件身分（有 `_07_UUID` 記 UUID，結構體記 Rhino GUID）。
2. 圖層、Type ID、規則、單位、狀態、空間（結構體後兩項留空）。
3. 建構方式：尺寸、斷面、路徑、開孔、Block transform。
4. **候選量清單**（見下），每一項附人工算式。
5. 換算後的 exact value 與顯示值分開記。
6. 容差。
7. 期望的量測結果與 Coverage 結果：**現階段用文字寫**（例如「應可量測」「應標記為包覆面」「應排除並說明原因」）。正式狀態值要等 QT-002 定義，屆時再對應。

沒有人工答案的樣本標為「探索」，不進 golden。

**候選量清單**——QR-15 未裁決，所以不只記一個答案：

| 類別 | 每件都記 |
|---|---|
| 面積件 | 最大單一面、露出面、背面、水平面合計、垂直面合計、體積、厚度、體積÷厚度、建構時的 W／D／H |
| 長度件 | 中心線長、內側長、外側長、最長邊、體積、斷面積、體積÷斷面積、建構時的 W／D／H |
| 體積件 | 實體積、外包盒體積 |

裁決之後，從清單裡選定哪一項是「程式應輸出的值」。

容差起始值：平面與解析幾何用相對 1e-6；曲面與 Boolean 產生的件先用相對 1e-4，M2 實測後收緊。`COUNT` 與狀態必須完全相符。不得用放寬容差掩蓋單位錯誤或漏面。

## 10　分工與建模順序

誰能做什麼：

| 工作 | 誰做 |
|---|---|
| 測試字典新增 Type、Nexus 同步圖層、登記空間框與樓層框、寫入物件資料、發布 Registry、設定 `_02_建構狀態*` | **使用者在 Rhino 操作**。AI 不得用 MCP 代跑 LoopFlow 產品指令 |
| 幾何建模 | 使用者，或 AI 在**隔離的 Rhino slot** 以腳本產生草稿檔，再由使用者併入 |
| 群組命名 | Toolkit 指令或 `SetGroupName`；寫入後讀回核對 |
| 盤點、量測人工答案的驗算、manifest | AI 以唯讀方式進行 |

階段（全部屬於《開發順序計畫》的 QT-004）：

| 階段 | 內容 | 完成條件 |
|---|---|---|
| M0 | 測試字典加 T-01～T-05；確認專案設定；Nexus 建好圖層 | 字典能載入、量綱檢查通過；圖層齊全 |
| M1 | 殼體、結構、空間框與樓層框 | §3.2 三項實測有紀錄；7 個結構圖層都有實體 |
| M2 | 面積、長度、體積、計數樣本 | 每件有 oracle 或標為探索；已知失效情境各 ≥3 件 |
| M3 | 標記、發布 Registry | Registry 與模型 UUID 全對；結構體無 UserText |
| M4 | 群組、一式、Block、hidden／locked | Group Name 讀回正確；背景群組到位 |
| M5 | **凍結母模型**：版本、雜湊、物件盤點、manifest | 之後才開始複製派生檔與展示副本 |
| M6 | 派生檔；展示副本的材質、燈光、相機 | §8 每組有檔與期望結果 |

M6 之後進入《測試模型.md》§0.4 的三道關卡：三家各自以 Rhino MCP 驗收 → 三家各自重評決策 → 收斂後才寫程式。

## 11　交付物（QT-004 範圍）

- `loopflow_qty_3D.3dm`（母模型）、配套 2D、合法 `.rws`。
- 派生檔與展示副本，各註明來源母模型版本。

大型 3dm 留在工作檔區，不進 Git。manifest 與 oracle 是文字檔，進 repo；建議先放 `qty/docs/模型需求書/`，QT-006 建好測試骨架後再搬。

**不在本範圍**：typed-record fixtures、golden outputs、狀態 enum——那是 QT-002、QT-005。
