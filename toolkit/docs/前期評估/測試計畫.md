# LoopFlow Toolkit — 測試計畫

## 1　三層測試

| 層 | 驗證什麼 | 是否需要 Rhino |
|---|---|---|
| domain unit | 分隔數、單位換算、參數驗證、feature catalog、result 狀態 | 否 |
| geometry golden | 同一 typed input 產生的點、線、弧、實體數量與尺寸 | RhinoCommon 或受控 geometry runtime |
| live Rhino | preview、bake、layer、group、undo、取消／失敗復原與安裝入口 | 是 |

每個 golden case 都保存 input、文件單位、預期物件數、主要尺寸／端點、layer role、warning 與容差。圖像只作輔助，不用 screenshot 取代數值斷言。

## 2　共通安全案例

- 使用者在第一個 prompt、preview 與確認前分別取消
- geometry function 丟 exception、layer 建立失敗、部分 bake 失敗
- 原本已有同名 layer，且顏色／PlotWeight 與 defaults 不同
- selection、current layer、redraw、既有物件屬性在取消／失敗後完全恢復
- 成功操作只有一個 undo step
- cm 與 mm 模型產生相同物理尺寸
- 非平面、非矩形、過小尺寸、零長度、負數與超大輸入明確拒絕
- 不含某台電腦絕對路徑；設定 unknown version 明確停止

## 3　各工具 fixtures

### 3.1 2D Shelf Gap

- X／Y 方向、旋轉矩形、批次多矩形
- `n = 0`、剛好整除、round 邊界、板厚大於可用長度
- 每個矩形各有自己的結果摘要，不以最後一件代表全部
- 2D 與 3D divider 共用同一 equal-division domain 結果

### 3.2 2D Cabinet Symbol

- Tall、Low、Wardrobe Full、Wardrobe Lived-In 各至少三種長寬比
- WorldXY 與旋轉矩形
- 固定 seed 的衣架數、角度與位置可重現；不同 seed 仍符合最小間距
- offset 失敗、非四邊矩形、過窄衣櫃不留下半套幾何
- 原始矩形不被換 layer 或刪除

### 3.3 2D Door／Window

- 8 種門與 3 種窗各有 golden case
- 每種門測 flip 兩側；有／無門檻的 layer role 正確
- 不等扇、淋浴門的輸入上下限
- 三種窗各測 split 1、2、3
- 動態 preview 與最終 bake 的幾何一致
- 既有 layer 不被靜默改 PlotWeight；找不到 Hidden／Dashed 時明確降級

### 3.4 Cabinet features（若 TKO-01／09 採用）

- Generate、Dividers、BOM／Metadata 分開驗收，不靠同一大型 end-to-end 才知道失敗
- 旋轉櫃體與 local frame；L／W／T 不得由三邊排序取代語意
- 純框、單門、雙門、玻璃、Baffle、Upper／Lower／Tall
- 原始 box 預設保留；若使用者選擇 consume，可一次 Undo
- 人工改過 part type／尺寸時 BOM updater 不靜默覆寫
- Toolkit metadata 在 LoopFlow 2.0 Verify／Publish 下不造成錯誤或進入 Registry 核心欄

### 3.5 Cabinet Group／QTY 交界

- 同一組櫃體幾何建立 0°、45° 與任意角度版本；Z-up OBB 的長、寬、高必須在容差內一致，World bbox 只作反例
- 測試真正 Group Name 與成員物件名稱不同；QTY 只接受真正 Group Name
- `SetGroupName` 建立的群組不需同步；共同物件名稱轉換只由 `LF_Cabinet_Group_Sync` 處理
- 同步遇到空白、兩種以上物件名稱、既有重名、部分重疊群組或兩個候選最外層群組時停止，不猜測、不改名
- 巢狀群組必須選到涵蓋完整櫃體的最外層成員集合；子群組不得各自重複計量
- Group 內零件仍可個別使用 Tag；群組建立、改名、同步與檢查不得清除既有 UserText
- 把手、門片、檯面與突出物都納入 OBB；不對量得尺寸套標準值或自動分類
- 弧形、不規則與難以定義的櫃體仍輸出 OBB；人工可在報表判定分類／單位，量測層不改值
- cm／mm 模型輸出相同物理尺寸，內部保留 raw，匯出時才作單位換算

MCP 已有一組探索性基準：各 11 個 Brep，0°／45° 的 World bbox 分別為 `100 × 36.746 × 75`、`96.694 × 96.694 × 75` cm；方向校正後兩組 Z-up OBB 都是 `100 × 36.746 × 75` cm。正式 golden fixture 仍須另存隔離副本與 manifest。

## 4　發布基線

一支 feature 只有同時具備以下項目才可從 experimental 升 stable：

1. domain 與 geometry golden 全通過
2. Rhino 8 正常、取消、失敗、Undo、cm／mm 實機通過
3. feature catalog、直接 command、launcher 與安裝包 smoke test 通過
4. 使用文件列出輸入、輸出、副作用、限制與回復方法
