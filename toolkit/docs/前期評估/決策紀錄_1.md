## 建議強度

| 強度 | 意義 |
|---|---|
| **強烈建議** | 關係到資料安全、可復原、避免靜默錯誤或長期可維護性；若不採用需有同等安全替代方案 |

## 櫃體群組與 QTY 交界裁決（2026-09-02）

以下為使用者在 Rhino MCP 實測後的明確裁決，不再列為待決定：

| # | 裁決 | 理由／限制 |
|---|---|---|
| **TKO-13** | **完整櫃體不用 Block，改用 Rhino Group** | Block 會阻礙既有 Tag 工作；Group 保留各零件為可個別標記的 Rhino 物件 |
| **TKO-14** | **QTY 只認 Rhino Group Table 中帶 `QTY_CB_` 前綴的真正 Group Name** | 前綴只標記「這是待量測櫃體」，不含分類。內容面板的「物件名稱」只是成員屬性，不等於 Group Name；真正名稱須由 `SetGroupName` 或 Toolkit 指令寫入 |
| **TKO-15** | **提供 Cabinet Group 同步與檢查指令** | 同步只把既有共同物件名稱轉成真正 Group Name，供舊模型／既有流程使用；新流程應直接建立真正名稱。檢查必須抓未命名、重名、交叉群組與無法量測 |
| **TKO-16** | **Group Name 只負責唯一識別，不編入高／矮、深／淺或特殊櫃分類** | 原先四類自動分類已取消；分類延後到 QTY 輸出後人工判斷 |
| **TKO-17** | **QTY 對完整櫃體群組輸出 Z-up OBB 的長、寬、高原始值** | 群組包含什麼就量什麼，不修正標準尺寸、不排除門片、檯面、把手或突出物 |
| **TKO-18** | **不修改 Nexus／Registry 契約** | Cabinet Group 是 Toolkit 建模組織與 QTY 量測邊界；Nexus 仍逐物件處理身分與 Tag 所需資料 |

### MCP 實測證據

- 場景模型單位為 cm；兩組各有 11 個 Brep，幾何相同但分別旋轉 0°／45°。
- 目前 `櫃體群組測試0`／`櫃體群組測試45` 是成員的共同物件名稱；真正外層 Group Name 仍是 `Group03`／`Group04`，內部另有子群組。
- 世界座標 bbox：0° 為 `100 × 36.746 × 75`，45° 為 `96.694 × 96.694 × 75`。
- 以幾何主要水平邊自動推定 0°／45°，再計算 Z-up OBB，兩組都得到 `100 × 36.746 × 75`；證明不能用 World bbox，但可由完整群組穩定量測旋轉櫃體。
