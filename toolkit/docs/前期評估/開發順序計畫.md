# LoopFlow Toolkit — 開發順序計畫

> 本文件只安排工程工作；業務與資料答案回到 [`決策紀錄_1.md`](./決策紀錄_1.md) 裁決。

## 1　分支與停點

- 前期文件可留在 `main`
- P0 裁決完成、開始寫程式時，由 `main` 建立 `toolkit-development`
- 每批由整合分支建立 `codex/toolkit-<scope>` 短期分支
- Toolkit 使用自己的 package、tests、Yak 與版本；不改 `v2` 或 QTY 的 runtime
- 每個階段都是可提交、可換機、可獨立回復的停點

## 2　階段總覽

```text
P0  範圍與契約
 ↓
P1  Toolkit foundation + launcher
 ↓
P2  2D Shelf Gap                 最小、先驗證架構
 ↓
P3  2D Cabinet Symbol
 ↓
P4  2D Door / Window             11 種模板
 ↓
P4.5 Cabinet Group 與 QTY 交接   已裁決，不受 TKO-01／09／10 阻擋
 ↓
P5  Cabinet features             不阻擋 P2～P4 發布
 ↓
P6  Yak／RUI／發布驗收
```

## 5　P2～P4　三支 2D 工具

每支都依相同順序：domain → memory geometry → preview → bake → live tests → user docs。

| 階段 | 工具 | 升 stable 前的重點 |
|---|---|---|
| **P2** | 2D Shelf Gap | equal-division 核心、批次結果、旋轉矩形、cm／mm、失敗不留物件 |
| **P3** | 2D Cabinet Symbol | 四型式、固定 seed、原矩形不被改動、offset 失敗可復原 |
| **P4** | 2D Door／Window | 11 型式 golden、flip／preview 一致、layer／linetype 無靜默副作用 |

P2 完成即可產生第一個內測版；P3、P4 逐支加入，不需要等全部完成才驗證安裝架構。

## 6　P4.5　Cabinet Group 與 QTY 交接

依 TKO-13～18 已裁決，**不受 TKO-01、09、10 阻擋**；QTY 的 QT-026 直接依賴這批，因此排在 Cabinet Suite 之前。只需要 P1 的 foundation 與 transaction adapter。

| ID | 任務 | 完成條件 |
|---|---|---|
| **TKT-056** | Cabinet Group 建立／命名 | 選取零件後建立最外層 Group 並直接設定唯一的真正 Group Name；不建立 Block、不影響成員 Tag |
| **TKT-057** | Cabinet Group Check | 唯讀零寫入。報告未命名／缺前綴／重名、最外層與巢狀判定、交叉重疊、已成群但未命名（複製與解散重組最常見）、櫃體圖層上未成群的零件、成員空間不一致與無法量測（TKO-19／20） |
| **TKT-058** | QTY 群組交接契約 | 以真正 Group Name 與完整成員集合交給 QTY；Z-up OBB 的 raw 長寬高、角度、成員數、空間歸屬與錯誤狀態有 typed schema 與 fixtures，不含櫃體分類 |

方向推定必須用最小面積矩形實作，並以 0°／30°／45° 三組同幾何 fixture 驗證不變性。
