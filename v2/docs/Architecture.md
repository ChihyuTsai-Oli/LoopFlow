# LoopFlow 2.0 — 邏輯架構

> 用 ASCII 圖說明 LoopFlow 整體是怎麼組成的，輔助閱讀，**不是規格**。
> 內容整理自 `實作總覽.md`、`工作流程.md` 與實際程式目錄；若與六份實作文件不同，以六份為準。

## 一、一個 repo，四個產品

```
LoopFlow repo
|
+-- v1/        1.x 唯讀參考
|     舊版腳本與字典，只當工作邏輯的證據，不再開發，不可與 2.0 混用
|
+-- v2/        出圖 2.0（現行產品，以 .yak 發布到 Package Manager）
|     本文件說明的主體：從字典、模型資料到圖面 Tag 的整條工作鏈
|
+-- qty/       數量計算（不同產品，前期評估中，尚無程式）
|     單向讀 2.0 發布的 Registry 與物件資料，自己產出 Excel 估價單
|     不寫回物件、不進 2.0 安裝包
|
+-- toolkit/   建模／圖面小工具集（不同產品，前期評估中，尚無程式）
      櫃體與三支 2D 產生工具，獨立安裝包，不是 2.0 的必要相依

+-- docs/      公開使用說明（Rhino 指令 LFDocument 會開這裡）
+-- releases/  已發布的安裝包
```

## 二、產品工作鏈：從字典到圖面

每一步都可以單獨執行、驗證、存檔、重跑；使用者決定何時往下走。

```
+--------------------------------------------------------------------------+
| A. 資料準備（Nexus 選單 1～6）
|
|  [1 開案檢查]        LF_Nexus    確認 .3dm 已存檔、讀專案設定、檢查單位
|        |
|        v
|  [2 同步 Type Layers] LF_Nexus   依 Excel 字典建立圖層與材質
|        |
|        v
|  ( 使用者用 Rhino 一般工具建 3D 模型 )
|        |
|        v
|  [3 登記高程框]      LF_Nexus    封閉曲線＋樓層高程（FFL／FL）
|  [4 登記空間框]      LF_Nexus    封閉曲線＋空間名稱（須在高程框內）
|        |
|        v
|  [5 寫入模型 Metadata] LF_Nexus  把 ID、Type、空間、高程寫到物件上
|  [6 檢核模型 Metadata] LF_Nexus  只比對不寫入，列出不符的物件
+--------------------------------------------------------------------------+
         |
         v
+--------------------------------------------------------------------------+
| B. 發布
|
|  [發布串接資料]  LF_Publish_Exchange
|     全案檢核通過才發；產生唯讀的 Registry 快照（每發一次版次 +1）
|     失敗時保留上一份有效檔，不會留下半套資料
+--------------------------------------------------------------------------+
         |
         v
+--------------------------------------------------------------------------+
| C. 圖面
|
|  [註冊 View]     LF_Anchor_Frame   把剖面與 2D 圖的對應關係固定下來
|        |
|        v
|  [抽出可編輯圖]  LF_Extract_CP     圖 A（連動、不編）--> 圖 B（可人工整理）
|        |
|        v
|  [圖紙與圖號]    LF_Tagger_Layout_ID   建立 Sheet 資料、自動編圖號
|                  LF_Duplicate_Layout   複製配置頁
|                  LF_Catalog            產生圖目錄（選用）
+--------------------------------------------------------------------------+
         |
         v
+--------------------------------------------------------------------------+
| D. 標註
|
|  [建立並綁定 Tag]  LF_Tagger_Grab    直接點選物件綁定
|                    LF_Tagger_Laser   從 2D 圖射向 3D 模型找物件
|                    LF_Tagger_Index   索引類標籤
|        |
|        v
|  [注入顯示資料]    LF_Infuser_Part／LF_Infuser_All   把模型資料填進 Tag
|        |
|        v
|  [健康檢查]        LF_TAG-O   過期塗橘、斷連塗紅；只提示，不自動修
+--------------------------------------------------------------------------+

旁支（隨時可用，不在主鏈上）：
  LF_Data_Viewer            只讀查看單一物件的資料
  LF_Export_Type_Layers     把 Rhino 圖層反向匯出成字典比對檔
  LF_Open_Dictionary(_Export)  開啟正式字典／匯出檔
  LF_Sync_Worksession       多檔協作的 Worksession 同步
  LF_Document／LF_Language  開文件入口／切換介面語系
```

## 三、程式分層（`v2/src/`）

```
+--------------------------------------------------------------------------+
| 1. 入口層  entrypoints/
|    每支 Rhino 指令一個檔（LF_Nexus.py、LF_Tagger_Grab.py …）
|    只負責「轉交」，不放業務邏輯
+--------------------------------------------------------------------------+
         |
         v
+--------------------------------------------------------------------------+
| 2. 派工層  loopflow/
|    bootstrap.py        啟動與載入
|    command_catalog.py  指令身分與實作狀態清單
|    runners.py          指令 ID --> 實際執行函式 的查表
+--------------------------------------------------------------------------+
         |
         v
+--------------------------------------------------------------------------+
| 3. 功能層  loopflow/features/   （依「一起變動的功能群」分，不是一鈕一檔）
|
|    資料準備   project      開案檢查
|               dictionary   讀字典、驗證、同步圖層
|               model_data   空間、物件 ID、高程
|               registry     安全發布唯讀快照
|               viewer       只讀資料檢視
|
|    圖面       view         登記 View
|               drawing      抽出可編輯圖
|               sheet        圖紙資料（圖號、圖名的真相）
|               catalog      圖目錄
|
|    標註       tagger       Grab／Laser／Index／Layout ID
|               infuser      注入 Tag 顯示資料
|               health       TAG-O 檢查與上色
|
|    其他       worksession  Worksession 同步
|               document     開啟文件入口
+--------------------------------------------------------------------------+
         |                                   |
         v                                   v
+-----------------------------------+  +------------------------------------+
| 4. 平台層  loopflow/platform/     |  | 5. 基礎層  loopflow/foundation/
|    隔離所有「有副作用」的操作     |  |    跨功能共用的小工具
|    rhino/   選取、鎖定、顯示、    |  |    config／project_config 設定
|             顏色的快照與還原      |  |    paths      路徑解析
|    excel.py 讀寫簡單 xlsx         |  |    atomic_io  安全寫檔
|                                   |  |    i18n／locale 中英介面句子
|                                   |  |    usertext   物件資料欄位
|                                   |  |    results／logging／version
+-----------------------------------+  +------------------------------------+
```

## 四、資料放在哪裡

```
+-------------------------------+     +--------------------------------------+
| Excel 字典 (.xlsx)            |     | Rhino 物件 UserText
| 與 .3dm 同一層                | --> | 每個 3D 物件自己的現值：
| Type 的預設值與規則           |同步 | ID、Type、空間、高程、備註、版次
| 人工維護的唯一來源            |圖層 | （結構層 00_STR 不寫）
+-------------------------------+     +--------------------------------------+
                                                   |
                                                   | 檢核通過後發布
                                                   v
+--------------------------------------------------------------------------+
| .3dm 所在資料夾／_LoopFlow_Config／loopflow／
|    LoopFlow_Project.json   專案名稱、字典檔名
|    <專案名稱>／            Registry：版本化的唯讀模型快照（給 qty 等下游讀）
+--------------------------------------------------------------------------+

+-------------------------------+     +--------------------------------------+
| %APPDATA%\LoopFlow\           |     | 文件\LoopFlow\
| preferences.json              |     | 官方範本：Tag 圖塊庫、字典範本
| 介面語系偏好（不寫進 .3dm）   |     | 由正式指令從安裝包拷出，不是工作資料夾
+-------------------------------+     +--------------------------------------+
```

## 一句話總結

Excel 字典定義 Type，Nexus 把資料寫到 3D 物件並發布成唯讀的 Registry 快照；圖面端以 View、Drawing、Sheet 為基礎，Tag 綁定穩定 ID 後由 Infuser 填入資料、TAG-O 檢查是否過期。程式上是「入口 → 派工 → 功能 → 平台／基礎」四層，所有會改動 Rhino 或檔案的動作都集中在平台層與安全寫檔。
