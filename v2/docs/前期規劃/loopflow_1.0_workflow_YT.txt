

01 - Data Writing via Nexus
LF_Nexus is the data hub of LoopFlow — and this is where everything begins.
In this video, we walk through the full Nexus workflow:
• Dict. to Layer — generate Rhino layers directly from your dictionary Excel file
• SpaceBoundary — define spatial data by selecting closed curves
• TagTrigger — write dictionary data into all 3D objects on M3D layers, regardless of visibility or lock state
• TagChecker — validate data integrity and catch any objects with missing or incorrect attributes
• Layer to Dict. — reverse-export your current Rhino layers back to Excel, so you can reconcile and update your dictionary after modeling
No manual keying. No copy-pasting between spreadsheets and Rhino. Just define it once, and let Nexus handle the rest.

02 - Section Views & Anchor Frame
Once your 3D model is tagged, it's time to generate 2D drawings — and set up the targeting system that makes everything downstream work.
In this video:
• Use Rhino 8's built-in Section Tools to create clipping section drawings from your 3D model
• Run LF_Anchor_Frame to generate a bounding frame around the 2D output
The Anchor Frame acts as a fixed target for all subsequent Tagger commands. Think of it as a bullseye — Tagger aims at this frame to locate and link data to your 2D drawing.
One rule to remember: never delete the Anchor Frame. If you move the 2D drawing, the frame must move with it.

03 - Auto Layout Numbering & Tag Block Data
This is where LoopFlow starts writing into your layouts — automatically.
In this video:
• Introduction to Tag Blocks — what they are, how they work, and how the write-protection mechanism (x / X) lets you switch individual tags from automatic to manual mode
• LF_Tagger_Layout_ID — auto-number all Layout sheets and write drawing numbers directly into title blocks; customize the numbering format using NamingRules_Config.json
• LF_Tagger_Laser & LF_Tagger_Grab — link material, furniture, and door/window Tag Blocks to 2D drawing data
• LF_Tagger_Index — bind elevation and section index Tag Blocks to their Detail Views
• LF_Infuser_Part & LF_Infuser_All — inject all linked data into Tag Blocks across one layout or all layouts at once
After Infuser runs, each Tag Block displays its state:
🟣 Purple — linked and written
🟠 Orange — not yet linked
🔴 Red — broken link (source deleted)


04 - 3D Model to 2D Layout Synchronization
Design changes are inevitable. This video covers what happens when they do — and how LoopFlow keeps everything in sync.
We walk through real-world scenarios:
• Modifying a 3D object — how to re-push data to Project_Registry.json and re-run Infuser to update all affected Tag Blocks
• Deleting a Detail View — what causes a Tag Block to turn red (broken link) and how to re-link it
• Handling layout restructuring without losing your data connections
This is the core promise of LoopFlow: you change the model, the drawings follow. Not automatically without you — but with minimal effort from you.

Extra 01 - Section Linework Extraction by Color
Section Tools generates 2D linework, but the output layers aren't always what you need for your drawing setup. LF_Extract_CP solves that.
In this video:
• How LF_Extract_CP extracts Section Tools output by color into separate new layers, making it easy to select, reassign, or restyle individual line categories
• The critical rule: if you move extracted 2D linework to a new position, the Anchor Frame must move with it — Tagger commands rely on the frame to locate the drawing, not the linework itself
A small detail that prevents a lot of broken links later.

Extra 02 - Cabinet Suite Generator
LF_Cabinet_Suite is a dedicated cabinet modeling tool built into LoopFlow — 30 combinations covering carcasses, doors, and shelves, with BOM dimension data calculated automatically.
In this video:
• Walk through the Cabinet Suite interface and generate cabinet models
• Understand the two BOM modes:
  — Models generated by Cabinet Suite: dimensions written automatically, works on any layer
  — Manually built models: use BOM Update to write dimensions (must be on the M3D::04_CB layer)
• Why you can safely select all objects when running BOM Update — it only writes to objects on the cabinet layer, everything else is ignored
• The 1mm panel gap explained: it's intentional for rendering, and BOM compensates for it automatically in all dimension output


Extra 03 - 2D Drawing & Cabinet Generator
