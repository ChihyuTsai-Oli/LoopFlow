## 工作資料夾

**`.3dm` 所在資料夾就是工作資料夾**，不再用環境變數指定。

- 專案設定：`<3dm 資料夾>\_LoopFlow_Config\LoopFlow_Project.json`
- 採用 Dictionary：`<3dm 資料夾>\<檔名>.xlsx`（預設 `LoopFlow_Dictionary.xlsx`；可改名，檔名記在專案設定 `dictionary_filename`）
- 交換 JSON：`<3dm 資料夾>\_LoopFlow_Config\<專案名稱>\`
- log：`<3dm 資料夾>\_LoopFlow_Config\logs\loopflow.log`
- 介面語系：`%APPDATA%\LoopFlow\preferences.json`（這台電腦；不在專案資料夾、不寫 `.3dm`）
- Registry 正式檔／lock／pending／last-good 檔名見 `資料契約.md`
- 雙機實際的 Dropbox 工作檔位置：依 workspace 根目錄的 `工作檔路徑.md`

三者（`.3dm`、Dictionary、`_LoopFlow_Config`）只以相對關係綁定，整包搬到別的上層目錄或別的磁碟都不影響；`LOOPFLOW_WORKFILES_ROOT` 已停用。

2.0 官方 Dictionary 範本在 `v2/docs/字典/`：`LoopFlow_Dictionary_tw.xlsx`（繁中，微軟正黑體）、`LoopFlow_Dictionary_en.xlsx`（English，Arial）。`v1/LoopFlow_Dictionary.xlsx` 是 1.x 參考，不作 2.0 來源。專案使用時仍把選用的那一份複製到 `.3dm` 同一層（檔名可改，記在專案設定）。程式不寫死任何電腦的絕對路徑；`.3dm` 未存檔時停止相關操作並說明要先存檔。

## 介面語系

正式發布只出**一份** `.yak`，不要中／英兩個安裝包，也不要兩套程式。

| 項目 | 規則 |
|---|---|
| 套件 | 同一份 `.yak` 帶程式＋兩份顯示句子表（繁中／English） |
| 開發期 | 記住語系後，彈窗、選單、成功／失敗說明依定稿切換；未記住時用英文。句子表定稿為 `介面語系/3_claude/介面語系_final.md`，程式讀產出的 `foundation/i18n_catalog.json`，不即時讀 markdown。第一次跑任一產品指令會問正體中文／English，並說明之後可用 Document 右鍵切換。選擇記在這台電腦。Dictionary 載入認繁中或英文欄名；只用 Nexus 選中的那本 |
| 抽出去的 | 彈窗、按鈕、清單標題、成功／失敗說明、選單給人看的字、Dictionary 顯示欄名 |
| 留在程式裡的 | 繁中註解、指令 ID、JSON／machine key、物件 UserText 鍵（如 `_01_空間名稱`）、網址與檔名 |
| 語系存在哪 | `%APPDATA%\LoopFlow\preferences.json`（這台電腦）。**不寫進 `.3dm`**，也不放 `_LoopFlow_Config` |
| 第一次 | 任一產品指令第一次跑時問正體中文／English，記住。取消則不記住，下次再問。未記住前畫面用英文。沒有 Rhino 介面時不擋測試 |
| 之後要改 | **Document 右鍵**跑 `LFLanguage`（左鍵仍開文件入口）。命令列也可打 `LFLanguage`。不另加工具列按鈕，不放進 Nexus |
| 猜測 | Rhino 不猜介面語系，也不依 Dictionary 檔名或 Windows 語言自動切 |
| 公開文件 | 一篇一語；繁中為真相、英文為翻譯。入口頁 `docs/README.md` 上半英文、下半中文，表格只連該語指南。繁中指南檔名維持 `USER_GUIDE_TW.md`、`Dictionary_GUIDE_TW.md` |
| Tag 圖塊 | 只維護一份 `v2/docs/Tag_Blocks_3dm/Tag_Blocks.3dm`；檔內中英說明並列，不另做中／英兩個 3dm。公式預設提示維持英文 |

記住語系後，畫面句子會切換。要在 Rhino 看到英文：開發按鈕指向 repo 時關 Rhino 再開即可；已裝的 yak 須等下次升版。Dictionary 繁中／英文欄名都可載入，只認 Nexus 選中的那本。`介面語系.md` 是較早的檢視稿，英文以定稿為準。

2.0 由 `loopflow.foundation.paths.resolve_project_folder` 從目前 `.3dm` 位置組出工作資料夾、`_LoopFlow_Config` 與字典路徑；專案設定由 `loopflow.foundation.project_config` 讀寫。Registry 在 `_LoopFlow_Config/<專案名稱>/`。Dictionary 預設檔名 `LoopFlow_Dictionary.xlsx`，可改成同一層的其他 `.xlsx`；不掃全部 Excel、不猜檔名。測試注入暫存資料夾當 `.3dm` 位置，不依賴真實 Dropbox。log 檔名屬進階設定（預設 `logs/loopflow.log`）；Registry 檔名不是設定。

## 2.0 開發模式

- `v1/` 與 `v1.0.0` 是 1.x 唯讀參考，不在現行產品上做成半新半舊系統。
- 2.0 已發布；後續仍在 `v2/src/`、同一套 yak 建置、設定與測試資料上改。
- 數量計算在 `qty/`，不接 Nexus、不寫物件、不進 2.0 yak。
- 開始建立新 feature 前，契約以 `資料契約.md` 為準。A03–A06 已完成。
- 新核心只接受 2.0 canonical contract；2.0 不提供一鍵從 1.x 升級。
- 每批仍須有自動測試；改到已實機過的主鏈時，在 `重構進度.md` 標明是否已重跑 Rhino 實機。

## 重構期間的 Rhino 測試入口

重構期間直接從 repo 執行開發中的入口，不必先複製到 `%APPDATA%`。Rhino 測試按鈕固定指向 `entrypoints/`，不要直接指向仍會調整的 `features/`、`platform/` 或 `foundation/` 內部模組：

```text
E:\_GitHub\LoopFlow\v2\src\entrypoints\
```

本機開發按鈕目前仍指向舊路徑 `E:\_GitHub\LoopFlow\wip\src\entrypoints\`。日常用已裝的 yak 工具列即可。日後若要用 repo 開發入口，再改成上面這條，細節見 `rhino指令.md`。

目前可跑的指令清單與按鈕巨集（含左鍵／右鍵配置）統一維護在 **`rhino指令.md`**，本節不再複製一份會過期的清單。`LF_Test_Random_M3D_Layers.py` 只是開發期輔助：把**目前選取**的物件隨機分到專案 M3D 底下的類型子圖層（例如 `M3D::00_STR_結構::Slab.樓板` 只會分到 `Slab.樓板` 這種末端圖層，不會分到 `00_STR_結構` 或 `_Data`）。略過 `DNA_REF_` 與空間／樓層框。`LF_D08_Migrate_Display_Keys.py` 同樣是開發期輔助：全檔圖塊把舊顯示欄抄到 `lf_*` 後刪舊 key；鎖定欄若寫 `x`／`X` 會抄到 `lf_00_lock_state`。**都不是產品指令**，不進正式工具列。

不要用工具列上的 1.x `LF_Nexus` 或 1.x `LF_Data_Viewer`。Nexus 成功連上後會先做開案檢查，通過才跳出步驟清單：

```text
1  開案檢查
2  從字典同步 Type Layers
3  登記高程框（封閉曲線）
4  登記空間框（封閉曲線，須在高程框內）
5  寫入模型 Metadata
6  檢核模型 Metadata（不寫入）
```

Esc 取消後續步驟。缺框或 Dictionary 驗證失敗會彈窗說明（含第幾列）。寫入後用選 **6** 核對。匯出字典與發布已改為獨立指令：`LF_Export_Type_Layers` 只在字典目錄新增 `{原檔名}_Export.xlsx`（第 1 列紅色提示），有變動的 `diff_status` 會換色；`LF_Publish_Exchange` 須全案檢核通過，才寫入目前 `.3dm` 旁 `_LoopFlow_Config/<專案名稱>/Project_Registry.json`，並把版次寫進物件 `_14`。`LF_Open_Dictionary`／`LF_Open_Dictionary_Export` 只開啟既有 xlsx。

### 隔離測試檔準備

請開**新的測試 `.3dm`**，存檔後即可用，不必再開文件 UserText 手填 UUID。文件單位建議 cm。第一次跑指令會順便在 `_LoopFlow_Config/LoopFlow_Project.json` 寫入 `schema_id`／`schema_version`。專案名稱在 Nexus 選單 2 填，同時寫入設定檔的 `layer_prefix` 與 `project_id`。

**把 `LoopFlow_Dictionary.xlsx` 複製到測試 `.3dm` 同一層**（雙機的 Dropbox 來源位置見 `工作檔路徑.md`）；不再設環境變數。設定檔、Registry 與 log 都會出現在該 `.3dm` 同目錄的 `_LoopFlow_Config/` 下。整包資料夾搬到別處或別的磁碟仍可用。

### 建議實機順序

1. 先跑指令，確認出現清單。選 **1** 只看開案檢查訊息。
2. 選 **2**：每一次都彈出視窗問專案名稱，第一次不預填 `M3D`；之後框裡預填已記住的名稱，按 OK 即可。Dictionary 只在第一次同步、或已記住的 `.xlsx` 改名／搬離 `.3dm` 同層時才選檔；選過會記住。找不到時應先彈窗說明「請把字典移回 `.3dm` 同一層」，再開選檔視窗，起始位置就是 `.3dm` 所在資料夾並預選記住的檔名。選到別的資料夾會說明並**再跳出選檔**，不要直接結束。字典改名後應能重新選取並記住新檔名。應出現對應 Type layers 與原點 `DNA_REF_` 點；已有同名 layer 的 UserText 不被蓋掉。圖層應有顯示色；新建材質顏色與圖層相同，已有材質不改色。再跑一次不應累加 `DNA_REF_`，舊參考線應被點取代。Esc 取消不應留下半套 layer。
3. 選 **3** 登記高程框（封閉曲線）：彈出清單點選 FFL 或 FL，選封閉曲線後按 Enter，再彈出視窗輸入高程（`0`、`320`）。選 **4** 登記空間框（封閉曲線，須在高程框內）：可複選，彈出視窗輸入「廊道」或「衛浴」。選線只用曲線過濾，不鎖全檔實體。房間框須與高程框高差 ±20 且整圈在高程框內。框線只寫 UserText，不改物件名稱。不必手填樓層 UUID。
4. 在 Type layer 上放測試用 3D 物件。選 **5** 寫入模型 Metadata：物件 UserText 應為 `_01_空間名稱`（無 `*`）、`_03_ID編號`、`_05_高程基準`、`_07_UUID` 等中文編號 key，**沒有**寬深高或實作數量。空間框仍是 `_01_空間名稱*`。樓面高程框填 50、窗台 BH 在相對高度 100 時 `_06` 應為 150。物件在房間內應寫入空間名稱而不是 `EXT`。跨多空間會彈出清單點選。選 **6** 檢核模型 Metadata：相符會彈窗；不符會彈窗說明、提醒跑 **Nexus 5**，並一次選取那些物件。手動改 `_14` 應被報成不符，選單 5 會寫回正確版次。

## 自製 Eto 面板慣例

### Rhino 內建 Section 按鈕

目前工具列中複製排列的 Section 按鈕只包含簡單 Rhino Macro，例如 `! _ClippingSections`。2.0 保留這種快捷入口，但它們不列入 Python entrypoint 清單：

```text
! _ClippingSections
! _ClippingDrawings
! _ClearClippingSections
! _EditClippingDrawings
! _UpdateClippingDrawings
```

正式安裝包部署 LoopFlow 自有工具列（RUI）；Macro 仍由 Rhino 8 內建指令執行。不得複製 Rhino Section 程式本體，也不以 Rhino 預設 Macro／bitmap GUID 作長期必要相依。安裝與升級只管理 LoopFlow 工具列，不覆蓋使用者完整 workspace。圖示由使用者在 Rhino 8 排工具列時決定。

## `_LoopFlow_Config.py` 可編輯設定

### Dictionary

| 設定 | 預設值 | 用途 |
|---|---|---|
| `DICTIONARY_FILENAME_XLSX` | `LoopFlow_Dictionary.xlsx` | Dictionary 檔名 |
| `DICTIONARY_KEY_COLUMN` | `__Rhino Layer` | layer 主鍵欄 |
| `DICTIONARY_SKIPROWS` | `1` | 資料前略過列數 |

### Layer

| 設定 | 預設值／規則 |
|---|---|
| `LAYER_PREFIX_3D` | 預設 `M3D`；實際以前綴文件 UserText `lf_layer_prefix` 為準 |
| `LAYER_DATA_SUFFIX` | `_Data` |
| `LAYER_SPACE_BOUNDARIES` | `M3D::_Data::Space_Boundaries` |
| `LAYER_LEVEL_FFL` | `M3D::_Data::Level_Boundaries_FFL`；高程寫在 `_15_樓層高程`，不寫物件名稱 |
| `LAYER_LEVEL_FL` | `M3D::_Data::Level_Boundaries_FL`；同上 |
| `LEVEL_Z_TOLERANCE` | `20`（模型單位；建議 cm 時為 ±20 cm） |
| `LAYER_DW_PLAN` | `M3D::20_DW` |
| `LAYER_CABINET_PREFIX` | `04_CB` |
| `LAYER_PREFIX_2D` | `M2D`（一般 2D 內容；1.x 現況） |
| `LAYER_ANCHOR` | `LoopFlow::Anchor_Frame`（2.0 View 框；父圖層是 `LoopFlow`，不是 `M2D`） |
| `LAYER_EXTRACT_ROOT` | `LoopFlow_Extract`（Extract 產出根圖層，與 `LoopFlow` 平級。可列印；Visible／Hatch 列印色 `#BEBEBE`，其餘黑。子層 `Visible`／`Hatch`／`Curve_#RRGGBB`） |

修改 3D prefix 不會自動改名既有 layer，且部分值需要重啟 Rhino；不得把它視為無風險文字設定。

### 系統檔案與並行

| 設定 | 預設值 |
|---|---|
| `REGISTRY_FILENAME` | `Project_Registry.json` |
| `REGISTRY_LOCK_FILENAME` | `Project_Registry.lock` |
| `DEBUG_LOG_FILENAME` | `cursor_LF_debug_log.txt` |
| `SYNC_INTERVAL` | `0.5` 秒（2.0 對應 `AppConfig.worksession_refresh_delay`） |
| `LOCK_TIMEOUT` | `20.0` 秒 |
| `STALE_LOCK_SECONDS` | `30.0` 秒 |

Registry P0 已由 C03 實作：活著的持有者不可搶 lock；同機死 PID 或 lock 超過 30 秒視為 stale。不等待 20 秒重試，鎖定中立即停止。獨立指令 `LF_Publish_Exchange` 呼叫 C03。

### 其他設定

- 2D layer 與顏色：門窗、櫃體、Defpoints、Extract。2.0 Extract 根圖層是 `LoopFlow_Extract`（見上表）；1.x 仍是 `Extract`。
- Block definitions：Index、Height、Finish、Item、Door/Window 與 title frame。現行 `TAG_DW` 已改純手動，但 1.x Config／Infuser 仍把它列為資料 Tag；2.0 不承接這個衝突。
- `WHITE_LIST`：TagTrigger／Checker 不覆寫的 UserText key。
- Layout 命名：`LAYOUT_NAME_SEPARATOR`、copy suffix、baseline marker。
- Ceiling／mirror keywords 與 `INVERT_Y`。

完整實際值以 `_LoopFlow_Config.py` 為準；文件改動時必須核對程式，不建立第二份可執行設定。

上表描述 1.x 現況。2.0 的 Dictionary resolver 只認 `.3dm` 所在資料夾加上專案設定記住的檔名；不掃子資料夾、不猜檔名。

## 不屬於使用者設定的契約

下列內容應集中於所屬 module 並測試，但不因「硬編碼」就移至 config：

- Rhino command 字串與 API type mask。
- 完整 layer path 組裝規則與 legacy alias；2.0 以 `資料契約.md` 為準。
- Registry schema、pending／last-good 檔案命名與 result stage。
- UUID／UserText canonical key（`lf_*` 前綴與 JSON `snake_case`）。
- Tag Block 內部欄位與幾何容差。

## Build 與 Release

### 1.x（歷史發布；說明可改）

- `build.ps1` 將 `v1/` 打包成本機 `releases/` 下的 ZIP（不進 git）。

### 專案範本

Yak 按下安裝時不能跑複製腳本。官方檔留在套件 `templates/`；Rhino 第一次執行任一 LoopFlow 產品指令（套件此時才載入）再處理給人複製的那份。不必先有專案、也不必先有字典：

| 項目 | 規則 |
|---|---|
| 套件內 | 官方 `Tag_Blocks.3dm`、Dictionary 範本，以及程式用的 `tag_templates.json`，隨套件升級而更新 |
| 給人複製 | `%USERPROFILE%\Documents\LoopFlow\`（中文 Windows 即「文件\LoopFlow」） |
| 第一次載入 | 該資料夾沒有對應檔才從套件拷入；**已有的檔不要蓋掉** |
| 開資料夾 | 這次確實有拷檔才開啟 `文件\LoopFlow\`；之後載入不再跳檔案總管 |
| 專案使用 | 使用者把需要的檔複製到已存檔 `.3dm` 同一層；Dictionary 仍須與 `.3dm` 同層才算這份專案的正式字典 |

`文件\LoopFlow\` 不是專案工作資料夾，只是好找的範本來源。真正工作仍以 `.3dm` 所在資料夾為準，見上文「工作資料夾」。

工具列：

- 版面、圖示、左鍵／右鍵由使用者在 Rhino 8 排好，再交給封裝放進同一份 `.yak`。裝完就有那一排按鈕。
- 存 **RUI**，不把 RHC 當 2.0 正式格式。1.x 的 `LoopFlow.rhc` 可當版面參考。
- 在 Rhino 8 存 RUI：`工具` → `選項` → `工具列` → 左上 `檔案` → `新增`，存成 `LoopFlow.rui`（不要改 Rhino 內建那份）→ 排按鈕 → 務必再按 `檔案` → `儲存`。只關 Rhino 的話，改動可能只留在 `%AppData%` 底下 Rhino 8 的暫存 XML，複製出去的 `.rui` 會是空的或舊的。交乾淨檔給封裝：命令列打 `ExportRuiFile`。
- 開發期按鈕仍用 ScriptEditor＋repo 路徑。進包後左／右鍵改成正式名稱，例如 `! _LFDocument`。Section 仍是 `! _ClippingSections` 等內建巨集。
- 使用者已交獨立的 `LoopFlow.rui`（來源 `v2/docs/toolbar/LoopFlow.rui`）。建置時刪掉 RhinoCode 自動產生的那份，再複製這份進去。不覆蓋使用者整個 workspace，也不改 `mori LoopFlow`。
- 產品 RUI 必須含一個指向既有 LoopFlow 工具列的 `tool_bar_group`（顯示名 `LoopFlow`）。**不要**改 RUI 檔 GUID 或工具列 GUID，**不要**寫入 `SelectedToolbarSet`。空的 `<tool_bar_groups />` 會在 Rhino 把這份檔當成目前工具列套件時讓畫面空白。
- 裝完若仍空白：工具列視窗改回 Default，再開啟套件裡的 `LoopFlow.rui` 並勾選 LoopFlow。

建置路徑（本機已核對）：Rhino 8 Script Editor 專案 `*.rhproj` → `"C:\Program Files\Rhino 8\System\RhinoCode.exe" project build` 產生 `.rhp` → `yak.exe build` 打成 `.yak`。不做 RHI。不可沿用 1.x 攤平腳本複製到 `%AppData%\...\scripts\LoopFlow\`。重裝同版時 Rhino 可能不更新指令清單，必要時加版本號。Package Manager 已上架 `loopflow` 2.0.5。

手寫的 `.rhproj` 即使 JSON 能被讀取，RhinoCode 仍會判定「存成 Rhino 8.9 或更早」而拒絕建置。**必須在 Rhino 8.11 以上的 Script Editor 新增專案、加入 `commands/` 下各正式指令 `.py`（名稱見 `指令名稱.txt`）、把 `v2/src` 加到 Libraries、另存成 `v2/packaging/g02-spike/LoopFlow.rhproj`，再跑 `build.ps1`。** 現在不要改開發期入口檔名。產品工具列來源是 `v2/docs/toolbar/LoopFlow.rui`。

指令的 `language` **必須是物件**，不可寫成字串 `"python3"`。字串會讓 RhinoCode 把 Python 當 C# 編譯（錯誤像 `__future__`、`def`、`import`）。正確寫法：

```json
"language": { "id": "*.*.python", "version": "3.*.*" }
```

腳本第一行用 `#! python 3`（中間有空格）。重裝同版可能不更新；最小 spike 為 `0.1.2`，全部正式指令為 `0.2.0`，附產品工具列為 `0.2.1`，含 Catalog 修正為 `0.2.2`。**公司 Rhino 8 已測（2026-08-21）**：命令列 `LFDocument` 可用，且不取代 `mori LoopFlow`。

RhinoCode `project build` 會順便產生 `LoopFlow.rui`。**建置時要刪掉自動產生的那份，再複製 `v2/docs/toolbar/LoopFlow.rui`。** 自動產生的那份會把 `Options.Toolbars.SelectedToolbarSet` 切走，原本的 `mori LoopFlow` 看起來像消失（檔案其實還在 `%APPDATA%\McNeel\Rhinoceros\8.0\UI\mori LoopFlow.rhc`）。產品 RUI 不覆蓋使用者 workspace，也不改 `mori LoopFlow`。
