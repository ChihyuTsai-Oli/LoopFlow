# LoopFlow 2.0 — 任務切分與開發路徑

本文件是任務 ID、工程前置、工作波次與雙機安全停點的唯一來源，把 2.0 重構拆成可在單一工作時段完成、驗證、提交與推送的單位。資料規格以 `資料契約.md` 為準；使用者操作順序以 `工作流程.md` 為準；即時狀態只記錄於 `重構進度.md`。本表只安排工程工作，不另立資料或業務答案。

## 執行規則

- 一次只修改一個 repo；同一 repo 同一時間只由一台電腦／一個 AI 作業。
- 每項任務從 `v2-development` 建立 `codex/v2-<scope>` 短期分支，不直接在整合分支施工。
- 任務開始前確認 upstream、乾淨工作樹與 `pull --ff-only`；結束前完成檢查、commit、push 與交接。
- 任務須小到能留下可驗證的完整狀態。若超過一個工作時段，先拆成子任務，不以未提交檔案換機。
- `%APPDATA%` 只用於正式安裝／RC 隔離驗證；開發期 Rhino 按鈕直接指向 repo 的 `wip/src/entrypoints/`。
- 下表是開發路徑，可隨功能增減、實測結果與架構調整；改動時同步更新本文件、系統設定與 `重構進度.md`。

## 建議開發波次

1. **契約波次**：A01–A06。只建立可裁決、可測的資料定義，不搬正式功能。
2. **架構波次**：B01–B03。只建立第一條功能真正需要的最小骨架。
3. **核心資料鏈**：C01–C04。Nexus 依 `Nexus拆分計畫.md` 的 NX-01～05、NX-07 逐包實作；C05 尺寸／數量不屬 2.0。
4. **可重複功能接入**：D01–E05 已完成主鏈（Grab／Laser／Index／Layout ID／View／Catalog）。D08 圖塊資產與停雙寫已完成。D06 Infuser Part、D07 Infuser All **公司已測（2026-08-19）**。D05 TAG-O 已有自動測試。剩餘：**E02 Extract → E03 Duplicate Layout → E04 Worksession**。操作邏輯：Infuser 注入 Tag → TAG-O 確認活著或斷連 → 下一輪 Infuser。全鏈實機通過後視為工具定案。每支入口獨立任務，逐項實機驗證。不要開尚未輪到的項。
5. **Loopflow_Toolkit（日後）**：Cabinet Suite 與三支 2D 工具不在本 repo 重構。獨立 repo 與 R2B／R2O 同級，建 repo 前再排程。
6. **切換與發布**：工具定案後才做 G01–G03（migration、安裝檔技術另議、Package Manager 另議、中英雙語與 GitHub 說明）。完成後才合入 `main`。

## 雙機換機檢查點

每次換機前必須達成：工作樹乾淨、任務分支已 push、upstream 差距 `0/0`、`重構進度.md` 記錄完成／未完成事項與下一步。另一台電腦先拉 workspace root 與全部子 repo，再從遠端分支續作；不可用雲端同步資料夾或手動複製程式碼取代 Git。
