# LoopFlow 2.0 — 工作流程

本文件是實作與驗收使用者操作順序、介入點、安全停點與重跑行為的唯一來源。資料語意以 `資料契約.md` 為準；工程相依以 `開發任務與路徑.md` 為準。

## 工作原則

- 每一階段可以單獨執行、驗證、存檔與換機。
- 使用者決定何時寫入、何時發布、綁誰、更新當頁或全案。
- 系統先報告影響，再執行有副作用的動作。
- 取消、失敗或中斷不得破壞上一份有效資料或 Rhino 工作狀態。
- 1.x 按鈕順序不是限制；保留的是已驗證可行的工作邏輯與控制點。

## 一條完整工作鏈

```text
開案檢查
→ 從字典同步 Type Layers
→ 建立 3D 模型
→ 登記高程框與空間框
→ 寫入模型 Metadata
→ 檢核模型 Metadata
→ 選用：匯出 Type Layers 為字典（獨立指令）
→ 發布串接資料（獨立指令）
→ 建立 Section／註冊 View
→ Materialize 可編輯 Drawing
→ 建立 Sheet／圖框／Layout ID
→ 建立並綁定 Tag
→ 選用：建立圖目錄（獨立指令 `LF_Catalog`，須先有 Sheet metadata）
→ Sync 顯示資料
→ Health／Repair
```

## 1. 開案檢查

**動作**：解析 `LOOPFLOW_WORKFILES_ROOT`、Dictionary、`exchange/`、project identity、schema version 與 Rhino 文件單位。

**使用者介入**：只有設定缺失、專案辨識不明或非 cm 警告時處理。

**結果**：顯示實際生效的路徑、版本與單位。非 cm 不阻擋，但明確警告風險並建議切換為 cm。

**失敗**：停止，不猜磁碟機、不建立檔案、不修改 Rhino 文件。Dictionary 驗證失敗會彈窗列出第幾列、什麼原因（例如 type_id 重複）。找不到 Dictionary 檔時不擋選單，警告並請用選單 2 指定。

## 2. 從字典同步 Type Layers

**Validate**：檢查 15 欄、schema、Type ID、類別與 layer mapping、單位、measurement rule、量綱與必填值。

**Sync**：

- 每一次同步都彈出視窗問專案名稱（圖層前綴）。第一次不預填 `M3D`；檔案已記住名稱時把文字預填在框裡，按 OK 即可，也可改名。名稱寫入文件 `lf_layer_prefix`，不是專案 UUID。未寫入前綴時圖層樹仍用 `M3D`。
- 同步 Type Layers 時才選 Dictionary `.xlsx`。第一次選檔並把檔名記住在 `lf_dictionary_filename`；之後沿用記住的檔。只有該檔找不到（例如改名）才再跳出選檔。預設建議 `LoopFlow_Dictionary.xlsx`。開案檢查不選檔；找不到檔時仍可進選單並警告。不掃全部 Excel，也不從 `.3dm` 旁猜。
- Dictionary 有、Rhino 沒有的 layer：建立並帶入初始 layer defaults。
- 已存在的同名 Rhino layer：保留既有 UserText／construction；顯示色依圖層代號前綴重套。新建材質顏色跟圖層；已存在的同名材質只掛接、不改色。材質名稱不含專案前綴，不改物件 instance 顏色。
- 不覆寫 object instance 的 `_02` 狀態，也不把 object data 回寫 Dictionary。
- 不執行 ZoomExtents，不改變使用者視圖。
- `DNA_REF_` 參考點放在 `(0,0,0)`，依穩定 Type ID 更新或取代，避免空 Type layer 被 Purge 且不重複累積。
- `20_DW` 維持單一 Type，排除 child layers。

**選用反向匯出**：獨立指令 `LF_Export_Type_Layers`（匯出 Type Layers 為字典）在 Dictionary 同一目錄新增 `{原檔名}_Export.xlsx`（例如正式檔 `LoopFlow_Dictionary.xlsx` 就匯出 `LoopFlow_Dictionary_Export.xlsx`；完整 15 欄加上 `diff_status`）。最上方一列紅色提示說明：此檔不能當正式字典、不可覆寫正式檔；藍字 `added_in_rhino` 合併時必須給新的 `_03_ID編號`。字體與字高跟正式字典相同；有變動的狀態文字會換色（缺漏紅、新增藍、修改橙）。不彙總 Object UserText、不自動覆寫正式 Dictionary。Rhino 多出來的 layer 以 `added_in_rhino` 列在底部。

**安全停點**：Layer 建好即可存檔，不必繼續跑完整鏈。

## 3. 建立與修改 3D 模型

使用者以 Rhino 一般工具建模。LoopFlow 不在背景自動注入資料。

`LF_Cabinet_Suite`／BOM 不屬 2.0；櫃體幾何與其他物件一樣使用一般 Type、Space、高程與 ID 規則。三個 2D Generator 是獨立工具，不阻擋主鏈。

## 4. 建立或維護高程框與空間框

選單 **3 登記高程框（封閉曲線）**，再 **4 登記空間框（封閉曲線，須在高程框內）**。選線只用曲線過濾，不鎖全檔實體；對齊 1.x。Esc 取消。

- 高程框：彈出清單點選 FFL 或 FL，選封閉曲線後按 Enter，再彈出視窗輸入數字高程（`0`、`320`）。高程寫入 `_15_樓層高程*`，不寫物件名稱。物件 `_06`＝此數字＋相對框線的高度（樓面與框都在 Z=0 時，窗台就是 50+100=150）。
- 空間框：可一次選多條，彈出視窗輸入同一個空間名稱。名稱寫入 `_01_空間名稱*`，不寫物件名稱。空間框上的 `_01*` 可之後手動改名；再跑選單 5 才會同步到框內物件（物件寫 `_01_空間名稱`，不加 `*`）。
- 空間框須與高程框高程差在 ±20 模型單位內，且整圈在高程框裡面（共邊可）。這只用來配對「這條空間線屬於哪個高程框」，不算物件高程。
- 相鄰空間可以共邊，內部不可重疊。
- 面積重疊只檢查同一 `level_id`；不同樓層允許平面投影重疊，但會警告。
- 同層房間會對到同一個高程框，因而共用同一個 `level_id`。不必手填樓層 UUID。
- 重疊時停止並列出全部衝突 Space，不用 priority 自動選擇。
- 門檻、墩座等跨兩個空間的物件：把空間框畫成只包到所屬空間。若仍同時命中兩個框，寫入模型 Metadata 會一件一件選取、zoom 到畫面中央，再彈出清單點選所屬空間（期間不能旋轉畫面）。指定過就記住，下次寫入不再問。
- 平面、boundary 或樓層變更後回到此階段，再重新資料化。

**安全停點**：Boundary 完成可直接存檔；既有物件資料不會在背景改變。

## 5. 資料化：寫入與檢核 Metadata

目前 Nexus 選單是 **5 寫入模型 Metadata → 6 檢核模型 Metadata**，到此為止共 6 項。匯出 Type Layers 為字典（`LF_Export_Type_Layers`）、發布串接資料（`LF_Publish_Exchange`）、開啟原字典／匯出字典（`LF_Open_Dictionary`／`LF_Open_Dictionary_Export`）與查看單一物件資料（`LF_Data_Viewer`）都是獨立指令，不是選單步驟。目前按鈕與巨集見 `rhino指令.md`。

### 寫入模型 Metadata

尚未登記高程框（3）與空間框（4）時，寫入會彈窗停止且不寫入。

使用者確認後才寫入：Object ID、Type reference、Space、高程、remarks 與 revision。物件 `_01` 不加 `*`。物件 `_06`／`_13`＝高程框 `_15` 加相對樓板高度。`_14` 寫尚未發布的 `0`，或已發布 Registry 的 `registry_revision`；手動改過的值會被寫回。ID 變更必須保存 `old_id → new_id` mapping。不寫寬深高、數量或座標框。

同時落在複數空間框的物件會依序 zoom 並彈出清單點選空間名稱。

### 檢核模型 Metadata

在記憶體算出再跑一次寫入會得到的 UserText，與物件現值比對，**不寫入**。相符彈出視窗說明符合；不符彈出視窗列出差異，提醒執行選單 **5 寫入模型 Metadata** 寫回正確資料，並一次選取那些物件。彈窗文字全黑。彈窗在還原 Rhino 狀態之後才出現。

**中斷**：保留已完成且可驗證的寫入與 mapping；重跑檢核顯示剩餘差異，不假裝全案完成。

### 匯出 Type Layers 為字典（獨立指令）

`LF_Export_Type_Layers` 先做開案檢查，再在字典目錄新增 `{原檔名}_Export.xlsx`，供人工核對後合併進正式 Dictionary。第 1 列紅色提示；`diff_status` 有變動時只改該格文字顏色。不得覆寫正式 Dictionary，也不可把匯出檔當正式字典開啟。`added_in_rhino` 列合併時必須編新的 `_03_ID編號`，不可與既有列重複。

### 開啟字典（獨立指令）

`LF_Open_Dictionary` 用系統預設程式開啟這份 `.3dm` 記住的正式字典；`LF_Open_Dictionary_Export` 開啟同資料夾的 `{原檔名}_Export.xlsx`。兩者只開檔，不編輯、不建檔。正式檔不存在時請用選單 2 指定；匯出檔不存在時請先跑 `LF_Export_Type_Layers`。

### 資料檢視（獨立指令）

`LF_Data_Viewer` 點選物件後只讀顯示 canonical UserText（`_01`～`_14`，高程框另含 `_15`）。可手動欄的鍵名本身帶 `*`：空間框 `_01_空間名稱*`、物件 `_02_建構狀態*`／`_08_備註*`、高程框 `_15_樓層高程*`。物件 `_01_空間名稱` 與 `_14_資料版次` 不加 `*`。缺值標為 `（缺）`；若值是從舊 `lf_*` 或無 `*` 舊鍵讀到，會標出來源。殘留的尺寸／數量欄另外列出，不當正式資料。不寫入、不改物件名稱。文件 `schema_id`／`schema_version` 未知或不完整時停止並說明，不猜測解析。Esc 或 Enter 結束。

## 6. 發布串接資料（獨立指令）

**前置**：全案檢核通過。`LF_Publish_Exchange` 先做開案檢查，組 payload 後呼叫 C03；C03 才寫檔。局部選取不得發布。

**動作**：取得 exclusive lock（PID、主機、時間）、重新讀取現況並遞增 `registry_revision`、寫 pending、驗證完整 payload，再 atomic replace 正式 Registry。成功後把該次 `registry_revision` 寫進正式範圍物件的 `_14_資料版次`。尚未發布的新物件維持 `0`。

**輸出**：新的不可人工編輯 Registry revision，只包含 canonical schema 與明確 extension。

**失敗**：保留 last-good；顯示失敗階段，不先刪正式 JSON。

## 7. 建立 Section 並註冊 View

使用 Rhino 8 內建 Clipping／Section 指令建立剖面、立面或平面。獨立指令 `LF_Anchor_Frame`（按鈕可顯示「註冊 View」）把 Section、固定 2D↔3D transform 登記為 `view_id`。不進 Nexus 選單。

**動作**（在 **2D 模型空間**，不要在 Layout）：

1. 框選該剖面的 2D 線／圖塊／填充，以及恰好一個 Text Dot（文字須能唯一對到 Clipping Plane 名稱）。
2. 輸入框線外擴距離（預設 50）。Esc 取消不寫入。
3. 系統以 Text Dot 文字唯一命中 Clipping Plane，計算並寫入固定 transform。找不到、或找到兩個以上，都停止、不猜測。
4. 新框畫在 `LoopFlow::Anchor_Frame`。若選取含既有 1.x `Role=Anchor_Frame` 框，則升級該框、不另畫一條、不刪舊 `Role`／`Target_CP`。

3D 模型（含 worksession 連結檔）須能與該 Clipping Plane 相交，否則無法寫入固定 transform。本批不要求 Layout 上已有 Detail，也不射線。Clipping Plane 之後若移動，須重新登記。

View 不依名稱或可變 bbox 重新猜測。Section linked output 可以先保留、更新與檢查，不必立即 Materialize 或 Tag。

## 8. Materialize 可編輯 Drawing

使用者需要獨立整理線稿時，將 Section 結果轉為 `drawing_id`：

- 辨識前次產出，讓使用者選擇取代、新增或略過。
- 保存來源 `view_id`、source revision 與 drawing element provenance。
- 回報 indexed／unindexed／ambiguous 覆蓋率。
- 復原原有 selection、layer lock 與 visibility。
- 使用者補線、刪線或改樣式後標記為 modified；更新不靜默覆寫。

**安全停點**：Drawing 完成即可獨立存檔與人工整理。

## 9. 建立 Sheet、圖框與 Layout ID

使用者建立 Layout、Detail、圖框與 Tag Blocks。圖號與圖名的真相是 Sheet metadata，不是頁名字串。指令 `LF_Tagger_Layout_ID` 負責建立與維持這份 metadata；其他功能（含圖目錄）只讀、不自行解析頁名。

### 頁名怎麼寫

格式：`**圖類別__圖編號__圖名`

- `**` 只加在**該系列第一頁**最前面，用來宣告起點；**寫入後起點頁會保留 `**`，請勿刪。** 圖框圖號不含 `**`。
- `__` 是分隔，固定三欄。
- 圖編號只要**尾端是數字**就放行，前面可以英數（`201`、`101.1`、`A01`）。不需要 `.01`。後面的頁只把**尾端數字 +1**。

| 你寫的起點 | 寫入後 Layout 頁名 | 圖框上的圖號 | 下一頁圖框圖號 |
|---|---|---|---|
| `**IN__201__立面圖` | `**IN__201__立面圖` | `IN 201` | `IN 202` |
| `**A__201.02__立面圖` | `**A__201.02__立面圖` | `A 201.02` | `A 201.03` |
| `**IN__101.1__一樓平面圖` | `**IN__101.1__一樓平面圖` | `IN 101.1` | `IN 101.2`（到 `101.9` 後是 `101.10`） |
| `**IN__A01__平面` | `**IN__A01__平面` | `IN A01` | `IN A02` |

尾數規則：`201` → `202`；`A09` → `A10`；單號進十位不加前導零、改兩位數，`101.1` → `101.2` → `101.9` → `101.10`。尾端不是數字（例如 `AB`）不當圖號。

同一系列後面幾頁**不要**加 `**`，頁名可只寫圖名（例如 `樓下30公分`），或維持 Rhino 預設名。寫入後會變成 `IN__202__樓下30公分`（沒有 `**`）。封面、`Preset` 等：還沒碰到任何 `**` 起點就不編號。

圖框圖號用**空格**（`IN 201`），Layout 頁名用 `__`。兩者不同，不要混。

寫入後頁名會長這樣：

```
**IN__101.01__一樓平面圖
IN__101.02__二樓平面圖
IN__101.03__三樓平面圖
**IN__201.01__立面圖1
IN__201.02__立面圖2
```

### 使用者怎麼跑 Layout ID

1. 每個系列的第一頁改成 `**圖類別__圖編號__圖名`。後面的頁只寫圖名即可。
2. 跑 `LF_Tagger_Layout_ID`。若跳出圖塊清單，只勾真正的圖框（例如 `_Frame_A3_shop_drawing`）；`tag_*` 那些註記不要勾。預設全不勾。若圖框已就緒但還沒有 `**` 起點，會停止並只顯示命名規則與 Sample，不列出未編號的頁。改頁名後再跑。
3. 核對清單會列出每頁的圖號、圖名、是否改頁名。確認才寫入；取消整批零寫入。
4. 寫入後同一輪會做三件事：Layout 頁名改成三欄（起點頁保留 `**`）、圖框寫入 `lf_drawing_no`／`lf_drawing_name`（並暫時同步舊欄 `DWG_NO`／`DWG_NAME`，讓現有圖框上的字立刻更新）、文件寫入 Sheet metadata。比例 `lf_scale` 人工，指令不碰。
5. 圖框畫面上的字目前仍讀舊欄 `DWG_NO`／`DWG_NAME`，所以 Layout ID 會把同一組圖號／圖名雙寫上去。D08 把 Block 文字欄改指 `lf_*` 之後，就只留新 key。Infuser 不負責圖框圖號。
6. 插頁、改頁序後必須再跑一次，圖號才會按尾數重排。沒重跑時圖目錄等 consumer 應回報過期，不得安靜輸出舊值。

一頁沒有圖框、或有兩個以上圖框，該頁跳過並報告，不改頁名。`TAG_ELEV_0` 寫目前頁的編號（例如 `201`）。其餘 Tag 不碰。

### 寫入後要手動改怎麼辦

不要直接改圖框 UserText（下次 Layout ID 會依規則重算圖號）。用頁名再跑一次：

- **還沒按確認：** 核對清單按取消，改 Layout 頁名，再跑。
- **只改圖名：** 把頁名第三欄改掉，例如 `**IN__201__立面圖` → `**IN__201__一樓平面`，再跑。圖號仍依系列重算。若把頁名改成沒有 `__` 的亂名，當成誤改：圖名維持舊的，頁名改回自動組成的名字（起點頁仍帶 `**`）。
- **改編號或從某頁重排：** 在那一頁最前面再加 `**`，寫成你要的 `**圖類別__圖編號__圖名`，再跑。該頁變成新起點，後面的頁跟著從這個尾數往後編，直到下一頁也有 `**`。例如第四頁起要從 `301` 開始 → 把第四頁改成 `**IN__301__新圖名` 再跑。
- **不要**刪掉起點頁的 `**`，否則該頁不再當系列起點。不要指望只改中間一頁、後面完全不動；連續編號就是這樣算的。

### Duplicate Sheet

複製後建立新的 `sheet_id`、`drawing_id` 與 `tag_id`；圖目錄定位點的 `lf_catalog_id` 也必須換新號：

- 除 `TAG_DW` 外，所有 Tag 清除來源綁定、自動欄位與人工補充說明，並恢復 template 預設 lock。
- `TAG_DW` 的人工編號、寬、高與其他內容完整保留。
- 使用者重新綁定新頁 Tag。
- 不覆蓋系統剪貼簿。

### 圖目錄（獨立指令，排在 Layout ID 實機驗收之後）

`LF_Catalog` 只消費 Sheet metadata，不建立第二套圖號。使用者選獨立的圖號／圖名定位點與要列入的 Sheet，由定位點綁 `sheet_id`、文字可重建。規劃見 `LF_Catalog規劃.md`；正式契約等實作時寫入 `資料契約.md`。

## 10. 建立與綁定 Tag

| 模式 | 使用者動作 | 結果 |
|---|---|---|
| Grab | 在 Layout 選 Tag，點進 Detail，再選來源 | Height／Finish 寫 `lf_source_object_id`；家具 Item 寫 `lf_source_block_name` |
| Laser | 在 Layout 選 Height／Finish Laser Tag，再在 Detail 內點位置 | 用固定 View transform 射線寫 `lf_source_object_id`；多候選由使用者選，清單只顯示圖層名 |
| Index | 在 Layout 選 `TAG_SECTION_DETAIL` 或 `TAG_ELEV_1`～`4`，再從清單選全檔任一 Layout 的 Detail（可搜尋，點選時 zoom） | 唯一對到已登記 View 才寫 `lf_target_view_id`；圖號之後由 Infuser 從目標頁算出 |
| Furniture Item | 經 Grab 選共用家具 Block | 解析 `FF-01__Chair-1`；格式錯誤停止並警告 |
| `TAG_ELEV_0` | 使用者直接填方向／編號 | 不建立模型 binding |
| `TAG_DW` | 使用者直接填編號／寬／高 | 純手動，不建立 binding |

同款家具可共用 Block 名稱；家具 Tag 綁定名稱類型，不具 object-level orphan 偵測。Locked Tag 不允許重新綁定，必須先由使用者解除 lock。

## 11. 同步顯示資料

使用者可選同步當前頁或全部頁。Sync 從指定 Registry revision 與 Sheet metadata 計算 render output：

- 不覆寫 locked Tag。
- 不覆寫 `TAG_DW`、比例、Detail 編號及其他人工欄位。
- 缺來源、過期、歧義與未知 template 回報明確狀態，不以顏色作唯一真相。
- Part 完成就是合法停點，不要求每次全案同步。

## 12. Health 與 Repair

Health 唯讀檢查 identity、binding、revision、template 與覆蓋範圍，包含 locked Tag；`TAG_DW` 無來源屬正常，不判 unbound。

Repair 是獨立動作：先顯示影響與預覽，使用者確認後才執行。不得偷偷重綁、換 ID、刪 Drawing 或覆寫人工內容。提示顏色必須可還原原始顏色。

## 變更循環

### 只改資料

重新 Scan／Apply／Verify → Publish 新 Registry revision → Sync → Health。若只是人工備註且屬 instance override，不得被 Dictionary 重匯覆寫。

### 修改模型幾何

重新資料化與發布 → 更新 Section → 使用者選擇保留、新增或取代 Drawing → 必要時重新綁定 → Sync → Health。

### 修改 Space／樓層

回到 Space Boundary → 全案 Scan／Apply／Verify → Publish → Sync → Health。

### Detail／Layout 重整

重新註冊 View 或執行 Duplicate Sheet 規則 → 重新綁定 → Sync → Health。不得沿用無法證明有效的舊 target ID。

## 實機驗收重點

- 正常、取消、失敗、中斷與重跑。
- hidden／locked 物件仍納入正式 Scan。
- ID mapping 與 rollback。
- Drawing 人工修改保護。
- Duplicate Sheet 清除／保留規則；圖目錄定位點換新 `catalog_id`。
- `TAG_DW` 永不被 Sync 覆寫。
- Layout ID：核對清單取消零寫入；插頁後未重跑時 consumer 回報過期；未勾選的 Block 不登錄、不寫入。
- 家具共用名稱與格式錯誤警告。
- 非 cm 警告。
- Registry last-good 與雙程序競態。
