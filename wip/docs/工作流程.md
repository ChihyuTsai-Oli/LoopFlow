# LoopFlow 2.0 — 工作流程

本文件是實作與驗收使用者操作順序、介入點、安全停點與重跑行為的唯一來源。資料語意以 `資料契約.md` 為準；工程相依以 `開發任務與路徑.md` 為準。

## 工作原則

- 每一階段可以單獨執行、驗證、存檔與換機。
- 使用者決定何時寫入、何時發布、綁誰、更新當頁或全案。
- 系統先報告影響，再執行有副作用的動作。
- 取消、失敗或中斷不得破壞上一份有效資料或 Rhino 工作狀態。
- 1.x 按鈕順序不是限制；保留的是已驗證可行的工作邏輯與控制點。

## 一條完整工作鏈

```text
開案檢查
→ 從字典同步 Type Layers
→ 建立 3D 模型
→ 登記高程框與空間框
→ 寫入模型 Metadata
→ 檢核模型 Metadata
→ 選用：匯出 Type Layers 為字典（獨立指令）
→ 發布串接資料（獨立指令）
→ 建立 Section／註冊 View
→ Materialize 可編輯 Drawing
→ 建立 Sheet／圖框／Layout ID
→ 建立並綁定 Tag
→ 選用：建立圖目錄（獨立指令 `LF_Catalog`，須先有 Sheet metadata）
→ Infuser 注入 Tag 顯示資料
→ TAG-O 確認活著或斷連
```

目前主鏈（開案到 TAG-O）已接通並實機通過。Extract CP 已有自動測試，**待 Rhino 實機**。剩餘：**Duplicate Layout → Sync Worksession → Document。** TAG-O 只檢查與上色，不實作 Repair。

## 1. 開案檢查

**動作**：解析 `LOOPFLOW_WORKFILES_ROOT`、Dictionary、`exchange/`、project identity、schema version 與 Rhino 文件單位。

**使用者介入**：只有設定缺失、專案辨識不明或非 cm 警告時處理。

**結果**：顯示實際生效的路徑、版本與單位。非 cm 不阻擋，但明確警告風險並建議切換為 cm。

**失敗**：停止，不猜磁碟機、不建立檔案、不修改 Rhino 文件。Dictionary 驗證失敗會彈窗列出第幾列、什麼原因（例如 type_id 重複）。找不到 Dictionary 檔時不擋選單，警告並請用選單 2 指定。

## 2. 從字典同步 Type Layers

**Validate**：檢查 15 欄、schema、Type ID、類別與 layer mapping、單位、measurement rule、量綱與必填值。

**Sync**：

- 每一次同步都彈出視窗問專案名稱（圖層前綴）。第一次不預填 `M3D`；檔案已記住名稱時把文字預填在框裡，按 OK 即可，也可改名。名稱寫入文件 `lf_layer_prefix`，不是專案 UUID。未寫入前綴時圖層樹仍用 `M3D`。
- 同步 Type Layers 時才選 Dictionary `.xlsx`。第一次選檔並把檔名記住在 `lf_dictionary_filename`；之後沿用記住的檔。只有該檔找不到（例如改名）才再跳出選檔。預設建議 `LoopFlow_Dictionary.xlsx`。開案檢查不選檔；找不到檔時仍可進選單並警告。不掃全部 Excel，也不從 `.3dm` 旁猜。
- Dictionary 有、Rhino 沒有的 layer：建立並帶入初始 layer defaults。
- 已存在的同名 Rhino layer：保留既有 UserText／construction；顯示色依圖層代號前綴重套。新建材質顏色跟圖層；已存在的同名材質只掛接、不改色。材質名稱不含專案前綴，不改物件 instance 顏色。
- 不覆寫 object instance 的 `_02` 狀態，也不把 object data 回寫 Dictionary。
- 不執行 ZoomExtents，不改變使用者視圖。
- `DNA_REF_` 參考點放在 `(0,0,0)`，依穩定 Type ID 更新或取代，避免空 Type layer 被 Purge 且不重複累積。
- `20_DW` 維持單一 Type，排除 child layers。

**選用反向匯出**：獨立指令 `LF_Export_Type_Layers`（匯出 Type Layers 為字典）在 Dictionary 同一目錄新增 `{原檔名}_Export.xlsx`（例如正式檔 `LoopFlow_Dictionary.xlsx` 就匯出 `LoopFlow_Dictionary_Export.xlsx`；完整 15 欄加上 `diff_status`）。最上方一列紅色提示說明：此檔不能當正式字典、不可覆寫正式檔；藍字 `added_in_rhino` 合併時必須給新的 `_03_ID編號`。字體與字高跟正式字典相同；有變動的狀態文字會換色（缺漏紅、新增藍、修改橙）。不彙總 Object UserText、不自動覆寫正式 Dictionary。Rhino 多出來的 layer 以 `added_in_rhino` 列在底部。

**安全停點**：Layer 建好即可存檔，不必繼續跑完整鏈。

## 3. 建立與修改 3D 模型

使用者以 Rhino 一般工具建模。LoopFlow 不在背景自動注入資料。

`LF_Cabinet_Suite`／BOM 不屬 2.0；櫃體幾何與其他物件一樣使用一般 Type、Space、高程與 ID 規則。三個 2D Generator 是獨立工具，不阻擋主鏈。

## 4. 建立或維護高程框與空間框

選單 **3 登記高程框（封閉曲線）**，再 **4 登記空間框（封閉曲線，須在高程框內）**。選線只用曲線過濾，不鎖全檔實體；對齊 1.x。Esc 取消。

- 高程框：彈出清單點選 FFL 或 FL，選封閉曲線後按 Enter，再彈出視窗輸入數字高程（`0`、`320`）。高程寫入 `_15_樓層高程*`，不寫物件名稱。物件 `_06`＝此數字＋相對框線的高度（樓面與框都在 Z=0 時，窗台就是 50+100=150）。
- 空間框：可一次選多條，彈出視窗輸入同一個空間名稱。名稱寫入 `_01_空間名稱*`，不寫物件名稱。空間框上的 `_01*` 可之後手動改名；再跑選單 5 才會同步到框內物件（物件寫 `_01_空間名稱`，不加 `*`）。
- 空間框須與高程框高程差在 ±20 模型單位內，且整圈在高程框裡面（共邊可）。這只用來配對「這條空間線屬於哪個高程框」，不算物件高程。
- 相鄰空間可以共邊，內部不可重疊。
- 面積重疊只檢查同一 `level_id`；不同樓層允許平面投影重疊，但會警告。
- 同層房間會對到同一個高程框，因而共用同一個 `level_id`。不必手填樓層 UUID。
- 重疊時停止並列出全部衝突 Space，不用 priority 自動選擇。
- 門檻、墩座等跨兩個空間的物件：把空間框畫成只包到所屬空間。若仍同時命中兩個框，寫入模型 Metadata 會一件一件選取、zoom 到畫面中央，再彈出清單點選所屬空間（期間不能旋轉畫面）。指定過就記住，下次寫入不再問。
- 平面、boundary 或樓層變更後回到此階段，再重新資料化。

**安全停點**：Boundary 完成可直接存檔；既有物件資料不會在背景改變。

## 5. 資料化：寫入與檢核 Metadata

目前 Nexus 選單是 **5 寫入模型 Metadata → 6 檢核模型 Metadata**，到此為止共 6 項。匯出 Type Layers 為字典（`LF_Export_Type_Layers`）、發布串接資料（`LF_Publish_Exchange`）、開啟原字典／匯出字典（`LF_Open_Dictionary`／`LF_Open_Dictionary_Export`）與查看單一物件資料（`LF_Data_Viewer`）都是獨立指令，不是選單步驟。目前按鈕與巨集見 `rhino指令.md`。

### 寫入模型 Metadata

尚未登記高程框（3）與空間框（4）時，寫入會彈窗停止且不寫入。

使用者確認後才寫入：Object ID、Type reference、Space、高程、remarks 與 revision。物件 `_01` 不加 `*`。物件 `_06`／`_13`＝高程框 `_15` 加相對樓板高度。`_14` 寫尚未發布的 `0`，或已發布 Registry 的 `registry_revision`；手動改過的值會被寫回。ID 變更必須保存 `old_id → new_id` mapping。不寫寬深高、數量或座標框。

同時落在複數空間框的物件會依序 zoom 並彈出清單點選空間名稱。

### 檢核模型 Metadata

在記憶體算出再跑一次寫入會得到的 UserText，與物件現值比對，**不寫入**。相符彈出視窗說明符合；不符彈出視窗列出差異，提醒「請執行 Nexus 5 寫入模型 Metadata，把正確資料寫回。」，並一次選取那些物件。彈窗文字全黑。彈窗在還原 Rhino 狀態之後才出現。

**中斷**：保留已完成且可驗證的寫入與 mapping；重跑檢核顯示剩餘差異，不假裝全案完成。

### 匯出 Type Layers 為字典（獨立指令）

`LF_Export_Type_Layers` 先做開案檢查，再在字典目錄新增 `{原檔名}_Export.xlsx`，供人工核對後合併進正式 Dictionary。第 1 列紅色提示；`diff_status` 有變動時只改該格文字顏色。不得覆寫正式 Dictionary，也不可把匯出檔當正式字典開啟。`added_in_rhino` 列合併時必須編新的 `_03_ID編號`，不可與既有列重複。

### 開啟字典（獨立指令）

`LF_Open_Dictionary` 用系統預設程式開啟這份 `.3dm` 記住的正式字典；`LF_Open_Dictionary_Export` 開啟同資料夾的 `{原檔名}_Export.xlsx`。兩者只開檔，不編輯、不建檔。正式檔不存在時請用選單 2 指定；匯出檔不存在時請先跑 `LF_Export_Type_Layers`。

### 資料檢視（獨立指令）

`LF_Data_Viewer` 點選物件後只讀顯示 canonical UserText（`_01`～`_14`，高程框另含 `_15`）。可手動欄的鍵名本身帶 `*`：空間框 `_01_空間名稱*`、物件 `_02_建構狀態*`／`_08_備註*`、高程框 `_15_樓層高程*`。物件 `_01_空間名稱` 與 `_14_資料版次` 不加 `*`。缺值標為 `（缺）`；若值是從舊 `lf_*` 或無 `*` 舊鍵讀到，會標出來源。殘留的尺寸／數量欄另外列出，不當正式資料。不寫入、不改物件名稱。文件 `schema_id`／`schema_version` 未知或不完整時停止並說明，不猜測解析。Esc 或 Enter 結束。

## 6. 發布串接資料（獨立指令）

**前置**：全案檢核通過。`LF_Publish_Exchange` 先做開案檢查，組 payload 後呼叫 C03；C03 才寫檔。局部選取不得發布。

**動作**：取得 exclusive lock（PID、主機、時間）、重新讀取現況並遞增 `registry_revision`、寫 pending、驗證完整 payload，再 atomic replace 正式 Registry。成功後把該次 `registry_revision` 寫進正式範圍物件的 `_14_資料版次`。尚未發布的新物件維持 `0`。

**輸出**：新的不可人工編輯 Registry revision，只包含 canonical schema 與明確 extension。

**失敗**：彈窗與選單 6 檢核同一份不符清單，並一次選取那些物件。保留 last-good；顯示失敗階段，不先刪正式 JSON。若提示正式檔被佔用，等雲端同步結束後再發。

## 7. 建立 Section 並註冊 View

使用 Rhino 8 內建 Clipping／Section 指令建立剖面、立面或平面。獨立指令 `LF_Anchor_Frame`（按鈕可顯示「註冊 View」）把 Section、固定 2D↔3D transform 登記為 `view_id`。不進 Nexus 選單。

**動作**（在 **2D 模型空間**，不要在 Layout）：

1. 框選該剖面的 2D 線／圖塊／填充，以及恰好一個 Text Dot（文字須能唯一對到 Clipping Plane 名稱）。
2. 輸入框線外擴距離（預設 50）。Esc 取消不寫入。
3. 系統以 Text Dot 文字對 Clipping Plane：**完整名稱相同**（不分大小寫）才算。沒有完全相同時，才允許恰好一個較長名稱包含該文字（例如 `A-A` 對 `A-A Section`）。`LF_立面` 不會對到 `LF_立面2`。找不到、或找到兩個以上，都停止、不猜測。
4. 新框畫在 `LoopFlow::Anchor_Frame`。若選取含既有 1.x `Role=Anchor_Frame` 框，則升級該框、不另畫一條、不刪舊 `Role`／`Target_CP`。

3D 模型（含 worksession 連結檔）須能與該 Clipping Plane 相交，否則無法寫入固定 transform。本批不要求 Layout 上已有 Detail，也不射線。Clipping Plane 之後若移動，須重新執行 Anchor Frame。

一個剖面只有一個 Anchor Frame。框與當下要 Laser 的那張圖（圖 A 或圖 B）一起平移時，不必重跑 Anchor Frame；Laser 用框的現況中心當 2D 原點，鏡射係數與 CP 三軸仍用登記時寫入的值。天花反射平面須先把 Section 圖左右鏡射，再跑 Anchor Frame（名稱含 `天花`／`CEILING`／`RCP` 時 `scale_x = -1`）。登記後不要再額外鏡射或旋轉。

View 身分不依名稱或可變線稿 bbox 重新猜測。Section linked output（圖 A）可以先保留、更新與檢查，不必立即 Extract 或 Tag。

## 8. Materialize 可編輯 Drawing

使用者需要獨立整理線稿時，在 **2D 模型空間**跑 `LF_Extract_CP`。Section 產出是圖 A（linked、不編）；Extract 產出是圖 B（可編輯）。需要時把圖 B 與同一個 Anchor Frame 一起平移，讓圖 B 落在框內再 Laser。

- 勾選 Clipping Drawing 的剖面根圖層（底下有 Visible／Hatch／Curve 子層）。
- 產出放在根圖層 `LoopFlow_Extract`（與 `LoopFlow` 平級，不是 `LoopFlow::Extract`）。列印寬度 Default（可列印）。列印色：根層與 `Curve_#RRGGBB` 為黑；只有 `Visible`、`Hatch` 為灰 `#BEBEBE`。
- 子層：`Visible`、`Hatch`、`Curve_#RRGGBB`（依線的顏色；對齊 1.x 拆層習慣）。
- 複製後清掉從圖 A／3D 抄來的 `_01`～`_14`，只留 Drawing 的 `lf_*` 身分欄。Laser 仍射向 3D 模型，不讀圖 B 上的 UUID。
- 對到已登記 View 時寫來源 `view_id`（圖層前綴與框名須**完整相同**，`LF_立面` 不會對到 `LF_立面2`）；寫 source revision 與每個 element 的 `source_object_ids[]`。
- 同一 View／同一剖面若已有抽出，選取代、新增或略過。
- 回報 indexed／unindexed／ambiguous 覆蓋率；索引不完整仍產出。
- 復原原有 selection 與來源圖層 lock／visibility。
- 使用者補線、刪線或改樣式後應把 `lf_provenance_state` 標為 `modified`；取代不會覆蓋已修改的 Drawing。

Esc／取消、在 Layout 頁執行、找不到剖面圖層、一個剖面對到兩個 View，都不寫入。來源剖面本身不移動。

**安全停點**：Drawing 完成即可獨立存檔與人工整理。**未在 Rhino 8 實機驗證。**

## 9. 建立 Sheet、圖框與 Layout ID

使用者建立 Layout、Detail、圖框與 Tag Blocks。圖號與圖名的真相是 **Sheet metadata**，不是頁名字串。指令 `LF_Tagger_Layout_ID` 負責建立與維持這份 metadata；其他功能（含圖目錄）只讀、不自行解析頁名。

本節是 Layout ID 的操作說明與命名邏輯總覽，日後 GitHub 公開說明可直接沿用；機器可檢查的契約細節以 `資料契約.md` 的 Sheet 章節為準。

### 三欄命名格式

起點與手動頁都用同一套三欄：

```text
**圖類別__圖號__圖名
```

或手動頁：

```text
//圖類別__圖號__圖名
```

規則：

| 符號 | 意思 |
|---|---|
| `**` | 系列自動編號的**起點**。只加在該系列第一頁最前面。寫入後**會保留**，請勿刪。 |
| `//` | **手動頁**。不參與自動編號、不佔號，但仍須完整三欄。寫入後**會保留**。 |
| `__` | 三欄分隔（圖類別／圖號／圖名）。固定兩條底線。 |
| 圖框上的圖號 | 用**空格**：`IN 101.01`。頁名用 `__`，兩者不要混。 |
| `**`／`//` | 只出現在 Layout **頁名**；圖框圖號與圖名**不含**這兩個前綴。 |

圖號只要**尾端是數字**就放行，前面可英數：`201`、`101.01`、`101.1`、`A01` 都可以。不強制 `.01`。

### 自動編號怎麼算

1. 從頁序由上往下掃。
2. 碰到 `**圖類別__圖號__圖名` → 該系列從此圖號起算，寫入圖框，頁名保留 `**`。
3. 之後每一頁（直到下一個 `**`）繼承同一圖類別，把**尾端數字 +1**，頁名改成三欄（沒有 `**`）。
4. 碰到 `//…` → 照頁名三欄寫入圖框，**尾數不加**，系列接著往下。
5. 還沒碰到任何 `**` 之前的頁（封面、`Preset` 等）不編號。
6. 檔案裡一個 `**` 都沒有（也沒有可寫的 `//`）→ 停止、零寫入，彈出命名說明。

尾數例子：

| 目前 | 下一頁 |
|---|---|
| `201` | `202` |
| `201.02` | `201.03` |
| `201.09` | `201.10` |
| `101.1` | `101.2` |
| `101.9` | `101.10`（單號進十位改兩位數，不加前導零） |
| `A09` | `A10` |
| `A9` | `A10` |

尾端不是數字（例如 `AB`）不當圖號。

### 寫入前／寫入後對照（Sample）

你在 Layout 列表可以這樣排：

```text
**IN__101.01__一樓平面圖
二樓平面圖
三樓平面圖
**IN__201.01__立面圖1
立面圖2
//S__901__結構平面圖
```

跑完 Layout ID 後：

```text
**IN__101.01__一樓平面圖
IN__101.02__二樓平面圖
IN__101.03__三樓平面圖
**IN__201.01__立面圖1
IN__201.02__立面圖2
//S__901__結構平面圖
```

對應圖框圖號／圖名：`IN 101.01`／一樓平面圖 → `IN 101.02`／二樓平面圖 → …；手動頁 `S 901`／結構平面圖。

其他起點例子：

| 你寫的起點 | 寫入後頁名 | 圖框圖號 | 下一頁圖號 |
|---|---|---|---|
| `**IN__201__立面圖` | `**IN__201__立面圖` | `IN 201` | `IN 202` |
| `**A__201.02__立面圖` | `**A__201.02__立面圖` | `A 201.02` | `A 201.03` |
| `**IN__101.1__一樓平面圖` | `**IN__101.1__一樓平面圖` | `IN 101.1` | `IN 101.2` |
| `**IN__A01__平面` | `**IN__A01__平面` | `IN A01` | `IN A02` |
| `//S__901__結構平面圖` | `//S__901__結構平面圖` | `S 901` | （不佔號） |

### 使用者怎麼跑 Layout ID

1. 每個系列的第一頁改成 `**圖類別__圖號__圖名`。同一系列後面的頁只寫圖名即可（或維持 Rhino 預設名）。不參與系列的頁用 `//圖類別__圖號__圖名`。
2. 跑 `LF_Tagger_Layout_ID`。若跳出圖塊清單，**只勾真正的圖框**（例如 `_Frame_A3_shop_drawing`）；`tag_*` 註記不要勾。預設全不勾。
3. 若圖框已就緒但還沒有 `**` 起點（也沒有可寫入的 `//`），會停止並**只顯示**命名規則與 Sample，彈窗不列未編號頁。改頁名後再跑。
4. 核對清單會列出每頁的圖號、圖名、是否改頁名、是否系列起點／手動頁。確認才寫入；取消整批零寫入。
5. 寫入後同一輪會做三件事：
   - Layout 頁名整理成三欄（起點保留 `**`，手動頁保留 `//`）
   - 圖框寫入 `lf_drawing_no`／`lf_drawing_name`
   - 文件寫入 Sheet metadata  
   比例 `lf_scale` 由人工維護，指令不碰。
6. 圖框畫面上的字讀 `lf_drawing_no`／`lf_drawing_name`／`lf_scale`。Layout ID 不再寫舊欄 `DWG_NO`／`DWG_NAME`。Infuser 不負責圖框圖號。
7. 插頁、改頁序後必須再跑一次，圖號才會按尾數重排。沒重跑時圖目錄等 consumer 應回報過期，不得安靜輸出舊值。

一頁沒有圖框、或有兩個以上圖框，該頁跳過並報告，不改頁名。`//` 格式不對（不是合法三欄）也跳過該頁，不擋其他頁。`TAG_ELEV_0` 寫目前頁的編號（例如 `201`）。其餘 Tag 不碰。

### 五條要記住的規則（與警告視窗相同）

1. `**` 作為自動編號起點，勿刪。
2. `**` 之間的頁面為同一系列。
3. `**` 頁面之外的 Layout 名稱，只需要填寫圖名。
4. `//` 頁面不參與自動編號，但仍需使用相同命名格式規範。
5. 圖號、圖名的編號與命名可以從 Layout 列表手動調整；經由自動編號寫入圖框中，**不可直接修改圖框內容**。

### 寫入後要手動改怎麼辦

不要直接改圖框 UserText（下次 Layout ID 會依規則重算）。用 Layout 頁名再跑一次：

- **還沒按確認：** 核對清單按取消，改頁名，再跑。
- **只改圖名：** 改第三欄，例如 `**IN__201__立面圖` → `**IN__201__一樓平面`，再跑。圖號仍依系列重算。若把頁名改成沒有 `__` 的亂名，且前面已有 `**`：當成誤改，圖名維持舊的，頁名改回自動組成的名字（起點頁仍帶 `**`）。
- **改編號或從某頁重排：** 在那一頁最前面再加 `**`，寫成你要的 `**圖類別__圖號__圖名`，再跑。該頁變成新起點，後面跟著從這個尾數往後編，直到下一頁也有 `**`。例如第四頁起要從 `301` 開始 → 把第四頁改成 `**IN__301__新圖名` 再跑。
- **手動固定某一頁圖號：** 用 `//圖類別__圖號__圖名`，不佔系列。
- **不要**刪掉所有起點頁的 `**`；檔案裡一個 `**` 都沒有時會停止、不改圖框。不要指望只改中間一頁、後面完全不動；連續編號就是這樣算的。

### Duplicate Sheet

2.0 **尚未實作** Duplicate Layout；本節只鎖定複製後的 ID 與清除／保留規則。**Extract CP 之後再開，現在不要實作程式。**

複製後建立新的 `sheet_id`、`drawing_id` 與 `tag_id`；圖目錄定位點的 `lf_catalog_id` 也必須換新號：

- 除 `TAG_DW` 外，所有 Tag 清除來源綁定、自動欄位與人工補充說明，並恢復 template 預設 lock。
- `TAG_DW` 的人工編號、寬、高與其他內容完整保留。
- 使用者重新綁定新頁 Tag。
- 不覆蓋系統剪貼簿。

### 圖目錄（獨立指令，須先有 Sheet metadata）

`LF_Catalog` 只消費 Sheet metadata，不建立第二套圖號。使用者選獨立的圖號／圖名定位點與要列入的 Sheet；定位點綁 `sheet_id`，新建文字以定位點為左下角原點，Refresh 更新內容並保留字型、大小、圖層與已移動的位置。可清除定位點資料並還原選取前的圖層。`LoopFlow` 與其子圖層不列印（列印寬度 `No Print`）。操作見 `rhino指令.md`；契約見 `資料契約.md` 的 Catalog Anchor。

## 11. 同步顯示資料（Infuser）

使用者可選同步當前頁（Part）或全部頁（All）。**目前可跑 `LF_Infuser_Part`（當前 Layout 頁）與 `LF_Infuser_All`（全檔 Layout 頁）。** 公司已測注入；家中已測與 TAG-O 來回。Infuser 從指定 Registry revision 與 Sheet metadata 把資料**注入** Tag Block 顯示欄：

- Height／Finish 先對 Registry `objects[]` 的 `object_id`（不分大小寫、可去 `{}`）；對不到再讀文件裡帶同一 `_07_UUID` 的物件 UserText（含連結檔；同 UUID 多筆時取資料最齊的）。`type_display_name` 仍優先從 Registry `types[]` 補。
- Index 先用綁定時記下的 `lf_target_layout` 對目標頁；沒有這欄才從目標 View 反查 Layout 頁。同一 View 也打到 Tag 所在頁時，改用其他頁；其他頁拆不出圖號再改回本頁。頁上沒有可用圖框時改從頁名拆圖類別／圖號（含 `DC__201.a2`）。`lf_detail_no` 是手填編號，Infuser 不寫。Layout ID 改頁名時會同步更新 `lf_target_layout`。若記下的目標頁已刪，或該頁還在但已沒有對到 `lf_target_view_id` 的 Detail：寫 `?`、塗紅，摘要標「目標消失」，不可改對到別頁。
- 家具若 Grab 時有記下實例，Infuser 讀該實例**現況** Block 名稱再拆三段；改名會更新畫面，實例刪除則寫 `?`、塗紅。沒有實例 id 的舊 Tag 仍用記下的名稱。不需 Registry。
- 未綁定寫 `-`，不塗警示色。已標斷連（`lf_health_state=broken`）不灌回；再 Grab／Laser／Index 會清掉此欄，接著再跑 Infuser 可恢復。不必刪 Tag。
- 不覆寫 locked Tag。
- 不覆寫 `TAG_DW`、比例、Detail 編號及其他人工欄位。
- 只處理 D08 Tag 圖塊；其他圖塊略過、不警告。
- 缺來源、過期、歧義回報明確狀態，不以顏色作唯一真相。
- Part 完成就是合法停點，不要求每次全案同步。All 一次處理所有 Layout 頁，規則與 Part 相同；模型空間也可跑。失敗／缺 schema／Registry 檔損壞則整批不寫。
- 第一輪 Infuser 不必等 TAG-O；TAG-O 標成斷連後，下一輪 Infuser 不灌回。再綁定後跑 Infuser 可恢復。

## 變更循環

### 只改資料

重新 Scan／Apply／Verify → Publish 新 Registry revision → Sync → Health。若只是人工備註且屬 instance override，不得被 Dictionary 重匯覆寫。

### 修改模型幾何

重新資料化與發布 → 更新 Section → 使用者選擇保留、新增或取代 Drawing → 必要時重新綁定 → Sync → Health。

### 修改 Space／樓層

回到 Space Boundary → 全案 Scan／Apply／Verify → Publish → Sync → Health。

### Detail／Layout 重整

重新註冊 View 或執行 Duplicate Sheet 規則 → 重新綁定 → Sync → Health。不得沿用無法證明有效的舊 target ID。
