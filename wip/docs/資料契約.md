# LoopFlow 2.0 — 資料契約

本文件是 2.0 Dictionary、模型資料、Registry、View、Drawing、Sheet、Tag 與 Health 契約的唯一來源。前期決策已封存在 `前期規劃/資料生態決策表.md`；實作不得再從前期討論文字推測答案。

## 契約狀態

- ECO-01～11、ED-01～18、ND-01～28 已裁決。
- 本文件固定資料語意、所有權、值域、序列化名稱與驗證規則。
- LF-A03 已鎖定 machine key、身分格式、layer path、指令、檔名與非 Block local frame。
- LF-A04 已鎖定 Registry 物件欄、10 份 Block template manifest、24 個 legacy key 的 owner 與 migration mapping。
- LF-A06 已鎖定可機器驗證的 fixtures；檢查器為 `wip/tools/check_contract_fixtures.py`。第一條規則是計量規則與單位量綱一致。
- 正式專案資料仍不得寫入，直到對應功能通過驗收。
- Machine key 固定使用英文；中文／英文只作顯示標籤。

## 共通規則

| 項目 | 規則 |
|---|---|
| 缺值 | 內部使用 typed null；只有 Tag／報表顯示 `-` |

| 未知版本 | 停止並說明，不猜測解析 |

## 序列化慣例

- JSON、in-memory schema 與文件層欄位使用英文 `snake_case`，對齊本文件的概念名。
- Rhino 物件／文件 UserText 另加前綴 `lf_`，避免撞上 1.x 的 `_12_UUID` 或其他外掛。
- 同一語意在 JSON 與 UserText 使用同一英文詞幹：JSON 為 `object_id`，UserText 為 `lf_object_id`。
- `schema_version` 為正整數，從 `1` 起跳，獨立於產品版號 `v2.0.0`。
- 每個持久化 payload 還必須有 `schema_id`，用來分辨種類；未知 `schema_id` 視同未知版本。

| schema_id | 用途 | 目前 schema_version |
|---|---|---|
| `loopflow.project` | Rhino 文件上的專案身分 | `1` |
| `loopflow.dictionary` | Type Catalog 載入後的正規化資料 | `1` |
| `loopflow.object` | 3D 物件 instance 現值 | `1` |
| `loopflow.space` | Space Boundary | `1` |
| `loopflow.local_frame` | 尺寸用的持久化座標框 | `1` |
| `loopflow.view` | Section／View 註冊 | `1` |
| `loopflow.drawing` | 可編輯 Drawing 與 provenance | `1` |

| `loopflow.tag_template` | 單一 Tag／圖框 manifest | `1` |
| `loopflow.tag_template_set` | 10 份 manifest 的集合檔 | `1` |

### 身分格式

| 欄位 | 格式 | 規則 |
|---|---|---|
| `project_id`、`object_id`、`space_id`、`level_id`、`view_id`、`drawing_id`、`drawing_element_id`、`sheet_id`、`tag_id` | UUID v4，canonical 小寫 `8-4-4-4-12` | 專案範圍唯一；複製產生新 ID；1.x 大寫 UUID 由 migration 正規化 |
| `type_id` | `{type_category}-{type_sequence}` | 不是 UUID。載入時用 Dictionary 的 12 個類別碼當前綴拆分，禁止只切第一個 `-` |
| `type_category` | 12 個類別碼之一 | 清單由現行 Dictionary 凍結，A06 fixtures 固化 |
| `type_sequence` | 非空字串 | 不含用來組 `type_id` 的那一個連接 `-` |
| `registry_revision` | 每個 `project_id` 從 `1` 起的正整數 | 發布成功才遞增 |
| `EXT` | 保留字 | 未命中 Space 時的唯一 `space_id`；不是 UUID |

### Layer path

- 使用完整 path，分隔符為 `::`；terminal name 不得單獨當身分。
- 大小寫與空白以 Dictionary 的 `__Rhino Layer` 為準，程式不得自行折疊或補空白。
- 3D 正式範圍前綴 `M3D`；2D 前綴 `M2D`。更改前綴不會自動改名既有 layer。
- 系統資料層為契約，不是可隨意改的顯示偏好：

```text
M3D::_Data::Space_Boundaries
M3D::_Data::Level_Boundaries_FFL
M3D::_Data::Level_Boundaries_FL
M3D::20_DW
M2D::Anchor_Frame
```

- `DNA_REF_` 參考線依 `type_id` 更新或取代，名稱不得只依 layer 字串累加。
- Type layer 顯示色與材質依圖層代號前綴（1.x 顯示慣例），不是 Dictionary 欄位；不寫入物件 instance 顏色。
- `2D_D1`、`3D_W1` 只供獨立 2D 工具解析，主鏈不當身分。家具 `FF-01__Chair-1` 見 ED-14。

### Dictionary → Rhino 合併

- Dictionary 有、Rhino 尚無的 layer：建立 layer，帶入 Type mapping 與 `_02` 初始資料。
- Dictionary 與 Rhino 已有同名 layer：保留 Rhino layer 既有資料。
- `_02` instance 現值只由物件維護；同 layer 物件可以不同。
- 重新匯入 Dictionary 不覆寫物件人工修改，也不把物件現值回寫 Dictionary。
- `DNA_REF_` 保留以避免空 Type layer 被 Purge；依穩定 `type_id` 更新或取代，不得累積。
- `20_DW` 維持單一 Type 與 child-layer 排除規則。

## 模型單位、尺寸與數量

### 文件單位

- 啟動時必須偵測並顯示 `ModelUnitSystem`。
- 非 cm 不阻擋，但要明確警告後續風險並建議切換為 cm。
- 實作不得假裝非 cm 已安全支援；每項量綱計算都必須有單位測試。

### 尺寸 frame

軸向固定，不比較邊長大小：寬＝local X，深＝local Y，高＝local 垂直軸。

#### 推導

1. Block instance：使用插入平面；`derivation_method` 為 `block_insertion`。
2. 非 Block 且為 Extrusion：使用底面平面；`derivation_method` 為 `extrusion_base`。
3. 非 Block 且幾何只有一個支撐平面（平面曲線或單一平面）：使用該平面；`derivation_method` 為 `unique_plane`。
4. 其餘（封閉 Box、多面 Brep、Mesh、方向不唯一）**不得**用 World bbox、最長邊或面積最大面去猜；Scan 列為阻擋項「無法建立穩定 local frame」，不寫 `dimension_*` 與 `quantity`。

#### 持久化

成功推導後寫入物件 UserText `lf_local_frame`，JSON 物件、`schema_id` 為 `loopflow.local_frame`：

```text
schema_id            loopflow.local_frame
schema_version       1
origin               [x, y, z]     模型單位
x_axis               [x, y, z]     單位向量，寬
y_axis               [x, y, z]     單位向量，深
z_axis               [x, y, z]     單位向量，高
derivation_method    block_insertion | extrusion_base | unique_plane
```

- 重跑 Scan 若已有合法 `lf_local_frame`，沿用既有框，不因物件旋轉或移動而默默重算。
- 使用者明確要求重算時才重新推導；推導失敗則保留舊框並報告，或在舊框也不合法時阻擋數量。
- 已持久化的框若軸向不正交或長度不是單位向量，視為損壞，阻擋尺寸與數量。

### 計量規則

允許 token：

```text
COUNT
LEN_W
LEN_D
LEN_H
AREA_WD
AREA_WH
AREA_DH
VOL_WDH
```

- Token 量綱必須與 `estimation_unit` 一致，不符直接阻擋。
- 規則留空時不計算 quantity，顯示 `-`，並在報告列出「計量規則未定義」。
- `坪 = 指定面積（m²）× 0.3025`。
- `才 = 指定面積（cm²）÷ (30.3 × 30.3)`，即 1 才＝918.09 cm²。
- `樘`、`片`、`組`、`台`、`座` 等 COUNT 每個物件計 1，再於報表加總。
- `cm`／`mm` 是長度單位；依文件單位轉換後輸出。
- 體積使用 W × D × H 並轉換至指定單位。

| 規則 | 量綱 | 允許單位 |
|---|---|---|
| `COUNT` | count | 樘、片、組、台、座 |
| `LEN_W`／`LEN_D`／`LEN_H` | length | cm、mm |
| `AREA_WD`／`AREA_WH`／`AREA_DH` | area | 坪、才 |
| `VOL_WDH` | volume | m3 |

現行 Dictionary baseline 92 列只用到 `COUNT`、`LEN_W`、`AREA_WH`、`AREA_WD`、`VOL_WDH`；其餘 token 仍屬契約，C05 必須實作。

## Space 與高程

### Space

- 每個 boundary 帶穩定 `space_id`、`level_id` 與顯示名稱；UserText 為 `lf_space_id`、`lf_level_id`、`lf_space_display`。
- ObjectName 只作顯示，不承擔數值或身分。
- 同一 `.3dm` 可有多樓層。
- 相鄰 boundary 可以共邊；**同一 `level_id`** 的內部面積不可重疊。不同樓層允許平面投影重疊。
- 發現同樓層重疊時停止並列出所有衝突 Space；不使用 priority 自動選一個。
- 未命中維持單一 `EXT`，同時可能代表真正室外或漏畫 boundary。
- Coverage Report 必須列出全部 `EXT` 物件與原因：無 boundary layer、layer 無 boundary、取不到 bbox、有 boundary 但未命中；由使用者判斷，不新增第三種狀態。

### Elevation

| Basis | 計算 |
|---|---|
| `BH` | 物件底部高程 |
| `TH` | 物件頂部高程 |
| `CH` | 天花物件底部高程 |
| `BC` | Block 基準點高程；非 Block 直接報錯 |

1.x `TH/BH` 只由 migration 辨識，不進 2.0 enum。

## Registry

- Registry 是不可人工編輯的版本化發布快照；檔名與路徑見「檔案與路徑」。
- 根物件必須含 `schema_id: loopflow.registry`、`schema_version`、`project_id`、`registry_revision`。
- 正式發布掃描 M3D 正式範圍內全部 3D 物件，包含 hidden／locked。
- 不符合 schema 的物件仍須進報告並阻擋發布，不能先被過濾掉。
- 選取／篩選模式只作局部預覽或套用，不得宣告全專案可發布。
- Payload 只含下列 canonical 欄與明確 `extension` 物件，不快照全部 UserText。
- 寫入採 lock → 重讀 → pending → validate → atomic replace；失敗保留 last-good。
- 機器可讀形狀見 `wip/fixtures/schema/registry.json`。

### 根物件

| JSON key | 型別 | 規則 |
|---|---|---|
| `schema_id` | string | 必須為 `loopflow.registry` |
| `schema_version` | integer | 目前 `1` |
| `project_id` | UUID | 與 Rhino 文件 `lf_project_id` 相同 |
| `registry_revision` | integer | 本專案從 `1` 起，發布成功才遞增 |
| `published_at` | string | ISO-8601；只作紀錄，不作身分 |
| `model_unit` | string | 發布當下的 `ModelUnitSystem` 名稱 |
| `types` | array | 當時 Dictionary 的 Type 快照，讓此 revision 不依賴事後改過的 Excel |
| `spaces` | array | 當時全部 Space Boundary；必含保留列 `EXT` |
| `objects` | array | 正式範圍內全部 3D 物件 |
| `extension` | object | 唯一允許的非核心區；未知核心欄仍阻擋 |

| `local_frame` | `loopflow.local_frame` 物件或 null |
| `data_revision` | 寫入此 Registry 前的 Apply revision |

Tag、View、Drawing、Sheet 不進 Registry；Sync 用 `object_id`／Sheet metadata 去對。

## View／Drawing／Sheet

### View

- `view_id`（UserText `lf_view_id`）綁定 Section／Clipping Plane、Detail 與固定 2D↔3D transform。
- 不以名稱或可變 bbox 作正式定位身分。
- 持久化至少包含：`view_id`、`schema_id`、`schema_version`、固定 transform、來源 Section／Detail 參照。

### Drawing

- `drawing_id`（UserText `lf_drawing_id`）保存來源 `view_id`、來源 `registry_revision` 與人工狀態。
- 第一個必做能力是辨識前次產出，讓使用者選取代、新增或略過。
- Drawing element 以 `drawing_element_id` 識別，可有零個、一個或多個 `source_object_ids[]`。
- Provenance 欄位：

| JSON key | 值域 |
|---|---|
| `provenance_method` | `rhino_association`／`loopflow_geometry`／`migration` |
| `provenance_state` | `current`／`modified`／`stale`／`unindexed`／`ambiguous` |

- 人工修改後 `provenance_state` 不得仍為 `current`。
- Materialize 回報 indexed／unindexed／ambiguous 覆蓋率；索引不完整不阻擋 Drawing 產出。
- 更新不得靜默覆寫人工修改的 Drawing。

### Sheet

- `sheet_id`（UserText `lf_sheet_id`）與 metadata 是圖號、圖名、系列、樓層、區域、序號、比例與版次的真相。
- Layout 名稱由 metadata 產生，不反向拆字串取得身分。
- 比例人工輸入；canonical key 為 `scale`，與圖幅、欄位排序及顯示標籤分離。1.x 的 `03-A3 Scale` 不得沿用為 key。
- Layout ID 只寫 manifest 宣告為 `role: title_frame` 的 Block；未知 Block 報告並零寫入。
- Sheet metadata 至少包含：`sheet_id`、`drawing_no`、`drawing_name`、`series`、`level`、`zone`、`sequence`、`scale`、`issue`。圖框顯示對應 `drawing_no`／`drawing_name`／`scale`。

### Duplicate Sheet 特例

- 建立新的 `sheet_id`、`drawing_id`、`tag_id`。
- 除純手動 `TAG_DW` 外，所有 Tag 清除來源綁定、自動（`owner: render`）欄位與 `remarks_manual`，由使用者重新綁定。
- Lock 恢復該 template 的 `default_lock_state`。
- `TAG_DW` 的 `dw_id`、`dw_width`、`dw_height` 及其他 Block 內容完整保留。
- 不使用或覆蓋使用者系統剪貼簿。

### Lock

- Canonical `lock_state` 為 boolean，由 UI 切換。
- Locked Tag 凍結內容與重新綁定，但 Health 仍唯讀判斷 stale／orphaned。
- `TAG_DW` 與 `SAMPLE_FRAME` 沒有 lock 欄；不得為它們寫入 `lf_lock_state`。
- 1.x 非單一 `x/X` 的值只由 migration 列為待確認，不推測使用者意圖。
- 新建與 Duplicate 後，可鎖 template 的 `lock_state` 恢復為 `false`。

## Health 與 Repair

Health 必須唯讀產生 Issue Report；顏色只是可復原的提示層。至少表達：

```text
healthy
unbound
orphaned
stale
ambiguous
manual_locked
unindexed
unchecked
```

- 每項問題保存原因、影響、建議修復、預覽、使用者選擇與 repair result。
- Repair 不得偷偷重綁、換 ID、覆寫人工成果或刪除 Drawing。
- 報告要列出涵蓋與未涵蓋的 Tag／Block；未檢查項目不可併入通過數。
