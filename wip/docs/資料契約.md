# LoopFlow 2.0 — 資料契約

本文件是 2.0 Dictionary、模型資料、Registry、View、Drawing、Sheet、Tag 與 Health 契約的唯一來源。前期決策已封存在 `前期規劃/資料生態決策表.md`；實作不得再從前期討論文字推測答案。

## 契約狀態

- ECO-01～11、ED-01～18、ND-01～28 已裁決。
- 本文件固定資料語意、所有權、值域與驗證規則。
- A03／A04 需將概念欄位鎖成版本化 serialized schema；在 fixtures 通過前不得寫正式專案資料。
- Machine key 固定使用英文；中文／英文只作顯示標籤。

## 共通規則

| 項目 | 規則 |
|---|---|
| 缺值 | 內部使用 typed null；只有 Tag／報表顯示 `-` |
| 版本 | Dictionary、Registry、manifest 與跨程序 payload 必須有 `schema_version` |
| 未知版本 | 停止並說明，不猜測解析 |
| 核心錯誤 | 重複、未知核心欄、錯型別、錯單位、錯量綱直接阻擋 |
| 擴充 | 只允許放在明確的 extension 區，不把任意 UserText 升格為 API |
| ID | 專案範圍唯一；複製產生新 ID；跨檔關聯另用 mapping |
| 顯示名稱 | 可改名，不承擔穩定身分 |
| 人工內容 | 除本文件明列的 Duplicate Sheet 特例外，Sync、Repair、migration 與錯誤處理不得覆寫 |

### Dictionary → Rhino 合併

- Dictionary 有、Rhino 尚無的 layer：建立 layer，帶入 Type mapping 與 `_02` 初始資料。
- Dictionary 與 Rhino 已有同名 layer：保留 Rhino layer 既有資料。
- `_02` instance 現值只由物件維護；同 layer 物件可以不同。
- 重新匯入 Dictionary 不覆寫物件人工修改，也不把物件現值回寫 Dictionary。
- `DNA_REF_` 保留以避免空 Type layer 被 Purge；依穩定 Type ID 更新或取代，不得累積。
- `20_DW` 維持單一 Type 與 child-layer 排除規則。

### Rhino → Dictionary 差異匯出

- 只匯出 layer defaults，以及新增、刪除、改名、修改差異。
- 不彙總 Object UserText。
- 輸出獨立比較用 XLSX；變動 layer 在底部列出。
- 由使用者人工核對與更新正式 Dictionary；不得自動覆寫。

## 模型單位、尺寸與數量

### 文件單位

- 啟動時必須偵測並顯示 `ModelUnitSystem`。
- 非 cm 不阻擋，但要明確警告後續風險並建議切換為 cm。
- 實作不得假裝非 cm 已安全支援；每項量綱計算都必須有單位測試。

### 尺寸 frame

- Block 使用 Block local frame。
- 高度＝local 垂直軸，寬＝local X，深＝local Y；不比較邊長大小。
- 非 Block 幾何的 local frame 來源由 A03 schema／A06 fixtures 固定；在可重現 frame 尚未建立時，validator 必須阻擋尺寸與數量計算，不得退回 World bbox 猜測。

### 計量規則

允許 token：

```text
COUNT
LEN_W
LEN_D
LEN_H
AREA_WD
AREA_WH
AREA_DH
VOL_WDH
```

- Token 量綱必須與 `estimation_unit` 一致，不符直接阻擋。
- 規則留空時不計算 quantity，顯示 `-`，並在報告列出「計量規則未定義」。
- `坪 = 指定面積（m²）× 0.3025`。
- `才 = 指定面積（cm²）÷ (30.3 × 30.3)`，即 1 才＝918.09 cm²。
- `樘`、`片`、`組`、`台`、`座` 等 COUNT 每個物件計 1，再於報表加總。
- `cm`／`mm` 是長度單位；依文件單位轉換後輸出。
- 體積使用 W × D × H 並轉換至指定單位。

## Space 與高程

### Space

- 每個 boundary 帶穩定 `space_id`、`level_id` 與顯示名稱。
- 同一 `.3dm` 可有多樓層。
- 相鄰 boundary 可以共邊，內部面積不可重疊。
- 發現重疊時停止並列出所有衝突 Space；不使用 priority 自動選一個。
- 未命中維持單一 `EXT`，同時可能代表真正室外或漏畫 boundary。
- Coverage Report 必須列出全部 `EXT` 物件與原因：無 boundary layer、layer 無 boundary、取不到 bbox、有 boundary 但未命中；由使用者判斷，不新增第三種狀態。

### Elevation

| Basis | 計算 |
|---|---|
| `BH` | 物件底部高程 |
| `TH` | 物件頂部高程 |
| `CH` | 天花物件底部高程 |
| `BC` | Block 基準點高程；非 Block 直接報錯 |

1.x `TH/BH` 只由 migration 辨識，不進 2.0 enum。

## Registry

- Registry 是不可人工編輯的版本化發布快照。
- 正式發布掃描 M3D 正式範圍內全部 3D 物件，包含 hidden／locked。
- 不符合 schema 的物件仍須進報告並阻擋發布，不能先被過濾掉。
- 選取／篩選模式只作局部預覽或套用，不得宣告全專案可發布。
- Payload 只含 canonical schema 與明確 extension，不快照全部 UserText。
- 寫入採 lock → 重讀 → pending → validate → atomic replace；失敗保留 last-good。

## View／Drawing／Sheet

### View

- `view_id` 綁定 Section／Clipping Plane、Detail 與固定 2D↔3D transform。
- 不以名稱或可變 bbox 作正式定位身分。

### Drawing

- `drawing_id` 保存來源 `view_id`、來源 revision 與人工狀態。
- 第一個必做能力是辨識前次產出，讓使用者選取代、新增或略過。
- Drawing element 可有零個、一個或多個 `source_object_ids[]`。
- Provenance 必須保存 method、revision 與 state；人工修改後不可仍宣稱最新。
- Materialize 回報 indexed／unindexed／ambiguous 覆蓋率；索引不完整不阻擋 Drawing 產出。
- 更新不得靜默覆寫人工修改的 Drawing。

### Sheet

- `sheet_id` 與 metadata 是圖號、圖名、系列、樓層、區域、序號、比例與版次的真相。
- Layout 名稱由 metadata 產生，不反向拆字串取得身分。
- 比例由使用者人工輸入；canonical ID 與圖幅、欄位排序及顯示標籤分離。
- Layout ID 只寫 manifest 宣告為 `role: title_frame` 的 Block；未知 Block 報告並零寫入。

### Duplicate Sheet 特例

- 建立新的 `sheet_id`、`drawing_id`、`tag_id`。
- 除純手動 `TAG_DW` 外，所有 Tag 清除來源綁定、自動欄位與 `attr_manual_補充說明`，由使用者重新綁定。
- Lock 恢復該 Block template 的預設狀態；manifest 必須保存 default lock state。
- `TAG_DW` 的人工編號、寬、高及其他 Block 內容完整保留。
- 不使用或覆蓋使用者系統剪貼簿。

## Tag Template 與 binding

Manifest 至少包含：template ID、family、role、允許的 binding mode、欄位 owner、缺值顯示、template version、default lock state 與 migration mapping。

| Family | Binding | 重要規則 |
|---|---|---|
| Height／Finish Grab | `source_object_id` | 使用者直接選模型來源 |
| Height／Finish Laser | `source_object_id` | 以固定 View transform／有效 provenance 找候選；多候選由使用者選 |
| Index | `target_view_id`／`target_sheet_id` | 圖號來自 Sheet metadata |
| `TAG_ELEV_0` | 無模型 binding | 六個方向／編號欄人工維護 |
| `TAG_DW` | `binding_mode: manual` | 全部欄位人工；Sync 不碰；Health 不判 unbound |
| Furniture Item | `source_type: block_name` | 同款可共用 `FF-01__Chair-1`；格式錯誤停止並警告 |
| Title Frame | `role: title_frame` | 接收圖號／圖名；比例人工 |

家具 Block 名稱是 ECO-04 的明確例外：它不是 object-level binding，Health 不判 `orphaned`。若未來需要逐件追蹤，另增 instance ID，不把流水號塞進共用 Block 名稱。

### Lock

- Canonical `lock_state` 使用 typed boolean／enum，由 UI 切換。
- Locked Tag 凍結內容與重新綁定，但 Health 仍唯讀判斷 stale／orphaned。
- 1.x 非單一 `x/X` 的值只由 migration 列為待確認，不推測使用者意圖。

## Health 與 Repair

Health 必須唯讀產生 Issue Report；顏色只是可復原的提示層。至少表達：

```text
healthy
unbound
orphaned
stale
ambiguous
manual_locked
unindexed
unchecked
```

- 每項問題保存原因、影響、建議修復、預覽、使用者選擇與 repair result。
- Repair 不得偷偷重綁、換 ID、覆寫人工成果或刪除 Drawing。
- 報告要列出涵蓋與未涵蓋的 Tag／Block；未檢查項目不可併入通過數。

- Object ID 複製、碰撞、mapping 與 rollback。
- Space 多樓層、共邊、重疊、EXT 四種原因。
