# LoopFlow 2.0 — 資料契約

本文件是 2.0 Dictionary、模型資料、Registry、View、Drawing、Sheet、Tag 與 Health 契約的唯一來源。前期決策已封存在 `前期規劃/資料生態決策表.md`；實作不得再從前期討論文字推測答案。

## 契約狀態

- ECO-01～11、ED-01～18、ND-01～28 已裁決。
- 本文件固定資料語意、所有權、值域、序列化名稱與驗證規則。
- LF-A03 已鎖定 machine key、身分格式、layer path、指令與檔名。
- LF-A04 已鎖定 Registry 物件欄、10 份 Block template manifest、24 個 legacy key 的 owner 與 migration mapping。
- LF-A06 已鎖定可機器驗證的 fixtures；檢查器為 `wip/tools/check_contract_fixtures.py`。第一條規則是計量規則與單位量綱一致（Type Catalog 給後續 GH 使用；2.0 不算尺寸／數量）。
- 正式專案資料仍不得寫入，直到對應功能通過驗收。
- Machine key 固定使用英文；中文／英文只作顯示標籤。日後正式發布會有 tw／en 兩套使用者文字（指令說明、選單、彈窗、Dictionary 顯示欄名），載入仍對到同一組英文 machine key。開發期只維護繁中，本階段不做語系切換。**Tag 圖塊庫例外**：2.0 `Tag_Blocks.3dm` 只維護一份英文（公式預設提示與鎖定欄皆英文），不另做中文 3dm。

## 共通規則

| 項目 | 規則 |
|---|---|
| 缺值 | 內部使用 typed null；只有 Tag／報表顯示 `-` |
| 版本 | Dictionary、Registry、manifest 與跨程序 payload 必須有 `schema_version` |
| 未知版本 | 停止並說明，不猜測解析 |

| 雙寫 | 日常指令只寫 2.0 canonical key；1.x 名稱只由獨立 migration 辨識 |

## 序列化慣例

- JSON、in-memory schema 與文件層欄位使用英文 `snake_case`，對齊本文件的概念名。
- 3D 物件 UserText 使用編號中文 key（`_01_空間名稱`、`_07_UUID`…），編號沿用 Dictionary 圖面欄 `_01`～`_08`、一個編號只給一個 key，內部欄位接在 `_09` 之後。`_04_ID名稱`（Type 顯示名）只留在 Dictionary 與 Registry 快照，不寫進物件，所以物件上沒有 `_04`。可手動欄的鍵名帶 `*`：空間框 `_01_空間名稱*`、物件 `_02_建構狀態*`／`_08_備註*`、高程框 `_15_樓層高程*`。物件 `_01_空間名稱` 由 Apply 寫入，不加 `*`。Dictionary Excel 欄名不加 `*`。`Q_01`～`Q_06` 是數量欄，只存在 Dictionary，2.0 不寫進物件。JSON 詞幹仍為英文。
- 圖層與文件 UserText 維持 `lf_` 前綴（`lf_type_id`、`lf_project_id`），避免撞上物件的 `_07_UUID` 或其他外掛。
- 同一語意在 JSON 與物件 UserText 對照：JSON 為 `object_id`，物件 UserText 為 `_07_UUID`。
- `schema_version` 為正整數，從 `1` 起跳，獨立於產品版號 `v2.0.0`。
- 每個持久化 payload 還必須有 `schema_id`，用來分辨種類；未知 `schema_id` 視同未知版本。

| schema_id | 用途 | 目前 schema_version |
|---|---|---|
| `loopflow.project` | Rhino 文件上的專案身分 | `1` |
| `loopflow.dictionary` | Type Catalog 載入後的正規化資料 | `1` |
| `loopflow.object` | 3D 物件 instance 現值 | `1` |
| `loopflow.space` | Space Boundary | `1` |
| `loopflow.local_frame` | 尺寸用的持久化座標框 | `1` |
| `loopflow.view` | Section／View 註冊 | `1` |
| `loopflow.drawing` | 可編輯 Drawing 與 provenance | `1` |
| `loopflow.sheet` | Sheet metadata | `1` |
| `loopflow.registry` | 發布快照 | `1` |
| `loopflow.tag_template` | 單一 Tag／圖框 manifest | `1` |
| `loopflow.tag_template_set` | 10 份 manifest 的集合檔 | `1` |

### 身分格式

| 欄位 | 格式 | 規則 |
|---|---|---|
| `project_id`、`object_id`、`space_id`、`level_id`、`view_id`、`drawing_id`、`drawing_element_id`、`sheet_id`、`tag_id` | UUID v4，canonical 小寫 `8-4-4-4-12` | 專案範圍唯一；複製產生新 ID；1.x 大寫 UUID 由 migration 正規化 |
| `type_id` | `{type_category}-{type_sequence}` | 不是 UUID。載入時用 Dictionary 的 12 個類別碼當前綴拆分，禁止只切第一個 `-` |
| `type_category` | 12 個類別碼之一 | 清單由現行 Dictionary 凍結，A06 fixtures 固化 |
| `type_sequence` | 非空字串 | 不含用來組 `type_id` 的那一個連接 `-` |
| `registry_revision` | 每個 `project_id` 從 `1` 起的正整數 | 發布成功才遞增 |
| `EXT` | 保留字 | 未命中 Space 時的唯一 `space_id`；不是 UUID |

### 檔案與路徑

Dictionary 與交換檔只經 `LOOPFLOW_WORKFILES_ROOT` 解析，不寫死磁碟機。

| 用途 | 路徑 |
|---|---|
| Dictionary | `%LOOPFLOW_WORKFILES_ROOT%\<檔名>.xlsx` |
| Registry 正式檔 | `%LOOPFLOW_WORKFILES_ROOT%\exchange\<project_id>\Project_Registry.json` |
| Registry lock | `%LOOPFLOW_WORKFILES_ROOT%\exchange\<project_id>\Project_Registry.lock` |
| Registry pending | `%LOOPFLOW_WORKFILES_ROOT%\exchange\<project_id>\Project_Registry.pending.json` |
| Registry last-good | `%LOOPFLOW_WORKFILES_ROOT%\exchange\<project_id>\Project_Registry.last-good.json` |

- 預設 Dictionary 檔名為 `LoopFlow_Dictionary.xlsx`。可改成同一個工作檔資料夾根目錄裡的其他 `.xlsx` 檔名；記住在 Rhino 文件 UserText `lf_dictionary_filename`（只存檔名，不含路徑）。第一次同步或已記住的檔找不到時才選檔。
- 不掃同目錄所有 Excel，也不從 `.3dm` 旁猜檔。匯出檔（`*_Export.xlsx`）不能當正式字典。
- `project_id` 寫在 Rhino 文件 UserText `lf_project_id`，不從 `.3dm` 檔名推導。
- 缺少環境變數、目錄或 `project_id` 時停止，不猜測路徑、不建立正式 Registry。
- log 檔名可為進階設定；Registry 檔名是契約，不是使用者偏好。

### 文件與圖層 UserText

物件用編號中文 key；**文件與圖層** 維持 `lf_` 前綴，避免撞上物件的 `_07_UUID` 或其他外掛。

| 寫在哪 | 鍵 | 值 | 規則 |
|---|---|---|---|
| Rhino 文件 | `lf_project_id` | 小寫 UUID v4 | 專案身分；不從 `.3dm` 檔名推導，缺少即停止 |
| Rhino 文件 | `lf_schema_id` | `loopflow.project` | 開案檢查必讀；缺少或未知即停止 |
| Rhino 文件 | `lf_schema_version` | `1` | 同上；非整數或未知版本即停止 |
| Rhino 文件 | `lf_layer_prefix` | 專案名稱，預設 `M3D` | 圖層樹前綴；不是 UUID |
| Rhino 文件 | `lf_dictionary_filename` | 檔名，不含路徑 | 記住選過的 Dictionary |
| Rhino 文件 | `lf_sheet.<sheet_id>.<field>` | Sheet metadata 各欄 | 圖號、圖名與系列的真相；欄位見「Sheet」節 |
| Rhino 文件 | `lf_sheet_naming.<key>` | 圖號格式設定 | 缺值用內建預設；見「Sheet」節 |
| Rhino 文件 | `lf_title_frame_blocks` | `;` 分隔的 Block 名 | 本專案認可的圖框；未登錄不寫入 |
| Rhino 圖層 | `lf_type_id` | Dictionary `_03_ID編號` | Type layer 的 Type mapping |
| Rhino 圖層 | `lf_construction_default` | Dictionary `_02_建構狀態` 預設 | 只供新建 layer 的初值，不覆寫物件現值 |

缺 `lf_project_id`、`lf_schema_id` 或 `lf_schema_version` 時開案檢查即停止，不自動補寫、不建立檔案。

### Layer path

- 使用完整 path，分隔符為 `::`；terminal name 不得單獨當身分。
- 大小寫與空白以 Dictionary 的 `__Rhino Layer` 為準，程式不得自行折疊或補空白。
- 3D 正式範圍前綴預設 `M3D`，可改成這份 `.3dm` 記住的專案名稱（文件 UserText `lf_layer_prefix`）。一般 2D 前綴仍為 `M2D`。View 框的父圖層是 `LoopFlow`，不是 `M2D`。更改前綴不會自動改名既有 layer。
- 系統資料層為契約，不是可隨意改的顯示偏好；根名稱隨專案前綴變化：

```text
<專案名稱>::_Data::Space_Boundaries
<專案名稱>::_Data::Level_Boundaries_FFL
<專案名稱>::_Data::Level_Boundaries_FL
<專案名稱>::20_DW
LoopFlow::Anchor_Frame
LoopFlow::Drawing_Number
LoopFlow::Drawing_Name
LoopFlow::Drawing_Text
LoopFlow_Extract
```

未寫入前綴時 `<專案名稱>` 即 `M3D`。`LoopFlow` 與其子圖層建立時一律設為不列印。

`LoopFlow_Extract` 是 Extract／Materialize 產出的根圖層，與 `LoopFlow` **平級**，不是 `LoopFlow::Extract`。`is_loopflow_layer` 只認 `LoopFlow` 與 `LoopFlow::` 前綴，因此這個根層不會自動套用現有 No Print；E02 實作時須同樣把列印寬度設為 `No Print`（`PlotWeight = -1`）。子層（1.x 的 `Visible`／`Hatch`／`Curve_#HEX`）等 E02 開工再定。本批只鎖根名稱，不實作 Extract。

- `DNA_REF_` 參考點依 `type_id` 更新或取代，名稱不得只依 layer 字串累加。
- Type layer 顯示色依圖層代號前綴（1.x 顯示慣例）。新建材質名稱為去掉 `M3D::` 的相對路徑（保留一個父圖層），顏色與圖層相同。已存在的同名材質只掛回圖層，不改使用者調過的色。不寫入物件 instance 顏色。
- `2D_D1`、`3D_W1` 只供獨立 2D 工具解析，主鏈不當身分。家具 `FF-01__Chair-1` 見 ED-14。

## Dictionary／Type Catalog

工作來源：`%LOOPFLOW_WORKFILES_ROOT%\LoopFlow_Dictionary.xlsx` 中文版本。

2026-08-14 已驗證狀態：`LoopFlow Dictionary v2.0`，15 欄、92 筆 Type、12 個類別碼、12 個頂層群組；`Q_05_計量規則` 為 92/92 已填、0 筆量綱不符。（該欄在 2026-08-14 併入主表時曾暫用欄名 `(單位計量規則)`，現行欄名見下表。）

### 欄位角色

| 現行顯示欄 | 2.0 概念欄位 | Role／Owner | 規則 |
|---|---|---|---|
| `__Rhino Layer` | `layer_path` | Type mapping | 人類分類入口，不是 Type 主鍵 |
| `_01_空間名稱` | `space_id`／`space_display` | computed instance | Dictionary row 不提供預設 |
| `_02_建構狀態` | `construction_default` | Type default | 只為新建 Rhino layer 提供初始值 |

| `_04_ID名稱` | `type_display_name` | Type display | 非唯一、可改名 |
| `_05_高程基準` | `elevation_basis` | Type rule | 2.0 只允許 BH／TH／CH／BC |
| `_06_高程計算` | `elevation_value`／`elevation_display` | computed instance | typed 數值與顯示字串分離 |

### 字型

- 繁中版 Dictionary（現行工作來源與匯出）：微軟正黑體 10。
- 英文版 Dictionary（日後發布）：Arial 10。
- 本階段只維護繁中；匯出檔沿用繁中字型。程式常數為 `DICTIONARY_FONT_NAME`／`DICTIONARY_FONT_NAME_EN`。

### Dictionary → Rhino 合併

- Dictionary 有、Rhino 尚無的 layer：建立 layer，並在**圖層** UserText 寫入 `lf_type_id` 與 `lf_construction_default`（`_02_建構狀態` 的 Type 預設）。物件的 `_02_建構狀態*` 由物件自己維護。
- Dictionary 與 Rhino 已有同名 layer：保留 Rhino layer 既有資料。
- `_02` instance 現值只由物件維護；同 layer 物件可以不同。
- 重新匯入 Dictionary 不覆寫物件人工修改，也不把物件現值回寫 Dictionary。
- `DNA_REF_` 參考點放在原點，以避免空 Type layer 被 Purge；依穩定 `type_id` 更新或取代，不得累積。
- `20_DW` 維持單一 Type 與 child-layer 排除規則。

### 物件 instance 核心欄

3D 物件 UserText 只寫圖面需要的 canonical key。`Q_01`～`Q_06`（寬深高、單位、計量規則、實作數量）留在 Type Catalog，2.0 不下放、不計算。

編號沿用 Dictionary 圖面欄 `_01`～`_08`，但 `_04_ID名稱` 只在 Dictionary 與 Registry 快照，物件上沒有 `_04`。物件與空間框的 `_01` 鍵名不同（有無 `*`）；其餘一個編號只給一個 key。內部欄位接在 `_09` 之後。下表含只寫在框線上的欄（`_01*`、`_10`、`_15*`），規則欄已標明寫在哪裡。

| UserText key | JSON key | 型別 | Owner | 規則 |
|---|---|---|---|---|
| `_01_空間名稱` | `space_display` | string | computed | 3D 物件顯示名稱；`EXT` 時顯示 `EXT`。由 Apply 從空間框複製，不加 `*`。中文名稱如「廊道」「衛浴」合法 |
| `_01_空間名稱*` | `space_display` | string | 空間框 | 只寫在空間框，可手動改。再 Apply 才同步到框內物件 |
| `_02_建構狀態*` | `construction_status` | string | instance override | 新 layer 才從 `construction_default` 初值；之後只由物件維護 |
| `_03_ID編號` | `type_id` | string | Type reference | 必須能在 Dictionary 找到 |
| `_05_高程基準` | `elevation_basis` | enum | computed snapshot | Apply 時從 Type 複製，供 stale 比對 |
| `_06_高程計算` | `elevation_value` | number | computed | 命中空間後＝高程框 `_15` ＋（物件取樣 Z − 框曲線 Z）。`_05` 決定取樣點。未命中（`EXT`）或找不到高程框時用世界 Z |
| `_07_UUID` | `object_id` | UUID | system | 不接受 Dictionary 預設；碰撞時預覽 mapping，禁止靜默換號 |
| `_08_備註*` | `remarks` | string | instance override | 新物件可用 `(手動輸入備註)`；已填不覆寫 |
| `_09_空間ID` | `space_id` | UUID 或 `EXT` | computed | 未命中為 `EXT` |
| `_10_樓層ID` | `level_id` | UUID | 高程框／空間框 | 只寫在高程框與空間框；**3D 物件不寫**。登記空間框時由配對到的高程框帶入。Registry 只在 `spaces[]` 帶 `level_id`，物件的樓層由命中的空間框間接決定 |
| `_11_類型類別` | `type_category` | string | Type reference | 與 `type_id` 拆分結果一致 |
| `_12_類型序號` | `type_sequence` | string | Type reference | 與 `type_id` 拆分結果一致 |
| `_13_高程顯示` | `elevation_display` | string | computed | 顯示字串，不回解析成數值 |
| `_14_資料版次` | `data_revision` | integer | system | 尚未發布為 `0`；已有正式 Registry 則為該檔 `registry_revision`。Apply 寫回此值（覆寫手動亂填）。成功發布後寫入該次 `registry_revision` |
| `_15_樓層高程*` | `level_datum` | string | 高程框 | 只寫在高程框，不寫 3D 物件。數字字串如 `0`／`320`。讀取時若沒有此 key，才退回 ObjectName（舊檔相容）。可手動改；再 Apply 後該層物件 `_06` 跟著更新 |

Rhino 物件 UserText 用上表編號中文 key，讓面板依 `_01`、`_02`… 排序，且不得出現重複編號。可手動欄（空間框 `_01*`、物件 `_02*`／`_08*`、高程框 `_15*`）鍵名帶 `*`；物件 `_01` 與 `_14` 不加。Dictionary Excel 欄名不加 `*`。JSON／Registry 仍用英文。讀取時若沒有新 key，仍可讀無 `*` 的同名舊鍵、舊的 `lf_*` 與 2.0 開發期編號（含上一輪物件上的 `_01_空間名稱*`）。Apply 會寫新 key、清掉舊 key，並清掉尺寸／數量／座標框殘留（`_05_寬度W`、`Q_01_寬度W`、`lf_local_frame` 等）。圖層與文件 UserText（`lf_type_id`、`lf_project_id`）維持 `lf_`。

### Rhino → Dictionary 差異匯出

- 獨立指令 `LF_Export_Type_Layers` 在 Dictionary 同一目錄新增 `{原檔名}_Export.xlsx`。
- 第 1 列紅色提示（字高 20）：此檔只供核對，不能當正式字典、不可覆寫 `LoopFlow_Dictionary.xlsx`；`added_in_rhino` 合併時必須給新的 `_03_ID編號`。
- 第 2 列標題、第 3 列欄名。正式 Dictionary 不加提示列。
- 欄位對齊正式 Dictionary 的 15 欄，另加 `diff_status`（`unchanged`／`modified`／`missing_in_rhino`／`added_in_rhino`）。匯出檔不可當正式字典開啟。
- 整份字體、字高跟正式 Dictionary 相同（繁中微軟正黑體 10，英文版日後用 Arial；提示列除外）。只把有變動的 `diff_status` 文字換色，不改整列底色：`missing_in_rhino` 紅、`added_in_rhino` 藍、`modified` 橙；`unchanged` 維持預設黑。

- `added_in_rhino` 列在底部。新圖層若沿用舊 `lf_type_id`，合併前必須改成尚未使用的編號，否則正式字典會因 `duplicate_type_id` 無法載入。
- 由使用者人工核對與更新正式 Dictionary；不得自動覆寫。

## 模型單位與數量欄（2.0 不算尺寸）

2.0 只要圖面表達正確：高程、材料編號、空間。寬深高、面積、長度、實作數量留給後續 Grasshopper 可視化數量計算，不進 Nexus Scan／Apply，也不進 Registry `objects[]`。

### 文件單位

- 啟動時必須偵測並顯示 `ModelUnitSystem`。
- 非 cm 不阻擋，但要明確警告後續風險並建議切換為 cm。

### Dictionary 數量欄（給 GH）

`Q_01`～`Q_06` 留在 Type Catalog。`Q_04_單位` 與 `Q_05_計量規則` 是 Type 規則，載入時仍檢查量綱一致。`Q_01`～`Q_03`、`Q_06` 為計算欄，Dictionary row 留白。

允許 token（GH 後續使用；2.0 只驗證、不求值）：

```text
COUNT
LEN_W
LEN_D
LEN_H
AREA_WD
AREA_WH
AREA_DH
VOL_WDH
```

- Token 量綱必須與 `estimation_unit` 一致，不符直接阻擋 Dictionary 載入。
- 規則留空時警告「計量規則未定義」，不阻擋載入。
- `坪 = 指定面積（m²）× 0.3025`。
- `才 = 指定面積（cm²）÷ (30.3 × 30.3)`，即 1 才＝918.09 cm²。

| 規則 | 量綱 | 允許單位 |
|---|---|---|
| `COUNT` | count | 樘、片、組、台、座 |
| `LEN_W`／`LEN_D`／`LEN_H` | length | cm、mm |
| `AREA_WD`／`AREA_WH`／`AREA_DH` | area | 坪、才 |
| `VOL_WDH` | volume | m3 |

現行 Dictionary baseline 92 列只用到 `COUNT`、`LEN_W`、`AREA_WH`、`AREA_WD`、`VOL_WDH`。換算常數與 token 契約保留給 GH，不在 2.0 從模型幾何求值。

## Space 與高程

### Space

- 每個 boundary 帶穩定 `space_id`、`level_id` 與顯示名稱；UserText 為 `_09_空間ID`、`_10_樓層ID`、`_01_空間名稱*`。登記時曲線會放到 `M3D::_Data::Space_Boundaries`。中文名稱合法。
- 只有 `M3D::_Data::Space_Boundaries` 圖層上的曲線算 Space。畫在別層的曲線要先跑登記（選單 4）讓程式搬層，不在命中階段替使用者猜。
- 高程框與空間框**不寫入物件名稱**。高程框寫 `_10_樓層ID`、`_15_樓層高程*`；空間框寫 `_09_空間ID`、`_10_樓層ID`、`_01_空間名稱*`。讀樓層高程時若沒有 `_15_樓層高程*`，才退回無 `*` 舊鍵或 ObjectName（舊檔）。
- 登記高程框：先彈出清單點選 FFL 或 FL，選線後彈出視窗輸入高程。登記空間框：可複選，彈出視窗輸入同一個空間名稱。選線只用曲線過濾（對齊 1.x），不鎖全檔非曲線物件；已鎖定／隱藏的封閉曲線會先解開以便選到。兩步完成後曲線會搬到對應圖層。
- 登記時不必手填 `_10_樓層ID`。程式用空間框與高程框配對：高程差在 ±20 模型單位內（文件建議 cm 時即 ±20 cm），且空間多邊形整圈在高程多邊形內（共邊可）。對到後沿用或新建高程框上的 `_10_樓層ID`。
- FFL 與 FL 都算高程框；同一平面兩者都符合時優先 FFL。對不到或同時對到多個同條件高程框則停止。
- 同一 `.3dm` 可有多樓層。
- 相鄰 boundary 可以共邊；**同一 `level_id`** 的內部面積不可重疊。不同樓層允許平面投影重疊。
- 發現同樓層重疊時停止並列出所有衝突 Space；不使用 priority 自動選一個。
- 未命中維持單一 `EXT`，同時可能代表真正室外或漏畫 boundary。
- Coverage Report 必須列出全部 `EXT` 物件與原因：無 boundary layer、layer 無 boundary、取不到 bbox、有 boundary 但未命中；由使用者判斷，不新增第三種狀態。

### Elevation

物件 `_06_高程計算`／`_13_高程顯示` 在命中空間後＝該空間所屬高程框 `_15_樓層高程*` ＋（物件取樣 Z − 高程框曲線 Z）。`_05_高程基準` 決定取樣點（BH／TH／CH／BC）。各層畫在 Z=0、框也在 Z=0 時，就是框數字加物件高度（樓面 50、窗台 150）。找不到高程框時維持世界 Z。

未命中空間（`EXT`）時沒有高程框可對，用下表對世界座標取樣。

| Basis | 未命中空間時的取樣 |
|---|---|
| `BH` | 物件底部世界 Z |
| `TH` | 物件頂部世界 Z |
| `CH` | 天花物件底部世界 Z |
| `BC` | Block 基準點世界 Z；非 Block 直接報錯 |

幾何命中仍是 XY：底面中心，沒命中再用四角。同時命中兩個以上空間時不自動猜；Apply 會 zoom 後彈出清單點選空間名稱。已寫入且仍屬於命中集合的 `space_id` 視為已指定。

樓層歸屬靠空間框平面範圍。各層並排畫在 Z=0、用不同高程框包住，是預期畫法。上下層平面重疊會變成不明確。

1.x `TH/BH` 只由 migration 辨識，不進 2.0 enum。

## Registry

- Registry 是不可人工編輯的版本化發布快照；檔名與路徑見「檔案與路徑」。
- 根物件必須含 `schema_id: loopflow.registry`、`schema_version`、`project_id`、`registry_revision`。
- 正式發布掃描 M3D 正式範圍內全部 3D 物件，包含 hidden／locked。
- 不符合 schema 的物件仍須進報告並阻擋發布，不能先被過濾掉。
- 選取／篩選模式只作局部預覽或套用，不得宣告全專案可發布。
- Payload 只含下列 canonical 欄與明確 `extension` 物件，不快照全部 UserText。
- 寫入採 lock → 重讀 → pending → validate → atomic replace；失敗保留 last-good。唯一寫入模組是 `features/registry`（C03）。Nexus 組 payload 屬 NX-07，不得自己寫 lock 或刪正式 JSON。
- 機器可讀形狀見 `wip/fixtures/schema/registry.json`。

### 根物件

| JSON key | 型別 | 規則 |
|---|---|---|
| `schema_id` | string | 必須為 `loopflow.registry` |
| `schema_version` | integer | 目前 `1` |
| `project_id` | UUID | 與 Rhino 文件 `lf_project_id` 相同 |
| `registry_revision` | integer | 本專案從 `1` 起，發布成功才遞增 |

| `objects` | array | 正式範圍內全部 3D 物件 |
| `extension` | object | 唯一允許的非核心區；未知核心欄仍阻擋 |

對齊物件 instance 核心欄。`type_display_name` 在此為發布當下快照，供 Sync 讀取，不回寫物件 UserText。`measurement_rule` 與 `estimation_unit` 只在 `types[]`。`dimension_*`、`quantity`、`local_frame` 不進 `objects[]`。

## View／Drawing／Sheet

### View

- `view_id`（UserText `lf_view_id`）綁定 Section／Clipping Plane、Detail 與固定 2D↔3D transform。
- 不以名稱或可變 bbox 作正式定位身分。
- 持久化至少包含：`view_id`、`schema_id`、`schema_version`、固定 transform、來源 Section／Detail 參照。
- 指令 `LF_Anchor_Frame` 在 **2D 模型空間**框選剖面物件與恰好一個 Text Dot；Text Dot 文字只當唯一命中 Clipping Plane 的提示。0 或 ≥2 個命中即停，不猜測。Esc／取消零寫入。
- 框畫在 `LoopFlow::Anchor_Frame`，作為 UserText 宿主；Laser 只讀 `lf_view_id` 與固定 transform，不再靠名稱重算 bbox。`LoopFlow` 與其子圖層不列印。
- 若選取含既有 1.x `Role=Anchor_Frame` 框，則升級該框、不另畫一條、不刪舊 `Role`／`Target_CP`。
- 1.x `Role`／`Target_CP` 只供診斷與 migration；日常不雙寫。若選取含既有 1.x 框，升級寫入 2.0 欄、不刪線稿、不刪舊 key。
- 本批不要求 Layout 上已有 Detail，不射線。`lf_detail_id` 可缺。3D 模型須能與 Clipping Plane 相交（含 worksession 連結檔），否則無法寫入固定 transform。
- 機器可讀欄位見 `wip/fixtures/schema/view.json`；案例見 `wip/fixtures/contract/view/cases.json`。

| JSON key | UserText key | 規則 |
|---|---|---|
| `view_id` | `lf_view_id` | 小寫 UUID v4；缺才新建，升級既有框則沿用 |
| `schema_id` | `lf_schema_id` | 固定 `loopflow.view` |
| `schema_version` | `lf_schema_version` | 目前 `1` |
| `clipping_plane_id` | `lf_clipping_plane_id` | Clipping Plane 的 Rhino 物件 ID，不用名稱當身分 |
| `view_transform` | `lf_view_transform` | JSON：2D 原點、CP 局部原點、`scale_x`／`scale_y`（±1）、CP 平面原點與三軸 |
| `detail_id` | `lf_detail_id` | 可缺；本批不寫 |

`view_transform` 的 `scale_x` 在名稱含 `CEILING`／`天花`／`RCP` 時為 `-1`（鏡射）；`scale_y` 固定 `-1`（Invert Y）。此值在登記當下寫死。Clipping Plane 移動後須重新登記。

### Drawing

- `drawing_id`（UserText `lf_drawing_id`）保存來源 `view_id`、來源 `registry_revision` 與人工狀態。
- 第一個必做能力是辨識前次產出，讓使用者選取代、新增或略過。
- Drawing element 以 `drawing_element_id` 識別，可有零個、一個或多個 `source_object_ids[]`。
- Provenance 欄位：

| JSON key | 值域 |
|---|---|
| `provenance_method` | `rhino_association`／`loopflow_geometry`／`migration` |
| `provenance_state` | `current`／`modified`／`stale`／`unindexed`／`ambiguous` |

- 人工修改後 `provenance_state` 不得仍為 `current`。
- Materialize 回報 indexed／unindexed／ambiguous 覆蓋率；索引不完整不阻擋 Drawing 產出。
- 更新不得靜默覆寫人工修改的 Drawing。

### Sheet

- `sheet_id`（UserText `lf_sheet_id`）與 metadata 是圖號、圖名、系列、樓層、區域、序號、比例與版次的真相。
- Layout 名稱由 metadata 產生，不反向拆字串取得身分。
- 比例人工輸入；canonical key 為 `scale`，與圖幅、欄位排序及顯示標籤分離。1.x 的 `03-A3 Scale` 不得沿用為 key。
- Layout ID 只寫 manifest 宣告為 `role: title_frame` 的 Block，或本文件下述「專案圖框登錄」認可的 Block；未登錄 Block 報告並零寫入。
- Sheet metadata 至少包含：`sheet_id`、`drawing_no`、`drawing_name`、`series`、`level`、`zone`、`sequence`、`scale`、`issue`。圖框顯示對應 `drawing_no`／`drawing_name`／`scale`。

#### Sheet metadata 存放

Rhino 的 Layout 分頁沒有可持久化的 UserText，因此 metadata 存在**文件 UserText**，命名空間為 `lf_sheet.<sheet_id>.<field>`；`<field>` 只允許上列 canonical 欄位加 `page_position`。

| key | 內容 |
|---|---|
| `lf_sheet.<sheet_id>.drawing_no` | 圖框圖號，由圖類別與編號組成，例如 `IN 201` |
| `lf_sheet.<sheet_id>.drawing_name` | 人工維護；首次由頁名第三欄匯入，之後可改第三欄再跑 Layout ID 更新 |
| `lf_sheet.<sheet_id>.series` | 圖類別，例如 `IN`、`A` |
| `lf_sheet.<sheet_id>.sequence` | 圖編號字串，例如 `201`、`201.02`；由起點尾數與頁序推導 |
| `lf_sheet.<sheet_id>.page_position` | 寫入當下的 Layout 頁序，供 consumer 偵測過期 |
| `lf_sheet.<sheet_id>.level`／`.zone`／`.scale`／`.issue` | 目前由人工或後續 Sheet 管理介面維護；Layout ID 不寫 |

每一頁的身分錨點是該頁 title frame instance 上的 `lf_sheet_id`。一頁沒有圖框或有兩個以上圖框時無法決定身分，該頁跳過並報告，不改頁名、不寫 metadata。

#### persistent 與 derived

| 欄位 | 性質 |
|---|---|
| `sheet_id` | persistent identity，永不因重新編號而改變 |
| `series`、`drawing_name` | persistent metadata |
| `sequence`、`drawing_no` | derived，可被重新計算 |

`drawing_no` **不是** identity。插頁使既有頁的 `drawing_no` 由 `IN 202` 變成 `IN 203` 時，其 `sheet_id` 不得改變。任何跨模組關聯（Tag、Index、Drawing、Catalog）都以 `sheet_id` 為 binding key，不得使用 Layout 頁名、`drawing_no`、Rhino Layout GUID 或 title frame 物件 GUID。

#### 編號規則

Layout ID 頁名與圖框圖號的完整操作說明見 `工作流程.md` §9；本節鎖定契約行為，供實作與 fixtures 對照。

- 系列起點：頁名最前面加 `**`，格式 `**圖類別__圖編號__圖名`。寫入後起點頁保留 `**`；圖框 `drawing_no` 不含 `**`。頁名沒有 `**` 時不得用舊 metadata 當起點或把星號加回；檔案中零個 `**` 且無可寫入手動頁時，整批停止並只顯示命名說明（彈窗不附加 skipped 清單）。
- 最前面 `//` 的頁為手動頁：不參與自動編號、不佔系列尾數；格式必須相同（`//S__901__結構平面圖`）。寫入後保留 `//`；圖框寫入 `S 901`／圖名，不含 `//`。格式不對則該頁跳過，不阻擋其他頁。僅有合法 `//`、沒有 `**` 時，只寫入手動頁。
- 圖框 `drawing_no` 為「圖類別 + 空格 + 圖編號」（`IN 201`、`IN A01`）；Layout 頁名為三欄。兩者分隔符不同。
- 圖編號只要尾端是數字就放行，允許英數（`201`、`101.1`、`A01`）。不強制 `.01`。接續頁只把**尾端數字 +1**：`201`→`202`；`A09`→`A10`；單號進十位顯示兩位數，`101.1`→`101.2`→`101.9`→`101.10`。
- 新建的空白 Layout（例如 `Layout 05`）繼承上一頁的圖類別並接下一號。要開新系列或從某頁改號，在該頁再加 `**`。
- 頁序中第一個 `**` 起點尚未出現前的頁面不自動編號。
- 重跑時：頁名仍是可解析的三欄則第三欄更新圖名；改成沒有 `__` 的亂名且前面已有 `**` 則恢復 metadata 圖名。不要直接改圖框 UserText 來改號。編號與命名從 Layout 列表調整後再跑，由自動編號寫入圖框。
- 缺系列起點時的使用者說明全文由指令常數維護，內容與 `工作流程.md` §9 的 Sample／五條規則一致；`format_result_popup` 遇 `missing_series_start` 時不得再串接 skipped 明細。

命名格式存放於文件 UserText，缺值時使用內建預設：

| key | 預設值 |
|---|---|
| `lf_sheet_naming.separator` | `__` |
| `lf_sheet_naming.baseline_mark` | `**` |
| `lf_sheet_naming.drawing_no_format` | `{prefix} {number}` |
| `lf_sheet_naming.sheet_ref_format` | `{number}` |

不沿用 1.x 放在專案資料夾旁的 `NamingRules_Config.json`，避免綁死單機路徑。也不沿用 1.x 的 `IN 101.01`（空白＋強制 `.01`）。

#### 頁名解析

`**` 與三欄結構在每次執行都會讀，用來找新起點與更新圖名。`sheet_id` 仍以圖框 UserText 為準，不從頁名拆身分。

| 頁名情況 | 行為 |
|---|---|
| `**IN__201__立面圖` | 系列 `IN` 從 `201` 起；圖框圖號 `IN 201`；寫入後頁名仍為 `**IN__201__立面圖` |
| `**A__201.02__立面圖` | 系列 `A` 從 `201.02` 起；下一頁 `A 201.03` |
| `**IN__A01__平面` | 圖號英數、尾端是數字即放行；下一頁 `IN A02` |
| `**IN__101.9__一樓` | 單號尾數進十位為 `IN 101.10` |
| `//S__901__結構平面圖` | 手動頁；圖框 `S 901`；不佔系列尾數；寫入後保留 `//` |
| `樓下30公分`（無 `**`） | 繼承上一頁系列，尾數 +1；圖名用該頁現有名稱 |
| `IN__201__一樓平面`（無 `**`、三欄，且前面已有 `**`） | 不重設編號；第三欄當新圖名 |
| 沒有 separator 的亂名 | 前面已有 `**` 且已有 metadata 則恢復舊圖名與自動頁名 |
| 多個 separator | 第一欄圖類別、第二欄編號，其餘歸入圖名 |
| separator 後為空 | 圖名留空並在清單標示，不阻擋其他頁 |
| 頁名為空 | 該頁跳過並報告 |

所有解析結果先進核對清單顯示狀態，使用者確認後才寫入；取消則整批零寫入。

#### 專案圖框登錄

除 manifest 的 `role: title_frame`（`Sample_Frame`）恆定有效外，本份 `.3dm` 認可的圖框 Block 名記錄於文件 UserText `lf_title_frame_blocks`，以 `;` 分隔、查找不分大小寫。Layout ID 遇到未登錄的 Block 時列出名稱，讓使用者勾選哪些是圖框（預設全不勾）；沒勾選的不登錄、不寫入。不可把清單裡的全部 Block 整批當成圖框。不採用 1.x「不是 Tag 就當圖框」的排除法。

#### active Sheet 與 consumer rule

- active Sheet 以「目前存在的 Layout 頁 + 該頁 title frame 上的 `lf_sheet_id`」為準。**metadata 存在不等於該 Sheet 仍 active**；Layout 被刪除後 metadata 會成為 orphan record，Layout ID 不自動清除，consumer 必須自行判斷有效性。
- Sheet 的顯示順序預設 follow Rhino Layout 頁序，除功能自身有明確規則外不得改用 `drawing_no` 字串排序。
- `drawing_no` 與 `sequence` 是 derived 值，只有執行 `LF_Tagger_Layout_ID` 才會更新。consumer 必須以「目前頁序推算值」比對 metadata 的 `page_position`／`sequence`，不一致時回報 `stale` 並要求先執行 Layout ID，不得安靜輸出舊值。
- 跨模組取用 Sheet 資料一律經 `sheet_id` 與 Sheet metadata API，不得自行解析 Layout 頁名、讀圖框文字、或建立第二份 Layout registry；也不得建立 `drawing_no`／`drawing_name` 的資料副本。
- `lf_catalog_*` 前綴專供 `LF_Catalog` 的定位點與產生文字，其他功能不得占用。

### Duplicate Sheet 特例

- 建立新的 `sheet_id`、`drawing_id`、`tag_id`；圖目錄定位點的 `lf_catalog_id` 亦必須換新號，`lf_catalog_sheet_id` 依 Sheet 換號規則重新指定或清除，否則兩份圖目錄會共用同一個 `catalog_id` 而互相覆蓋。
- 除純手動 `TAG_DW` 外，所有 Tag 清除來源綁定、自動（`owner: render`）欄位與 `remarks_manual`，由使用者重新綁定。
- Lock 恢復該 template 的 `default_lock_state`。
- `TAG_DW` 的 `dw_id`、`dw_width`、`dw_height` 及其他 Block 內容完整保留。
- 不使用或覆蓋使用者系統剪貼簿。

## Catalog Anchor

Catalog 定位點是 Rhino 獨立 Point，用來記住「這一格對應哪個 Sheet」。新建目錄文字時以定位點為左下角原點；Refresh 只改內容，已移動的文字留在原處，並保留字型、大小、圖層。

| key | 意義 |
|---|---|
| `lf_catalog_id` | 屬於哪一份圖目錄，UUID；同一文件可有多份目錄 |
| `lf_catalog_field` | 只允許 `drawing_no` 或 `drawing_name`，不得由圖層名反推 |
| `lf_catalog_sheet_id` | 目前綁定的 Sheet；空位不寫此欄 |
| `lf_catalog_home_layer` | 選取歸位前的圖層；清除定位點時還原 |

判定條件是「在指定圖層**且**具備 `lf_catalog_id`」兩者同時成立。把無關 Point 拖進圖層不算 anchor。空位仍是合法定位點：40 格可只放 28 張圖。定位點不保存圖號、圖名實值，也不保存 Layout 頁名。

| 動作 | 目標圖層 | 顏色 |
|---|---|---|
| 選取圖號定位點 | `LoopFlow::Drawing_Number` | 紅 `(255, 0, 0)` |
| 選取圖名定位點 | `LoopFlow::Drawing_Name` | 綠 `(0, 255, 0)` |
| 產生目錄文字 | `LoopFlow::Drawing_Text` | `#CDB38B` `(205, 179, 139)` |

`LoopFlow` 與其子圖層（含 `Anchor_Frame`、圖目錄定位點與文字）建立時一律不列印。Rhino 8 圖層面板對應的是列印寬度 `No Print`（`PlotWeight = -1`），用 `rs.LayerPrintWidth` 寫入。

定位點必須是文件中的獨立 Point。選到 Block instance 或其子物件時報錯並零寫入。選取歸位當下就改圖層，後續 Build 取消不還原已歸位的點。

產生文字寫 `lf_generated_by = LF_Catalog`、`lf_catalog_id`、`lf_catalog_point_id`、`lf_catalog_field`。新建時左下角對齊定位點。Refresh 以 generated keys 找出文字，對得到定位點就只改內容，不重設字型、大小、圖層、顏色，也**不把已移動的文字拉回定位點**；對不到才在定位點新建。未用到的舊目錄文字才刪。不得用「定位點附近的文字」判斷。

定位點另寫 `lf_catalog_home_layer`（選取歸位前的圖層）。「清除定位點並還原圖層」會清掉目錄 UserText、把點放回原圖層，並刪除該目錄產生的文字。沒記下原圖層的點只清資料、放到 `Default`。

排序必須先依 Layout 頁序分組，再 X 分欄（容差 `2.0` cm）、各欄 Y 由上而下。跨頁座標會撞號，不分頁就排序是錯誤。圖號與圖名各自排序後配對：逐頁數量必須相等（全域總數相等不算過），且同列 Y 必須在容差內。Sheet 順序用 Rhino Layout 頁序。定位點多於 Sheet 則多餘留白；Sheet 多於空位則零寫入。

Build／Rebind 改綁定；Refresh 不改綁定，只更新文字內容。已移動的目錄文字留在新位置。新 Layout 不自動納入。Sheet metadata 過期（頁序變了沒重跑 Layout ID）必須擋下並要求先跑 D04。missing／orphan Sheet 逐項跳過並報告，不擋其餘更新。

### Lock

- Canonical `lock_state` 為 boolean，由 UI 切換；UserText 寫 `lf_00_lock_state` 的 `true`／`1`。畫面上亦可輸入 `x`／`X`（D08 後公式讀此欄）。`00` 是為了讓 Attribute User Text 列表排在最上面。
- Locked Tag 凍結內容與重新綁定，但 Health 仍唯讀判斷 stale／orphaned。
- `TAG_DW` 與 `SAMPLE_FRAME` 沒有 lock 欄；不得為它們寫入 `lf_00_lock_state`。
- Grab／Laser／Index／Layout ID 的 `TAG_ELEV_0` 把 `lf_00_lock_state` 的 `true`／`1` 或 `x`／`X` 視為鎖定。空值與預設提示 `x為不更新`／`x to lock` 不算。未遷移實例仍讀舊欄 `attr_Lock_不更新>寫入x或X`（或 key 含 `LOCK`／`不更新`），以及短暫用過的 `lf_lock_state`。日常指令不寫舊 key、不把 `x` 雙寫進 `lf_00_lock_state`。
- 1.x 非單一 `x/X` 的值只由 migration 列為待確認，不推測使用者意圖。
- 新建與 Duplicate 後，可鎖 template 的 `lock_state` 恢復為 `false`。

## Health 與 Repair

Health 必須唯讀產生 Issue Report；顏色只是可復原的提示層。至少表達：

```text
healthy
unbound
orphaned
stale
ambiguous
manual_locked
unindexed
unchecked
```

- 每項問題保存原因、影響、建議修復、預覽、使用者選擇與 repair result。
- Repair 不得偷偷重綁、換 ID、覆寫人工成果或刪除 Drawing。
