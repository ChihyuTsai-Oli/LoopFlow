LoopFlow 2.0 — 工作流程

本文件是實作與驗收使用者操作順序、介入點、安全停點與重跑行為的唯一來源。資料語意以 資料契約.md 為準；工程相依以 開發任務與路徑.md 為準。

工作原則

  • 每一階段可以單獨執行、驗證、存檔與換機。
  • 使用者決定何時寫入、何時發布、綁誰、更新當頁或全案。
  • 系統先報告影響，再執行有副作用的動作。
  • 取消、失敗或中斷不得破壞上一份有效資料或 Rhino 工作狀態。
  • 1.x 按鈕順序不是限制；保留的是已驗證可行的工作邏輯與控制點。

1. 開案檢查

動作：解析 LOOPFLOW_WORKFILES_ROOT、Dictionary、exchange/、project identity、schema version 與 Rhino 文件單位。

使用者介入：只有設定缺失、專案辨識不明或非 cm 警告時處理。

結果：顯示實際生效的路徑、版本與單位。非 cm 不阻擋，但明確警告風險並建議切換為 cm。

失敗：停止，不猜磁碟機、不建立檔案、不修改 Rhino 文件。

2. 驗證 Dictionary 並同步 Type Layers

Validate：檢查 15 欄、schema、Type ID、類別與 layer mapping、單位、measurement rule、量綱與必填值。

Sync：

  • 第一次尚未記住專案名稱時彈出視窗，不預填 M3D；檔案已有名稱後改在指令列詢問，Enter 接受已記住的名稱，也可改名。名稱寫入文件 lf_layer_prefix，不是專案 UUID。未寫入前綴時圖層樹仍用 M3D。
  • Dictionary 有、Rhino 沒有的 layer：建立並帶入初始 layer defaults。
  • 已存在的同名 Rhino layer：保留既有 UserText／construction；顯示色與材質依圖層代號前綴重套（1.x 顯示慣例），材質名稱不含專案前綴，不改物件 instance 顏色。
  • 不覆寫 object instance 的 _02 狀態，也不把 object data 回寫 Dictionary。
  • 不執行 ZoomExtents，不改變使用者視圖。
  • DNA_REF_ 參考點放在 (0,0,0)，依穩定 Type ID 更新或取代，避免空 Type layer 被 Purge 且不重複累積。
  • 20_DW 維持單一 Type，排除 child layers。

選用反向匯出：選單「寫回字典」在 Dictionary 同一目錄新增 LoopFlow_Dictionary_Export.xlsx（完整 15 欄加上 diff_status）。字體與字高跟正式字典相同；有變動的狀態文字會換色（缺漏紅、新增藍、修改橙）。不彙總 Object UserText、不自動覆寫正式 Dictionary。Rhino 多出來的 layer 以 added_in_rhino 列在底部。

安全停點：Layer 建好即可存檔，不必繼續跑完整鏈。

3. 建立與修改 3D 模型

使用者以 Rhino 一般工具建模。LoopFlow 不在背景自動注入資料。

LF_Cabinet_Suite／BOM 不屬 2.0；櫃體幾何與其他物件一樣使用一般 Type、Space、高程與 ID 規則。三個 2D Generator 是獨立工具，不阻擋主鏈。

4. 建立或維護樓層框與空間框

先登記樓層框，再登記空間框。選線期間鎖住場景中非封閉曲線，結束後還原。Esc 取消。

  • 樓層框：指令列選 FFL 或 FL，選封閉曲線後按 Enter，再彈出視窗輸入數字高程（0、320）。高程寫入 _15_樓層高程，不寫物件名稱。
  • 空間框：可一次選多條，彈出視窗輸入同一個空間名稱。名稱寫入 _01_空間名稱，不寫物件名稱。
  • 空間框須與樓層框高程差在 ±20 模型單位內，且整圈在樓層框裡面（共邊可）。
  • 相鄰空間可以共邊，內部不可重疊。
  • 面積重疊只檢查同一 level_id；不同樓層允許平面投影重疊，但會警告。
  • 同樓層的房間會對到同一個樓層框，因而共用同一個 level_id。不必手填樓層 UUID。
  • 重疊時停止並列出全部衝突 Space，不用 priority 自動選擇。
  • 平面、boundary 或樓層變更後回到此階段，再重新資料化。

安全停點：Boundary 完成可直接存檔；既有物件資料不會在背景改變。

5. 資料化：Apply → Verify

目前 Nexus 選單是 5 Apply → 6 Verify → 7 寫回字典。發布尚未實作。

Apply

使用者確認後才寫入：Object ID、Type reference、Space、高程、remarks 與 revision。ID 變更必須保存 old_id → new_id mapping。不寫寬深高、數量或座標框。

Verify

在記憶體算出再跑一次 Apply 會寫的 UserText，與物件現值比對，不寫入。相符彈出視窗說明符合；不符彈出視窗列出差異，並保持那些物件被選取。

中斷：保留已完成且可驗證的寫入與 mapping；重跑 Verify 顯示剩餘差異，不假裝全案完成。

寫回字典

在字典目錄新增 LoopFlow_Dictionary_Export.xlsx，供人工核對後合併進正式 Dictionary。字體、字高與正式字典相同；diff_status 有變動時只改該格文字顏色。不得覆寫 LoopFlow_Dictionary.xlsx。

6. 發布 Registry

前置：全案 Verify 通過。Nexus 組 payload 後呼叫 C03；C03 才寫檔。

動作：取得 exclusive lock（PID、主機、時間）、重新讀取現況並遞增 registry_revision、寫 pending、驗證完整 payload，再 atomic replace 正式 Registry。

輸出：新的不可人工編輯 Registry revision，只包含 canonical schema 與明確 extension。

失敗：保留 last-good；顯示失敗階段，不先刪正式 JSON。目前選單尚未接發布。

7. 建立 Section 並註冊 View

使用 Rhino 8 內建 Clipping／Section 指令建立剖面、立面或平面。LoopFlow 將 Section、Detail 與固定 2D↔3D transform 註冊為 view_id。

View 不依名稱或可變 bbox 重新猜測。Section linked output 可以先保留、更新與檢查，不必立即 Materialize 或 Tag。

8. Materialize 可編輯 Drawing

使用者需要獨立整理線稿時，將 Section 結果轉為 drawing_id：

  • 辨識前次產出，讓使用者選擇取代、新增或略過。
  • 保存來源 view_id、source revision 與 drawing element provenance。
  • 回報 indexed／unindexed／ambiguous 覆蓋率。
  • 復原原有 selection、layer lock 與 visibility。
  • 使用者補線、刪線或改樣式後標記為 modified；更新不靜默覆寫。

安全停點：Drawing 完成即可獨立存檔與人工整理。

9. 建立 Sheet、圖框與 Layout ID

使用者建立 Layout、Detail、圖框與 Tag Blocks。系統以 Sheet metadata 產生 Layout 名稱、圖號與圖名。

  • 只對 manifest 中 role: title_frame 的 Block 寫入圖框資料。
  • 未知 Block 報告並略過。
  • 比例維持人工輸入，canonical key 不含圖幅或排序資訊。

Duplicate Sheet

複製後建立新的 sheet_id、drawing_id 與 tag_id：

  • 除 TAG_DW 外，所有 Tag 清除來源綁定、自動欄位與人工補充說明，並恢復 template 預設 lock。
  • TAG_DW 的人工編號、寬、高與其他內容完整保留。
  • 使用者重新綁定新頁 Tag。
  • 不覆蓋系統剪貼簿。

10. 建立與綁定 Tag

模式使用者動作結果
Grab選 Tag，再直接選模型來源建立 source_object_id
Laser在 Drawing 點位置以固定 transform／有效來源索引找候選；多候選由使用者選
Index選 Tag，再選目標 View／Sheet建立 target_view_id／target_sheet_id
Furniture Item選共用家具 Block解析 FF-01__Chair-1；格式錯誤停止並警告
TAG_ELEV_0使用者直接填方向／編號不建立模型 binding
TAG_DW使用者直接填編號／寬／高純手動，不建立 binding

同款家具可共用 Block 名稱；家具 Tag 綁定名稱類型，不具 object-level orphan 偵測。Locked Tag 不允許重新綁定，必須先由使用者解除 lock。

11. 同步顯示資料

使用者可選同步當前頁或全部頁。Sync 從指定 Registry revision 與 Sheet metadata 計算 render output：

  • 不覆寫 locked Tag。
  • 不覆寫 TAG_DW、比例、Detail 編號及其他人工欄位。
  • 缺來源、過期、歧義與未知 template 回報明確狀態，不以顏色作唯一真相。
  • Part 完成就是合法停點，不要求每次全案同步。

12. Health 與 Repair

Health 唯讀檢查 identity、binding、revision、template 與覆蓋範圍，包含 locked Tag；TAG_DW 無來源屬正常，不判 unbound。

Repair 是獨立動作：先顯示影響與預覽，使用者確認後才執行。不得偷偷重綁、換 ID、刪 Drawing 或覆寫人工內容。提示顏色必須可還原原始顏色。

變更循環

只改資料

重新 Scan／Apply／Verify → Publish 新 Registry revision → Sync → Health。若只是人工備註且屬 instance override，不得被 Dictionary 重匯覆寫。

修改模型幾何

重新資料化與發布 → 更新 Section → 使用者選擇保留、新增或取代 Drawing → 必要時重新綁定 → Sync → Health。

修改 Space／樓層

回到 Space Boundary → 全案 Scan／Apply／Verify → Publish → Sync → Health。

Detail／Layout 重整

重新註冊 View 或執行 Duplicate Sheet 規則 → 重新綁定 → Sync → Health。不得沿用無法證明有效的舊 target ID。

實機驗收重點

  • 正常、取消、失敗、中斷與重跑。
  • hidden／locked 物件仍納入正式 Scan。
  • ID mapping 與 rollback。
  • Drawing 人工修改保護。
  • Duplicate Sheet 清除／保留規則。
  • TAG_DW 永不被 Sync 覆寫。
  • 家具共用名稱與格式錯誤警告。
  • 非 cm 警告。
  • Registry last-good 與雙程序競態。
