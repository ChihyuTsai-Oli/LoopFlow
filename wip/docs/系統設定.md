## 工作資料夾

**`.3dm` 所在資料夾就是工作資料夾**，不再用環境變數指定。

- 專案設定：`<3dm 資料夾>\_LoopFlow_Config\LoopFlow_Project.json`
- 採用 Dictionary：`<3dm 資料夾>\<檔名>.xlsx`（預設 `LoopFlow_Dictionary.xlsx`；可改名，檔名記在專案設定 `dictionary_filename`）
- 交換 JSON：`<3dm 資料夾>\_LoopFlow_Config\<專案名稱>\`
- log：`<3dm 資料夾>\_LoopFlow_Config\logs\loopflow.log`
- Registry 正式檔／lock／pending／last-good 檔名見 `資料契約.md`
- 雙機實際的 Dropbox 工作檔位置：依 workspace 根目錄的 `工作檔路徑.md`

三者（`.3dm`、Dictionary、`_LoopFlow_Config`）只以相對關係綁定，整包搬到別的上層目錄或別的磁碟都不影響；`LOOPFLOW_WORKFILES_ROOT` 已停用。

重構採用 Dropbox 的中文欄位／中英雙語 layer Dictionary。`releases/LoopFlow/LoopFlow_Dictionary.xlsx` 的英文版本保留為 1.x 參考，不作 2.0 的即時工作來源。日後 2.0 正式發布會另做 tw／en 兩套使用者文字與字典顯示欄；開發期只維護繁中。繁中 Dictionary 字型為微軟正黑體，英文版為 Arial。程式不寫死任何電腦的絕對路徑；`.3dm` 未存檔時停止相關操作並說明要先存檔。

## 介面語系

正式發布只出**一份** `.yak`，不要中／英兩個安裝包，也不要兩套程式。

| 項目 | 規則 |
|---|---|
| 套件 | 同一份 `.yak` 帶程式＋兩份顯示句子表（繁中／English） |
| 開發期 | 只寫繁中句子；現在不抽語系表、不做切換 |
| 抽出去的 | 彈窗、按鈕、清單標題、成功／失敗說明、選單給人看的字、Dictionary 顯示欄名 |
| 留在程式裡的 | 繁中註解、指令 ID、JSON／machine key、物件 UserText 鍵（如 `_01_空間名稱`）、網址與檔名 |
| 語系存在哪 | 這台電腦的 LoopFlow 偏好，**不寫進 `.3dm`** |
| 第一次 | 任一產品指令第一次跑時問繁中／English，記住 |
| 之後要改 | **Document 右鍵**（左鍵仍開文件入口）。不另加工具列按鈕，不放進 Nexus |
| 猜測 | Rhino 不猜介面語系，也不依 Dictionary 檔名或 Windows 語言自動切 |
| 公開文件 | 一篇一語；繁中為真相、英文為翻譯。只有入口頁可中英並列。G03 才換成 2.0 指南；屆時繁中檔名預定 `USER_GUIDE_zh-TW.md`，現在不要改 1.x 檔名 |
| Tag 圖塊 | 維持一份英文 `Tag_Blocks.3dm` |

Document 右鍵改語系等英文介面真正要出時才做；目前套件只登錄命令列開文件，右鍵語系尚未實作。

2.0 由 `loopflow.foundation.paths.resolve_project_folder` 從目前 `.3dm` 位置組出工作資料夾、`_LoopFlow_Config` 與字典路徑；專案設定由 `loopflow.foundation.project_config` 讀寫。Registry 在 `_LoopFlow_Config/<專案名稱>/`。Dictionary 預設檔名 `LoopFlow_Dictionary.xlsx`，可改成同一層的其他 `.xlsx`；不掃全部 Excel、不猜檔名。測試注入暫存資料夾當 `.3dm` 位置，不依賴真實 Dropbox。log 檔名屬進階設定（預設 `logs/loopflow.log`）；Registry 檔名不是設定。

## 2.0 開發模式

- `main`、`v1.0.0` 與 `releases/LoopFlow/` 作為舊版行為與回復參考，不在重構過程逐支改造成半新半舊系統。
- 2.0 在新的 `wip/src/`、隔離安裝、設定、資料與測試專案中乾淨建立，正式發布時一次切換。
- 開始建立 feature 前，先完成 `資料契約.md` 的 canonical schema、Block manifest、fixtures 與 validator。A03–A06 已完成此關卡。
- 新核心只接受 2.0 canonical contract；舊專案支援由獨立 migration 工具負責。
- 每個建造階段仍須有自動測試；完整 Rhino 實機測試於主要工作流接通後執行。

## 重構期間的 Rhino 測試入口

重構期間直接從 repo 執行開發中的入口，不必先複製到 `%APPDATA%`。Rhino 測試按鈕固定指向 `entrypoints/`，不要直接指向仍會調整的 `features/`、`platform/` 或 `foundation/` 內部模組：

```text
E:\_GitHub\LoopFlow\wip\src\entrypoints\
```

目前可跑的指令清單與按鈕巨集（含左鍵／右鍵配置）統一維護在 **`rhino指令.md`**，本節不再複製一份會過期的清單。`LF_Test_Random_M3D_Layers.py` 只是開發期輔助：把**目前選取**的物件隨機分到專案 M3D 底下的類型子圖層（例如 `M3D::00_STR_結構::Slab.樓板` 只會分到 `Slab.樓板` 這種末端圖層，不會分到 `00_STR_結構` 或 `_Data`）。略過 `DNA_REF_` 與空間／樓層框。`LF_D08_Migrate_Display_Keys.py` 同樣是開發期輔助：全檔圖塊把舊顯示欄抄到 `lf_*` 後刪舊 key；鎖定欄若寫 `x`／`X` 會抄到 `lf_00_lock_state`。**都不是產品指令**，不進正式工具列。

不要用工具列上的 1.x `LF_Nexus` 或 1.x `LF_Data_Viewer`。Nexus 成功連上後會先做開案檢查，通過才跳出步驟清單：

```text
1  開案檢查
2  從字典同步 Type Layers
3  登記高程框（封閉曲線）
4  登記空間框（封閉曲線，須在高程框內）
5  寫入模型 Metadata
6  檢核模型 Metadata（不寫入）
```

Esc 取消後續步驟。缺框或 Dictionary 驗證失敗會彈窗說明（含第幾列）。寫入後用選 **6** 核對。匯出字典與發布已改為獨立指令：`LF_Export_Type_Layers` 只在字典目錄新增 `{原檔名}_Export.xlsx`（第 1 列紅色提示），有變動的 `diff_status` 會換色；`LF_Publish_Exchange` 須全案檢核通過，才寫入目前 `.3dm` 旁 `_LoopFlow_Config/<專案名稱>/Project_Registry.json`，並把版次寫進物件 `_14`。`LF_Open_Dictionary`／`LF_Open_Dictionary_Export` 只開啟既有 xlsx。

### 隔離測試檔準備

請開**新的測試 `.3dm`**，存檔後即可用，不必再開文件 UserText 手填 UUID。文件單位建議 cm。第一次跑指令會順便在 `_LoopFlow_Config/LoopFlow_Project.json` 寫入 `schema_id`／`schema_version`。專案名稱在 Nexus 選單 2 填，同時寫入設定檔的 `layer_prefix` 與 `project_id`。

**把 `LoopFlow_Dictionary.xlsx` 複製到測試 `.3dm` 同一層**（雙機的 Dropbox 來源位置見 `工作檔路徑.md`）；不再設環境變數。設定檔、Registry 與 log 都會出現在該 `.3dm` 同目錄的 `_LoopFlow_Config/` 下。整包資料夾搬到別處或別的磁碟仍可用。

### 建議實機順序

1. 先跑指令，確認出現清單。選 **1** 只看開案檢查訊息。
2. 選 **2**：每一次都彈出視窗問專案名稱，第一次不預填 `M3D`；之後框裡預填已記住的名稱，按 OK 即可。Dictionary 只在第一次同步、或已記住的 `.xlsx` 改名／搬離 `.3dm` 同層時才選檔；選過會記住。找不到時應先彈窗說明「請把字典移回 `.3dm` 同一層」，再開選檔視窗，起始位置就是 `.3dm` 所在資料夾並預選記住的檔名。選到別的資料夾會說明並**再跳出選檔**，不要直接結束。字典改名後應能重新選取並記住新檔名。應出現對應 Type layers 與原點 `DNA_REF_` 點；已有同名 layer 的 UserText 不被蓋掉。圖層應有顯示色；新建材質顏色與圖層相同，已有材質不改色。再跑一次不應累加 `DNA_REF_`，舊參考線應被點取代。Esc 取消不應留下半套 layer。
3. 選 **3** 登記高程框（封閉曲線）：彈出清單點選 FFL 或 FL，選封閉曲線後按 Enter，再彈出視窗輸入高程（`0`、`320`）。選 **4** 登記空間框（封閉曲線，須在高程框內）：可複選，彈出視窗輸入「廊道」或「衛浴」。選線只用曲線過濾，不鎖全檔實體。房間框須與高程框高差 ±20 且整圈在高程框內。框線只寫 UserText，不改物件名稱。不必手填樓層 UUID。
4. 在 Type layer 上放測試用 3D 物件。選 **5** 寫入模型 Metadata：物件 UserText 應為 `_01_空間名稱`（無 `*`）、`_03_ID編號`、`_05_高程基準`、`_07_UUID` 等中文編號 key，**沒有**寬深高或實作數量。空間框仍是 `_01_空間名稱*`。樓面高程框填 50、窗台 BH 在相對高度 100 時 `_06` 應為 150。物件在房間內應寫入空間名稱而不是 `EXT`。跨多空間會彈出清單點選。選 **6** 檢核模型 Metadata：相符會彈窗；不符會彈窗說明、提醒跑 **Nexus 5**，並一次選取那些物件。手動改 `_14` 應被報成不符，選單 5 會寫回正確版次。
5. 跑 `LF_Export_Type_Layers.py`：應在字典目錄出現 `{原檔名}_Export.xlsx`，正式字典不變；匯出檔第 1 列紅色提示，缺漏／新增／修改的狀態文字分別為紅／藍／橙。
6. 跑 `LF_Publish_Exchange.py`：應寫出目前 `.3dm` 旁 `_LoopFlow_Config/<專案名稱>/Project_Registry.json`，物件 `_14` 跟上該次版次。未先檢核通過應被擋住，彈窗與選單 6 同一份不符清單（並選取那些物件），提醒「請執行 Nexus 5 寫入模型 Metadata，把正確資料寫回。」。若提示正式檔被佔用，等雲端同步結束後再發，不要刪 `Project_Registry.json`。
7. 跑 `LF_Open_Dictionary.py` 應開啟目前記住的正式字典；`LF_Open_Dictionary_Export.py` 應開啟 `{原檔名}_Export.xlsx`。這份檔還沒記住字典檔名時，即使工作檔裡有預設 Excel 也不該開啟。檔案不存在時應說明並停止，不建空檔。
8. 跑 `LF_Data_Viewer.py`：點物件應看到 canonical 欄與缺值 `（缺）`，關掉視窗後 UserText 不變。Esc／Enter 結束。未知文件 schema 應停止並說明。
9. 跑 `LF_Anchor_Frame.py`：在 **2D 模型空間**框選剖面線＋恰好一個 Text Dot，**彈出視窗**輸入外擴距離。應出現 `LoopFlow::Anchor_Frame` 框，UserText 有 `lf_view_id`、`lf_clipping_plane_id`、`lf_view_transform`。天花圖先左右鏡射再登記。Esc、取消彈窗、沒有 Text Dot、Clipping Plane 對不到或對到兩個，都不該畫框。
10. 跑 `LF_Tagger_Laser.py`：在 **Layout** 選 `Tag_Height_Laser` 或 Finish Laser，再在已登記 View 的 Detail 內點剖面位置。**選 Tag 時**命令列應出現 `DebugRay=No`（不是 ScriptEditor 的 Edit／Run／Open）。沒有 Anchor Frame 時應提示請先執行 Anchor Frame。射線沿 Clipping Plane 法線，2D 對位用框內剖面 Hatch／Curve（不含 Visible 背景），3D 用 Anchor Frame 寫死的 transform，不跟現況 CP 元件。Tag 應出現 `lf_source_object_id`。框與圖一起平移後仍應打到正確 3D UUID。Esc、點在 Detail 外、鎖定（含鎖定欄寫 `x`／`X`）、Grab 圖塊、沒打到，都不該寫入。舊鎖定欄 `x`／`X` 家中已測（2026-08-18）。日常不畫洋紅線；把 `DebugRay` 改成 Yes 才畫在 `LoopFlow::Debug_Laser`。
11. 跑 `LF_Tagger_Index.py`：在 Layout 選 `TAG_SECTION_DETAIL` 或 `TAG_ELEV_1`～`4`，清單應列出全檔各頁 Detail（頁名＋Detail 名），不是固定三個 View 框名。點清單應 zoom 到對應 Detail。Tag 應出現 `lf_target_view_id` 與 `lf_target_layout`。Esc、鎖定（含鎖定欄寫 `x`／`X`）、`TAG_ELEV_0`、模型空間、沒有 Detail、對不到或對到兩個 View、取消清單，都不該寫入。畫面上的圖號文字不會出現（那是 Infuser）。舊鎖定欄 `x`／`X` 家中已測（2026-08-18）。

建置路徑（本機已核對）：Rhino 8 Script Editor 專案 `*.rhproj` → `"C:\Program Files\Rhino 8\System\RhinoCode.exe" project build` 產生 `.rhp` → `yak.exe build` 打成 `.yak`。不做 RHI。不可沿用 1.x 攤平腳本複製到 `%AppData%\...\scripts\LoopFlow\`。重裝同版時 Rhino 可能不更新指令清單，必要時加版本號。Package Manager 上架是 G02 後段，本 spike 不做。

手寫的 `.rhproj` 即使 JSON 能被讀取，RhinoCode 仍會判定「存成 Rhino 8.9 或更早」而拒絕建置。**必須在 Rhino 8.11 以上的 Script Editor 新增專案、加入 `commands/` 下各正式指令 `.py`（名稱見 `指令名稱.txt`）、把 `wip/src` 加到 Libraries、另存成 `wip/packaging/g02-spike/LoopFlow.rhproj`，再跑 `build.ps1`。** 現在不要改開發期入口檔名。產品工具列來源是 `wip/docs/toolbar/LoopFlow.rui`。

```json
"language": { "id": "*.*.python", "version": "3.*.*" }
```
