本文件是 LoopFlow 維護設定與現況結構的權威來源。實作範圍與完成條件另見 `實作總覽.md`；任務依賴與工作波次另見 `開發任務與路徑.md`。

## 重構工作檔根目錄

- 本機環境變數：`LOOPFLOW_WORKFILES_ROOT`
- 雙機實際路徑：依 workspace 根目錄的 `工作檔路徑.md`
- 採用 Dictionary：`%LOOPFLOW_WORKFILES_ROOT%\<檔名>.xlsx`（預設 `LoopFlow_Dictionary.xlsx`；可改名，記住在文件 `lf_dictionary_filename`）
- 交換 JSON：`%LOOPFLOW_WORKFILES_ROOT%\exchange\<project_id>\`
- Registry 正式檔／lock／pending／last-good 檔名見 `資料契約.md`

重構採用 Dropbox 的中文欄位／中英雙語 layer Dictionary。`releases/LoopFlow/LoopFlow_Dictionary.xlsx` 的英文版本保留為 1.x 參考，不作 2.0 的即時工作來源。日後 2.0 正式發布會另做 tw／en 兩套使用者文字與字典顯示欄；開發期只維護繁中。繁中 Dictionary 字型為微軟正黑體，英文版為 Arial。程式只讀環境變數，不寫死公司路徑；環境變數缺少或目錄不存在時，應停止相關操作並顯示設定方式。

2.0 由 `loopflow.foundation.paths.resolve_workfiles` 解析根目錄，再組出 Dictionary 與 `exchange/<project_id>/` 的契約檔名。Dictionary 預設檔名 `LoopFlow_Dictionary.xlsx`，可改成同一資料夾根目錄的其他 `.xlsx`；不掃全部 Excel、不從 `.3dm` 旁尋檔。測試注入暫存資料夾，不依賴真實 Dropbox。log 檔名屬進階設定（預設 `logs/loopflow.log`）；Registry 檔名不是設定。

## 2.0 開發模式

- `main`、`v1.0.0` 與 `releases/LoopFlow/` 作為舊版行為與回復參考，不在重構過程逐支改造成半新半舊系統。
- 2.0 在新的 `wip/src/`、隔離安裝、設定、資料與測試專案中乾淨建立，正式發布時一次切換。
- 開始建立 feature 前，先完成 `資料契約.md` 的 canonical schema、Block manifest、fixtures 與 validator。A03–A06 已完成此關卡。
- 新核心只接受 2.0 canonical contract；舊專案支援由獨立 migration 工具負責。
- 每個建造階段仍須有自動測試；完整 Rhino 實機測試於主要工作流接通後執行。

## 重構期間的 Rhino 測試入口

重構期間直接從 repo 執行開發中的入口，不必先複製到 `%APPDATA%`。Rhino 測試按鈕固定指向 `entrypoints/`，不要直接指向仍會調整的 `features/`、`platform/` 或 `foundation/` 內部模組：

```text
E:\_GitHub\LoopFlow\wip\src\entrypoints\
```

目前可跑的指令清單與按鈕巨集（含左鍵／右鍵配置）統一維護在 **`rhino指令.md`**，本節不再複製一份會過期的清單。`LF_Test_Random_M3D_Layers.py` 只是開發期輔助：把**目前選取**的物件隨機分到專案 M3D 底下的類型子圖層（例如 `M3D::00_STR_結構::Slab.樓板` 只會分到 `Slab.樓板` 這種末端圖層，不會分到 `00_STR_結構` 或 `_Data`）。略過 `DNA_REF_` 與空間／樓層框。`LF_D08_Migrate_Display_Keys.py` 同樣是開發期輔助：全檔圖塊把舊顯示欄抄到 `lf_*` 後刪舊 key；鎖定欄若寫 `x`／`X` 會抄到 `lf_00_lock_state`。**都不是產品指令**，不進正式工具列。

不要用工具列上的 1.x `LF_Nexus` 或 1.x `LF_Data_Viewer`。Nexus 成功連上後會先做開案檢查，通過才跳出步驟清單：

```text
1  開案檢查
2  從字典同步 Type Layers
3  登記高程框（封閉曲線）
4  登記空間框（封閉曲線，須在高程框內）
5  寫入模型 Metadata
6  檢核模型 Metadata（不寫入）
```

Esc 取消後續步驟。缺框或 Dictionary 驗證失敗會彈窗說明（含第幾列）。寫入後用選 **6** 核對。匯出字典與發布已改為獨立指令：`LF_Export_Type_Layers` 只在字典目錄新增 `{原檔名}_Export.xlsx`（第 1 列紅色提示），有變動的 `diff_status` 會換色；`LF_Publish_Exchange` 須全案檢核通過，才寫入 `exchange/<project_id>/Project_Registry.json`，並把版次寫進物件 `_14`。`LF_Open_Dictionary`／`LF_Open_Dictionary_Export` 只開啟既有 xlsx。

### 隔離測試檔準備

請開**新的測試 `.3dm`**，不要開正式專案。文件單位建議 cm。文件 UserText：

| 鍵 | 值 |
|---|---|
| `lf_project_id` | 小寫 UUID v4，例如 `aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa` |
| `lf_schema_id` | `loopflow.project` |
| `lf_schema_version` | `1` |

環境變數 `LOOPFLOW_WORKFILES_ROOT` 須指向**這台電腦**的工作檔根目錄（內有 `LoopFlow_Dictionary.xlsx`）；兩台電腦的實際路徑見 `工作檔路徑.md`。

### 建議實機順序

1. 先跑指令，確認出現清單。選 **1** 只看開案檢查訊息。
2. 選 **2**：每一次都彈出視窗問專案名稱，第一次不預填 `M3D`；之後框裡預填已記住的名稱，按 OK 即可。Dictionary 只在第一次同步、或已記住的 `.xlsx` 找不到時才選檔；選過會記住。應出現對應 Type layers 與原點 `DNA_REF_` 點；已有同名 layer 的 UserText 不被蓋掉。圖層應有顯示色；新建材質顏色與圖層相同，已有材質不改色。再跑一次不應累加 `DNA_REF_`，舊參考線應被點取代。Esc 取消不應留下半套 layer。
3. 選 **3** 登記高程框（封閉曲線）：彈出清單點選 FFL 或 FL，選封閉曲線後按 Enter，再彈出視窗輸入高程（`0`、`320`）。選 **4** 登記空間框（封閉曲線，須在高程框內）：可複選，彈出視窗輸入「廊道」或「衛浴」。選線只用曲線過濾，不鎖全檔實體。房間框須與高程框高差 ±20 且整圈在高程框內。框線只寫 UserText，不改物件名稱。不必手填樓層 UUID。
4. 在 Type layer 上放測試用 3D 物件。選 **5** 寫入模型 Metadata：物件 UserText 應為 `_01_空間名稱`（無 `*`）、`_03_ID編號`、`_05_高程基準`、`_07_UUID` 等中文編號 key，**沒有**寬深高或實作數量。空間框仍是 `_01_空間名稱*`。樓面高程框填 50、窗台 BH 在相對高度 100 時 `_06` 應為 150。物件在房間內應寫入空間名稱而不是 `EXT`。跨多空間會彈出清單點選。選 **6** 檢核模型 Metadata：相符會彈窗；不符會彈窗說明、提醒跑 **Nexus 5**，並一次選取那些物件。手動改 `_14` 應被報成不符，選單 5 會寫回正確版次。
5. 跑 `LF_Export_Type_Layers.py`：應在字典目錄出現 `{原檔名}_Export.xlsx`，正式字典不變；匯出檔第 1 列紅色提示，缺漏／新增／修改的狀態文字分別為紅／藍／橙。
6. 跑 `LF_Publish_Exchange.py`：應寫出 `exchange/<project_id>/Project_Registry.json`，物件 `_14` 跟上該次版次。未先檢核通過應被擋住，彈窗與選單 6 同一份不符清單（並選取那些物件），提醒「請執行 Nexus 5 寫入模型 Metadata，把正確資料寫回。」。若提示正式檔被佔用，等雲端同步結束後再發，不要刪 `Project_Registry.json`。
7. 跑 `LF_Open_Dictionary.py` 應開啟目前記住的正式字典；`LF_Open_Dictionary_Export.py` 應開啟 `{原檔名}_Export.xlsx`。檔案不存在時應說明並停止，不建空檔。
8. 跑 `LF_Data_Viewer.py`：點物件應看到 canonical 欄與缺值 `（缺）`，關掉視窗後 UserText 不變。Esc／Enter 結束。未知文件 schema 應停止並說明。
9. 跑 `LF_Anchor_Frame.py`：在 **2D 模型空間**框選剖面線＋恰好一個 Text Dot，**彈出視窗**輸入外擴距離。應出現 `LoopFlow::Anchor_Frame` 框，UserText 有 `lf_view_id`、`lf_clipping_plane_id`、`lf_view_transform`。天花圖先左右鏡射再登記。Esc、取消彈窗、沒有 Text Dot、Clipping Plane 對不到或對到兩個，都不該畫框。
10. 跑 `LF_Tagger_Laser.py`：在 **Layout** 選 `Tag_Height_Laser` 或 Finish Laser，再在已登記 View 的 Detail 內點剖面位置。**選 Tag 時**命令列應出現 `DebugRay=No`（不是 ScriptEditor 的 Edit／Run／Open）。沒有 Anchor Frame 時應提示請先執行 Anchor Frame。射線沿 Clipping Plane 法線，2D 對位用框內剖面 Hatch／Curve（不含 Visible 背景），3D 用 Anchor Frame 寫死的 transform，不跟現況 CP 元件。Tag 應出現 `lf_source_object_id`。框與圖一起平移後仍應打到正確 3D UUID。Esc、點在 Detail 外、鎖定（含鎖定欄寫 `x`／`X`）、Grab 圖塊、沒打到，都不該寫入。舊鎖定欄 `x`／`X` 家中已測（2026-08-18）。日常不畫洋紅線；把 `DebugRay` 改成 Yes 才畫在 `LoopFlow::Debug_Laser`。
11. 跑 `LF_Tagger_Index.py`：在 Layout 選 `TAG_SECTION_DETAIL` 或 `TAG_ELEV_1`～`4`，清單應列出全檔各頁 Detail（頁名＋Detail 名），不是固定三個 View 框名。點清單應 zoom 到對應 Detail。Tag 應出現 `lf_target_view_id` 與 `lf_target_layout`。Esc、鎖定（含鎖定欄寫 `x`／`X`）、`TAG_ELEV_0`、模型空間、沒有 Detail、對不到或對到兩個 View、取消清單，都不該寫入。畫面上的圖號文字不會出現（那是 Infuser）。舊鎖定欄 `x`／`X` 家中已測（2026-08-18）。
12. 跑 `LF_Catalog.py`（家中 Rhino 8 已測，2026-08-18；關閉鈕與主面板高度 **2026-08-20 再測**）：開面板後 `LoopFlow` 圖層**列印寬度**為 `No Print`。選 Sheet 四欄對齊，Ctrl 可加選／取消。選定位點歸位紅／綠圖層；Build 產生文字；Refresh 更新內容但不拉回已移動位置；關閉鈕完整可見、鎖高 28。詳細見 `LF_Catalog規劃.md`。
13. 跑 `LF_Infuser_Part.py`（**公司 Rhino 8 已測注入，2026-08-19**；與 TAG-O 來回 **家中已測，2026-08-19**）：在 Layout 執行，只應改目前頁的 Height／Finish／Item／Index 顯示欄（含標在 Detail 圖上的 Tag）；鎖定、門窗、圖框比例、`TAG_ELEV_0`、Detail 編號與備註不該變。未綁定應出現 `-`。沒有 Registry 時 Height／Finish 仍應從已綁定物件的模型欄位灌入。其他 Layout 頁不該被改。`IN__101.01`／`A__106`／`DC__201.a2` 圖號應可灌。刪掉 Index 綁定的目標 Layout，或刪掉該頁上對到目標 View 的 Detail，應寫 `?`、塗紅，摘要出現「目標消失」，不可默默灌別頁圖號。已標斷連的 Tag 再跑 Infuser 不該被灌回；再綁定後再跑 Infuser 可恢復，不必刪 Tag。
14. 跑 `LF_Infuser_All.py`（**公司 Rhino 8 已測，2026-08-19**）：應改**所有** Layout 頁的 Tag 顯示欄，規則同 Part。模型空間也可跑。缺 schema 或 Registry 檔損壞則整批不寫。
15. 跑 `LF_TAG-O.py`（**家中 Rhino 8 已測，2026-08-19**）：應出現 **TAG-O ~ Holy Cargo ~~** 深色面板且**可捲動**，依 Layout 頁序列出已綁定 Tag，頁與頁之間灰線。`[正常]` 綠、`[過期]` 橘、`[斷連]` 紅。點選應反白該列並跳到該 Layout 拉近、看得見圖框。未綁定（畫面 `-`）不該出現。非 D08 圖塊不該出現。家具改名應列過期並把自動欄改成 `!`、整顆塗橘；刪實例應列斷連、自動欄 `?`、整顆塗紅。Index 目標圖號變了應列過期；刪掉綁定的目標 Layout，或刪掉該頁上對到目標 View 的 Detail，應列斷連。鎖定的斷連 Tag 仍應出現並標「鎖定」，但文字與顏色不該變。門窗與 `TAG_ELEV_0` 不該出現。
16. 跑 `LF_Extract_CP.py`（**公司 Rhino 8 已測，2026-08-20**）：先**完全關掉 Rhino 再開**。在 **2D 模型空間**勾選 Clipping Drawing 剖面根圖層。應複製到 `LoopFlow_Extract::Visible`／`Hatch`／`Curve_#HEX`，可列印；Visible／Hatch 列印色灰 `#BEBEBE`，其餘黑。抽出線 UserText 不該再有 `_01`～`_14`。來源剖面不該被搬走或解鎖。再跑應問取代／新增／略過。Layout 頁、Esc、找不到剖面圖層都不該寫入。
17. 跑 `LF_Duplicate_Layout.py`（**家中 Rhino 8 已測，2026-08-20**）：加高可捲動清單可複選來源 Layout（Ctrl／Shift 反白；拉高視窗時清單應變高、確定／取消鈕維持原高）。**彈窗**輸入一份份數 1～100（每一頁都複製那麼多份）。應出現新頁（頁名三欄、圖名 `_CopyN`、沒有 `**`）。完成提示關掉後應可立刻動作。新頁 Tag 應有新 `lf_tag_id`；Grab／Index 綁定應清空；手填欄（備註、Detail 編號、立面方向）應還在但畫面空白（不是 `####`）；自動欄應是 `?`、整顆紅；畫面上的 `x` 不該被改成 `false`。`TAG_DW` 編號／寬／高應還在；圖框比例應還在、圖號／圖名應先空。系統剪貼簿不該被改。Esc／取消、沒有 Layout、任一選頁沒物件，都不該寫入。再跑可再複製一份。
18. 跑 `LF_Sync_Worksession.py`（**家中 Rhino 8 已測，2026-08-20**）：須先存檔。第一次應**彈窗**開始監看目前檔案同資料夾的 `.3dm`（命令列也有路徑與 0.5 秒延遲）。改 3D 檔並等 idle，Worksession 參照應更新；暫存檔名含 `~`／`tmp` 不該觸發。Refresh 失敗不該拆掉上一份參照。再跑一次應彈窗停止監看。未存檔應說明並停止。
19. 跑 `LF_Document.py`（**待關 Rhino 再開再測**）：應開啟瀏覽器到 `https://github.com/ChihyuTsai-Oli/LoopFlow/blob/main/docs/README.md`（文件入口，不是專案首頁，也不是直接開某一語系說明）。頁上應看得到繁中／英文連結。Rhino 模型不該被改。打不開應只說明。
20. 把命令列與 UserText 異常貼回。

上列 1～18 為已通過的回歸清單。第 19 項 Document **待實機，須在 G02 之前**。之後才是 G01 migration。TAG-O 只檢查與上色，不實作 Repair。

## 自製 Eto 面板慣例

自製確認視窗的**共用外觀**只放 `wip/src/loopflow/platform/rhino/prompts.py`：外框 Padding 10、區塊 Spacing 5、清單列內邊距 8×2、OK／Cancel 75×23、控制項鎖高度。各扇 Width／Height 與欄位說明留在該 dialog，不抽成設定檔或字串表。

- 不指定 Font（用 Rhino 系統預設字）

### Rhino 內建 Section 按鈕

目前工具列中複製排列的 Section 按鈕只包含簡單 Rhino Macro，例如 `! _ClippingSections`。2.0 保留這種快捷入口，但它們不列入 Python entrypoint 清單：

```text
! _ClippingSections
! _ClippingDrawings
! _ClearClippingSections
! _EditClippingDrawings
! _UpdateClippingDrawings
```

正式安裝包部署 LoopFlow 自有工具列資源；Macro 仍由 Rhino 8 內建指令執行。不得複製 Rhino Section 程式本體，也不以 Rhino 預設 Macro／bitmap GUID 作長期必要相依。安裝與升級只管理 LoopFlow 工具列，不覆蓋使用者完整 workspace。圖示是否自製或引用可驗證的原生資源，與 RUI／RHC／其他安裝技術一起延後決定。

## `_LoopFlow_Config.py` 可編輯設定

### Dictionary

| 設定 | 預設值 | 用途 |
|---|---|---|
| `DICTIONARY_FILENAME_XLSX` | `LoopFlow_Dictionary.xlsx` | Dictionary 檔名 |
| `DICTIONARY_KEY_COLUMN` | `__Rhino Layer` | layer 主鍵欄 |
| `DICTIONARY_SKIPROWS` | `1` | 資料前略過列數 |

### Layer

| 設定 | 預設值／規則 |
|---|---|
| `LAYER_PREFIX_3D` | 預設 `M3D`；實際以前綴文件 UserText `lf_layer_prefix` 為準 |
| `LAYER_DATA_SUFFIX` | `_Data` |
| `LAYER_SPACE_BOUNDARIES` | `M3D::_Data::Space_Boundaries` |
| `LAYER_LEVEL_FFL` | `M3D::_Data::Level_Boundaries_FFL`；高程寫在 `_15_樓層高程`，不寫物件名稱 |
| `LAYER_LEVEL_FL` | `M3D::_Data::Level_Boundaries_FL`；同上 |
| `LEVEL_Z_TOLERANCE` | `20`（模型單位；建議 cm 時為 ±20 cm） |
| `LAYER_DW_PLAN` | `M3D::20_DW` |
| `LAYER_CABINET_PREFIX` | `04_CB` |
| `LAYER_PREFIX_2D` | `M2D`（一般 2D 內容；1.x 現況） |
| `LAYER_ANCHOR` | `LoopFlow::Anchor_Frame`（2.0 View 框；父圖層是 `LoopFlow`，不是 `M2D`） |
| `LAYER_EXTRACT_ROOT` | `LoopFlow_Extract`（Extract 產出根圖層，與 `LoopFlow` 平級。可列印；Visible／Hatch 列印色 `#BEBEBE`，其餘黑。子層 `Visible`／`Hatch`／`Curve_#RRGGBB`） |

修改 3D prefix 不會自動改名既有 layer，且部分值需要重啟 Rhino；不得把它視為無風險文字設定。

### 系統檔案與並行

| 設定 | 預設值 |
|---|---|
| `REGISTRY_FILENAME` | `Project_Registry.json` |
| `REGISTRY_LOCK_FILENAME` | `Project_Registry.lock` |
| `DEBUG_LOG_FILENAME` | `cursor_LF_debug_log.txt` |
| `SYNC_INTERVAL` | `0.5` 秒（2.0 對應 `AppConfig.worksession_refresh_delay`） |
| `LOCK_TIMEOUT` | `20.0` 秒 |
| `STALE_LOCK_SECONDS` | `30.0` 秒 |

Registry P0 已由 C03 實作：活著的持有者不可搶 lock；同機死 PID 或 lock 超過 30 秒視為 stale。不等待 20 秒重試，鎖定中立即停止。獨立指令 `LF_Publish_Exchange` 呼叫 C03。

### 其他設定

- 2D layer 與顏色：門窗、櫃體、Defpoints、Extract。2.0 Extract 根圖層是 `LoopFlow_Extract`（見上表）；1.x 仍是 `Extract`。
- Block definitions：Index、Height、Finish、Item、Door/Window 與 title frame。現行 `TAG_DW` 已改純手動，但 1.x Config／Infuser 仍把它列為資料 Tag；2.0 不承接這個衝突。
- `WHITE_LIST`：TagTrigger／Checker 不覆寫的 UserText key。
- Layout 命名：`LAYOUT_NAME_SEPARATOR`、copy suffix、baseline marker。
- Ceiling／mirror keywords 與 `INVERT_Y`。

完整實際值以 `_LoopFlow_Config.py` 為準；文件改動時必須核對程式，不建立第二份可執行設定。

上表描述 1.x 現況。2.0 的 Dictionary resolver 改由 `LOOPFLOW_WORKFILES_ROOT` 加固定檔名取得；Rhino 文件所在資料夾不再是 Dictionary 的主要搜尋位置。

## 文件與程式註解規則

- 全部實作文件的唯一責任表位於 `wip/README.md`；本文件不複製第二份清單。
